| ⑦ 시험대 | 처리기(실행 사본) | `gates/bench.json`(pass, **시험대 지문**, 케이스 수) | 케이스 수 ≥ 프로젝트 `state/` 마지막 케이스 수, 불안정 0 | 새 일에 비교값 없음 → 프로젝트 state |
| 커밋 | 처리기, ⑦ 통과 직후 스스로 | 임시 인덱스 `git commit`(pre-commit은 처리기 커밋만 통과) | **검토 지문 = 시험대 지문 = 지금 지문**; 다르면 멈추고 대표가 ⑦ 사본 복원 또는 지금 트리 수용(⑥부터) | ⑥ 뒤 지문이 바뀌면 장치 밖 변경 → 자동으로 ⑥에 넘기지 않음 |
| 배포 | 처리기 + 서버 쪽 검사 | 실행 사본에서 빌드, 산출물 경로만 따로 커밋(pre-commit 통과 조건 (나)) | 산출물 경로를 뺀 지문 = 시험대 지문, 바뀐 경로는 산출물 경로 안만, 교차 점검 도착 | 빌드 뒤 지문이 달라 관문에 걸림 → 배포 관문 별도 |
| ⑧ 보고 | 반장(쓰기 창 ⑧, report.md만) | `outputs/report.md` | 「실측」 절 ∈ 실행 기록, 대조표 = ⑥ 확인본 | 상태 줄 자동 부착 |
| 일 닫기 | 대표 `일 닫기` | 훅이 닫기 접수; 처리기가 「닫는 중」 → **HEAD와의 차이만** `archive/{일 이름}/{시각}/`에 보관(실패면 원래 상태) → HEAD로 맞춤 → 미뤄 둔 승인 적용·커밋 → 트리 = HEAD 재확인 → 지적 일이면 번호 갱신 → **「닫힘」** → 대기열 | 대표 입력인지, 보관 성공 | 일 시작 기준이면 커밋분까지 보관 → HEAD 기준. `/일` 일 닫기가 번호를 올려 지적이 사라짐 → 지적 일만 갱신 |

## 되돌림·종료

| 경우 | 누가 시작 | 어디로 | 누가 무엇을 고치나 | 상한 |
|---|---|---|---|---|
| 검토 불통과 | 검토자 판정 | ⑥ → ⑤(구현자 창 다시 열림) | 구현자, 검토 항목 번호별 | 바퀴 상한, 2연속이면 다른 계열 1회 |
| 명령 오류 | 구현자 표시 + 시험자 확인 | ⑤ → ③ | 계획자(plan.md), 시험자(다음 번호 스크립트) | 되돌림 상한 |
| 설치 요청 | 구현자 | ⑤ 잠시 멈춤 → 재개 | 처리기(비교 0 확인 → 샌드박스 설치 → manifest·잠금 반영 → 새 칸 시작 사본) | — |
| 포기 | 대표(지적 일은 다시 넣기 / 버리기, `/일` 일은 선택 없음) | 종료 | 처리기가 HEAD 차이 보관·되돌림·미뤄 둔 승인 적용. 다시 넣기면 그 뒤 같은 번호가 ⓪부터 다시 열림 | 승인 |
| 복구 | 대표 `일 복구 {프로젝트} {일 이름}` | 상태 「복구 중 {일 이름}」 | 변경은 손대지 않음, 닫기는 ⑧ 통과 기록 있을 때만·아니면 포기, 지적은 대기열에만 | — |
| 마무리 실패 | 처리기 | 보관 실패면 원래 상태(「열림」/「복구 중」), 그 뒤 실패면 「닫는 중 {일 이름}」에 머묾 | 대표가 `일 닫기` 재시도(끝난 단계 생략) 또는 `포기`; 직원 훅·승인은 거부 | — |
