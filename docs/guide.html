03

구현 담당과 검수 담당을 나누는 법

만드는 AI는 하나로, 검사하는 눈은 가능하면 서로 다른 모델 계열 둘로.

반장

계획을 쓰고
작업을 나눠 맡김
결과를 모아 보고

→

깎는 손

테스트 먼저 쓰고 구현
작성은 한 계열만
(코드 일관성)

→

보는 눈 ① 1차 검수

넓게 훑기 · 빠름

보는 눈 ② 교차 점검

다른 모델 계열 · 읽기 전용

→

모아서 결정

P0·P1은 반드시 고침
P2는 판단, P3는 기록
다시 검사는 최대 2번

같은 변경을 두 모델 계열에 보이면 서로 다른 것을 잡는 경우가 많다. 언제 둘 다 쓰나: 인증·권한·결제·삭제·외부 연동·배포·설정 변경은 필수로 두길 권장, 큰 기능은 권장, 문서·문구는 생략해도 된다.

04

검증은 다섯 겹

"됐다"는 말이 아니라 실행 결과로 통과해야 다음 칸으로 간다.

① 코드 검사

테스트 · 타입 검사 · lint
깎는 손이 매번 실행
코드가 안 깨졌나

→

② 검수 (리뷰)

읽고 문제를 P0~P3로
설계·보안·회귀

→

③ QA (실제로 돌려 보기)

임시 환경에서 실제 실행
진짜로 동작하나

→

④ 하네스 검문 · 시험대

품질 기준표로 통과/실패
좋아졌나

→

⑤ 마지막 교차 점검

같은 변경을 다른 계열이
읽기 전용으로 검사
놓친 큰 결함은 없나

어느 겹이든 실패하면 ① 깎기로 돌아간다. 완료 보고에는 실행 명령 · 출력 숫자 · 확인 못 한 것을 함께 쓴다.

07

곳간과 울타리

믿을 자료는 한 곳에, 위험한 일은 장치로 막는다.

곳간

자료의 구분

지금 쓰는 자료

library_root — 가장 먼저 믿는다

↑ 꾸준히 옮겨 정리

지난 자료

지우지 않고 "지난 자료"로 표시, 점점 줄인다

울타리

지시문이 아니라 장치가 막는다
장치막는 것
승인 관문삭제·보관 이동·서비스 정지·DB 변경·배포·push·설정 편집 → "승인 ○○" 뒤 설정된 시간만
위험 명령 차단되돌릴 수 없는 명령은 대표가 직접 실행
완료 보고 검증실행 근거 없는 "완료·통과"
착수 전 보고보고 없이 코드 수정 (경고 모드로 시작 가능)

못 막는 것: 지시 준수 100%, 보고 내용의 질 → 계획 승인·검수·시험대로 잡는다.

훅 구현: hooks/scope_guard.py, hooks/block_dangerous.py, hooks/verify_claims.py, hooks/preflight_gate.py

08

프로젝트가 진짜 자동화가 되려면

사람 없이 돌아도 믿을 수 있게 — 프로젝트마다 세 가지.

① 시험대

예시 입력 + 좋은 결과 기준 + 점수
고칠 때마다 같은 시험

② 혼자 돌 때 감시

실패를 기록만 하지 말고
사람에게 먼저 알림

③ 사람 확인 지점

발행·발송·결제·삭제처럼
틀리면 비싼 곳에만

예: 콘텐츠 자동 발행 도구는 발행 직전에, 광고 소재 생성 도구는 집행 직전에 사람 확인을 둔다 — 업종이 달라도 "비싼 지점"만 사람이 본다는 원칙은 같다.

다음 단계: 프로젝트마다 시험대 만들기(계획서 → 승인).

09

대표가 하실 일

이것만 하면 공방이 돌아간다.

정하기

무엇을 왜 할지 한두 문장으로

승인

채팅에 "승인 ○○" — 위험한 일은 이것 없이 안 열림

지적

"이거 하지 마, 왜냐면 ~" — 이유가 붙으면 일지가 정확해짐

승격

"승격 L1-번호" — 반복된 지적을 정식 기준으로

자료

쓸 자료는 자료 폴더에, 지난 자료는 보면서 옮기고 줄이기

숫자 보기

주기적으로: 지적 비율 · 반복된 일지 · 시험대 점수

하지 않으셔도 되는 것: 같은 말 반복하기 · 진행 상황 묻기(작업판에 있음) · 코드 확인(검수·시험대가 함).

한 세션에는 한 프로젝트의 한 가지 일만 — 기록이 섞이지 않게.
