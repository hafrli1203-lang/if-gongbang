## 정의 단일화 확인

범위·지문·세 지문·사본·요청·처리기·쓰기 창·상태 셋·보관·마지막 처리 번호·산출물 주인·보호 부류는 `v2-devices.md` §정의에만 있다. 범위는 커밋 트리 하나. 프로젝트 단위 것(상태·번호·케이스 수·원문·대기열·도면·일지·보관본)과 일 단위 것(산출물·요청·기록·bench·사본)은 전부 작업 트리 밖. 요청 경로는 `requests/{직원}/{번호}.md` 하나, 결과는 `records/requests/` 하나.

# IF 공방 v2 — 모든 개발에 걸기, 한계, 다음 목적지

읽는 순서는 `v2.md` 맨 위 표.

## 모든 개발에서 먹히게 — 장치는 전역, 데이터만 프로젝트

| 전역(하네스 홈, 이 저장소의 `harness/`) | 프로젝트 안(데이터) |
|---|---|
| 막는 훅과 설정 파일 | `tests/bench/` 시험 케이스 |
| 스킬(크래시 아웃·아우라 파밍·육칠·화면 품질 점검·계획 쓰기…) | `scripts/probe/` 실측 로그 |
| AI 직원 7명(⓪~⑥) 파일 | 도면(결정 문서) |
| 궤도 스크립트, `/일` 명령 | 프로젝트 안내 한 줄 |
| 공통 규칙 2장(안전 + 이 문서) 자동 로드 | 미리보기 스크립트(템플릿에서 생성) |

- 설치: 저장소를 받아 설치 절차 한 번 → 다른 컴퓨터에도 같은 훅·스킬·직원·명령.
- `/일 {이름} 루트={폴더} [소형] [화면]`: 어느 폴더든 처음이면 `tests/bench/`·`scripts/probe/`·도면을
  만들고 프로젝트 목록에 등록한다. 그 순간부터 같은 궤도다.
- **자동으로 읽히는 절차 문서는 두 장**(안전 규칙 + 궤도 요약)으로 유지한다. v2 문서 여섯 개는 설계 문서라 자동으로 읽히지
  않는다. 자동 로드 문서가 늘어나면 실패 신호다.
  "이 프로젝트에서만"이라는 말이 설계에 나오면 설계가 틀린 것이다.
