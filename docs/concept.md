# IF 공방이란

**IF 공방은 사용자(대표)의 판단을 작업 일지와 도면으로 쌓고, 그 기준과 울타리 안에서 AI 작업조가
프로젝트를 깎아 만들며, 시험대로 재어 조금씩 다듬어 가는 개발·운영 방식이다.**

- 목적: AI와 매번 같은 말을 반복하지 않고, 한 번 지적한 것을 다음 작업이 기억하게 한다.
- 기대치: 알아서 다 되는 것이 아니라 **깨지면 바로 보이고, 같은 실수는 반복되지 않는 것.**
- 모든 프로젝트는 업종·도메인 범용 도구로 다룬다. 특정 업종·브랜드를 기본값으로 박지 않는다.

## 공방의 부품 9개

| 이름 | 하는 일 | 이 저장소에서는 |
|---|---|---|
| **반장** | 일을 나누고, 맡기고, 확인하고, 대표에게 보고 | 대표와 대화하는 메인 에이전트 |
| **작업조** | 깎는 손(구현)과 보는 눈(검수)을 따로 둔다. 자기가 만든 것을 자기가 채점하지 않는다 | 구현 담당 에이전트 + 검수 담당 에이전트(가능하면 다른 모델 계열) |
| **울타리** | 사고를 지시문이 아니라 장치로 막는다 | `hooks/`의 승인 관문·위험 명령 차단·완료 보고 검증·착수 전 보고 훅 |
| **작업 일지** | 대표가 한 번 지적한 것을 3문장으로 남긴다 — 아직 기준 아님 | `hooks/lessons_store.py`가 쓰는 로컬 JSONL 파일 |
| **도면** | 작업 일지 중 반복 확인되고 **대표가 승격한 것만** 기준이 된다 | 프로젝트마다 두는 결정 문서(예: `docs/ai/DECISIONS.md`) |
| **곳간** | 참고 자료를 쌓고 근거로 꺼내 쓴다 | `library_root`에 둔 자료 + 검색 도구(프로젝트가 연결) |
| **시험대** | 좋아졌는지 나빠졌는지 숫자로 잰다 | 프로젝트별 테스트·채점 기준 |
| **다듬질** | 한 바퀴씩 고치는 고리(아래) | 모든 수정에 적용 |
| **작업판** | 할 일 한 곳 | `work_queue_path`로 가리키는 한 파일 |

## 다듬질 — 한 바퀴

1. **돌려 본다** — 실제로 실행해 기록을 남긴다.
2. **원인을 가른다** — 자료(곳간)·기준(도면)·지시문·도구 중 어디인가.
3. **한 자리만 깎는다** — 증상 난 곳에 조건을 덧대지 않는다.
4. **시험대에서 잰다** — 같은 시험으로 전후를 숫자로.
5. **대표가 정한다** — 결과가 기준으로 자동 승격되지 않는다.

## 큰 일 하나의 흐름

지시 → 반장이 곳간·일지·도면을 읽고 **계획서 + 착수 전 보고**(읽은 자료 파일:줄 / 예상 위험·병목 /
바꿀 파일 / 되돌리는 법) → **대표 승인** → 작업조(깎는 손 → 보는 눈) → 시험대 → 대표 확인 → 지적은
작업 일지로.

- 되돌리기 어려운 일(삭제·보관 이동·서비스 정지·DB 변경·배포·push·설정 편집)은 채팅에 `승인 <TASK>`를
  입력한 뒤 설정된 시간(기본 4시간) 동안만 열린다.
- 완료 보고에는 실행한 명령·출력 숫자·확인 못 한 것을 함께 쓴다.
- **마지막 교차 점검(권장):** 코드 변경은 테스트·1차 검수 뒤, 같은 변경분을 다른 모델 계열에
  읽기 전용으로 한 번 더 보인다. 서로 다른 모델이 서로 다른 결함을 잡는 경우가 많다.

## 작업 일지 → 도면

- 지적을 받으면 3문장으로 남긴다: **실제 장면 / 그대로 쓸 수 없는 이유 / 다음부터 적용할 기준.**
- 원문은 잘라 인용하지 않고 전체를 저장한다 — 앞부분만 인용하면 뜻이 바뀔 수 있다.
- 다음 세션이 시작할 때 작업 일지를 먼저 읽는다.
- 일정 기간 안에 서로 다른 세션에서 반복되면 승격 후보가 되고, 대표가 "승격 `L1-번호`"라고 하면
  그 프로젝트의 도면(결정 문서)에 올라간다. 결과가 나빠지면 내린다.
- 사실 · 한 번 겪은 경험 · 검증된 기준 · 이번 작업에만 필요한 정보를 한 기억에 섞지 않는다.

## 울타리가 막는 것과 못 막는 것

- **막는다:** 되돌리기 어려운 행동(승인 관문), 명백히 위험한 명령, 근거 없는 완료 보고.
- **못 막는다:** 지시문 준수 100%, 보고 내용의 질. 이것은 계획서 승인·작업조 검수·시험대로 잡는다.

## 프로젝트가 "진짜 자동화"가 되려면

1. **시험대** — 예시 입력 + 좋은 결과의 기준 + 점수. 고칠 때마다 같은 시험을 다시 돌린다.
2. **혼자 돌 때 감시** — 실패를 숨기지 않고 바로 알린다.
3. **사람 확인 지점** — 틀리면 비싼 곳(발행·발송·결제·삭제)에만 사람 확인을 둔다.

## 출처 표기 원칙

이 시스템은 특정 회사가 실제로 쓰던 내부 워크플로를 일반화한 것이다. 특정 교육 과정·컨설팅 브랜드·
내부 코드네임은 공개판에 옮기지 않는다. 아이디어의 뿌리(피드백을 구조화해 쌓는 방식, 깎는 손과 보는
눈을 분리하는 방식 등)는 여러 소프트웨어 개발·조직 운영 관행에서 공통적으로 쓰이는 것이며, 이 저장소
는 그것을 하나의 구체적인 도구 묶음으로 엮은 것이다.
