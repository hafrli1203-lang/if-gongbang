# 메인테이너용 — 공개 전 점검

이 문서는 저장소를 쓰는 사람이 아니라, 공개 저장소로 유지·관리하는 사람을 위한 것이다.

## 공개 적합성 검사 — 두 겹

`tests/test_public_ready.py`는 저장소 전체를 스캔해 서버/계정 정보가 공개 저장소로 새어 나가지
않는지 확인한다.

1. **일반 패턴(항상 실행)** — 홈 디렉터리 경로, `/srv` 경로, Windows 사용자 경로, IP 주소, 이메일
   형태처럼 어떤 환경에서나 통하는 구조적 패턴. 이 테스트 파일 자체에 커밋된다.
2. **로컬 전용 목록(선택, gitignore)** — 실제 회사명·빌려 쓰는 서비스 이름·사람 계정·내부 프로젝트
   코드네임 같은, 그 자체로 민감한 식별자. `tests/public_ready.local.txt`에 한 줄에 정규식 하나씩
   적는다(`#`로 시작하면 주석). 형식은 `tests/public_ready.local.example.txt`를 본다. 이 파일은
   절대 커밋하지 않는다 — 목록 자체가 지키려는 정보이기 때문이다.

로컬 목록이 없는 클론에서는 2번 검사가 건너뛰어진다(실패하지 않음). **공개하기 전에 반드시 메인
테이너가 그 로컬 목록을 실제 식별자로 채우고 테스트를 돌려야 한다.**

## 공개 전 체크리스트

- `python3 -m pytest tests/` 전부 통과.
- `tests/public_ready.local.txt`를 채운 상태에서 같은 테스트 통과.
- `gongbang.config.json`(개인 설정 파일, gitignore 대상)이 저장소에 커밋되지 않았는지 확인.
- README·docs에 특정 회사·브랜드·개인 식별 정보가 없는지 다시 읽는다.
