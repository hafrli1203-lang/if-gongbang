# IF 공방 v2 — 장치 상세 2: 케이스 관리 · 상한값 · 막는 훅

앞부분은 `v2-devices.md`. 읽는 순서는 `v2.md` 맨 위 표.

## 울타리 — 막는 훅

| 훅 | 언제 | 무엇을 막나 |
|---|---|---|
| 일 시작·닫기 | `/일 <이름>` · `일 닫기 <이름> <사유>` | 이미 열린 일이 있으면 두 번째 일 폴더 생성 차단. 열린 동안 들어온 대표 지적은 작업 일지에 「대기」로 적고, 지금 일이 닫히면 반장이 그 지적으로 ⓪ 일을 연다. 비정상 종료로 열린 채 남은 일은 **대표만** 사유를 적어 닫는다 |
| 편집 | 편집·쓰기 | 소스 폴더는 ⑤ 칸에서 소유표 안만. `scripts/probe/`는 ② 칸의 실측자만. `tests/bench/`는 **시험자이면서 ⓪ 칸이면서 새 파일**일 때만(케이스 번호는 실행기가 자동으로 매겨 겹침이 생기지 않음). 보호 파일은 누구도 못 씀 |
| 커밋 | 커밋(글자가 아니라 git 자체의 **pre-commit 훅**에도 같은 검사) | review.md 통과 + bench.json pass **+ 두 파일에 적힌 코드 지문(트리 해시)이 지금 올라갈 코드의 지문과 같을 것**. 다르면 ⑥으로. bench.json은 커밋 훅이 믿지 않고, 지문이 없으면 그 자리에서 시험을 다시 돌린다 |
| 배포 | 배포 스크립트, 그리고 main push로 배포가 자동 실행되는 프로젝트는 **push 훅**에도 | ⑥⑦ 산출물 + 코드 지문 일치 + 교차 점검 결과 도착 전엔 차단 |
| 작업조 | 작업조 생성 | ⑤⑥ 칸에서 역할 직원이 아닌 범용 작업조 차단 |
| 상태 줄 | 답이 끝날 때 | 금지어 검사는 쓰지 않는다("끝났습니다"로 피해 간다). 일이 열려 있으면 훅이 답 끝에 **"현재 칸 ④ · 미검증"** 같은 상태 줄을 자동으로 붙인다 — 어떤 표현을 쓰든 실제 상태가 같이 보인다 |
| 반장 터미널 | 일이 열린 동안 | 반장의 터미널 명령 전부 차단, 호출 수 초과 시 차단("새 창" 안내) |
| 터미널 | 직원의 터미널 명령 | 금지 목록이 아니라 **허용 목록**(화이트리스트)에 있는 명령만 통과(`python -c`·`node -e`·`perl -i`·`git checkout <파일>`·`git apply`·`curl -o` 같은 우회는 목록에 없으므로 막힘). 명령이 끝나면 `git status`로 허용 경로 밖 변경을 보고, 있으면 되돌린 뒤 막는다. 벽은 샌드박스 |
| 공개 저장소 push | `git push` | 금지 목록(빌려온 이름·사람 이름·내부 주소·경로·메일·계정명·날짜·일지 번호·승인 예시)에 걸리면 차단 |
| 시험대 보호 | 편집·쓰기 | 구현 칸에서 `tests/bench/` 편집 차단, `bench.json` 직접 쓰기 차단(시험 스크립트만 씀) |
| 승인 범위 | `승인 <이름>` | 이름이 열린 일·프로젝트와 맞지 않으면 거절하고 다시 입력받음. 배포·삭제는 짧은 창을 따로 둠(설정값) |
| v1 유지 | — | 승인 관문(`승인 <이름>`), 위험 명령, 비밀 파일, 훅 자체 보호 |

- 임계값과 민감 영역 패턴은 훅이 읽는 **설정 파일**에 둔다. 고치는 것은 승인 관문이다(아래 「보호 파일 목록」).
- 일 폴더가 열려 있지 않으면 v2 훅은 **아무것도 하지 않는다** → 다른 세션·다른 프로젝트는 `/일`을
  쓰기 전까지 영향이 없다. 되돌리기는 설정에서 훅 몇 줄을 빼는 것이다.

## 시험 케이스는 쌓기만 하지 않는다

- 케이스마다 **어느 지적에서 나왔는지**(작업 일지 번호)와 **어느 기준(도면)에 묶이는지**를 적는다.
- 도면이 바뀌어 더는 맞지 않는 케이스는 그 자리에서 정리한다(기준 변경 보고에 "정리한 케이스" 칸).
- 결과가 들쭉날쭉한 케이스는 「불안정」으로 표시한다: **통과 수에서는 빼되 ⑦은 막는다.** 따로 고친다. **불안정 판정은 사람도 AI도 하지 않는다** —
  시험 스크립트가 같은 코드로 여러 번(설정값, 처음 값 5회) 다시 돌려 결과가 갈릴 때만 붙이고, 불안정으로 넘어간 케이스 수는 보고에
  반드시 찍힌다. **불안정은 통과가 아니다** — 불안정 케이스가 하나라도 있으면 ⑦은 열리지 않고, 고쳐서 안정이 되거나
  대표가 그 케이스를 따로 판단해야 한다(면제에는 날짜와 유효 기한을 적는다 — 예: 다음 일까지. 영구 면제는 없다). 구현자는 `tests/bench/`를 못 고치므로 **불안정 판정이 나면 시험자에게 넘어간다** —
  원인이 시험 스크립트 쪽이면 시험자가 고치고, 코드 쪽이면 시험자가 재현 조건을 케이스에 적어 구현 칸으로 보낸다. 가끔만 터지는 진짜 버그가 불안정 뒤에 숨는 것을 막는다.
- **케이스 수가 줄면 실패다.** 시험대는 이전 실행의 케이스 수를 기억하고, 수가 줄었으면 pass를 내지 않는다
  (정리한 케이스는 기준 변경 보고에 적힌 것만 예외).
- **지적 → 케이스는 시험자가 ⓪ 시험 등록 칸에서 쓴다.** 대표 지적이 들어오면 반장이 작업 일지에 남기고 **그 지적으로 새 일을 연다.**
  그 일의 첫 칸이 ⓪ 시험 등록이다: 시험자가 케이스를 쓰고 **현재 코드에서 실패하는 실행 기록**을 남긴다. 그다음 ①~⑥을 지나
  ⑦에서 통과 기록이 남아야 케이스가 등록된다. 순서는 코드에 고정되어 "두 번째 일 차단"과 꼬이지 않는다(지적 일 하나 = 일 하나).
- **⓪에서는 새 파일만 더할 수 있다.** 기존 케이스를 고치거나 지우는 것은 재발 0이 무너지는 자리라 대표 승인으로만 열린다.
  케이스 번호는 **실행기가 자동으로 매겨** 겹침이 처음부터 생기지 않고, 그래도 겹치면 실패로 처리한다. 이전 케이스 수를 기억하는 파일은 보호 파일이며, **수동 케이스 수가 줄어도** 실패다.
- **자동 시험으로 실패를 재현할 수 없는 지적**(디자인 취향, 문구 느낌)은 ⓪을 영원히 못 빠져나가므로 출구를 둔다: 대표가
  "자동 시험 불가"를 고르면 「수동 케이스」로 등록되고 ⓪은 닫힌다. 수동 케이스는 검토자의 화면 품질 판정표에 줄 하나로
  들어가며, "고치기 전 실패·고친 뒤 통과" 대신 **고치기 전 캡처·고친 뒤 캡처·검토자 판정 줄**을 요구한다. 자동 케이스와
  섞지 않고 수를 따로 센다.
- **케이스는 "고치기 전 실패 · 고친 뒤 통과" 둘 다 확인돼야 등록된다.** 새 케이스를 고치기 전 코드에서 돌려 실제로
  실패하는 것을 실행 기록으로 남기고, 고친 뒤 통과하는 것도 기록으로 남긴다. 둘 중 하나라도 없으면 시험대에 들어가지
  않는다 — 아무것도 못 잡는 케이스가 쌓이는 것을 막는다. 이것이 "재발 0"이 말이 아니라 장치가 되는 지점이다.

## 상한값과 설치는 기록으로 관리한다

- 호출 상한·바퀴 상한·시간 상한·소형 궤도 파일 수는 처음 값이 정답이 아니다(터미널 비율은 상한이 아니라 계기판 지표다). 설정 파일에 **바꾼 날과 이유**를 함께 적고,
  계기판 숫자(막힘이 너무 잦은가, 너무 느슨한가)로 조정한다.
- 설치 뒤에는 읽기 전용 점검 스크립트로 훅이 실제로 등록됐는지 확인한다. 저장소에는 push마다 테스트가 자동으로
  돌게 하여(CI) 울타리 코드 자체가 망가지는 것을 막는다.


## 보호 파일 목록 — AI가 쓸 수 없고 훅·궤도 스크립트만 쓴다

쓰기·편집 도구와 샌드박스 양쪽에 같은 거부 규칙이 걸린다. 고치는 길은 **대표 승인 관문 하나**뿐이고, 바꾼 날과 이유가 기록된다.

| 파일 | 왜 보호하나 |
|---|---|
| 일 상태 파일(열린 일, 현재 칸, 건너뜀 기록) | 칸 숫자를 바꾸거나 표시를 지우면 울타리 전체가 꺼진다. **칸 이동과 일 닫기는 궤도 스크립트만** 하고, 앞 칸 산출물을 확인한 뒤에만 넘어간다 |
| 설정 파일(임계값·민감 영역 패턴·경고/차단 모드) | 느슨하게 고치면 모든 관문이 느슨해진다 |
| 훅 스크립트 폴더, 훅을 등록하는 **전역 설정 파일**, **하네스 설치 폴더**, **각 프로젝트의 `.claude/` 설정** | 훅 하나를 고치거나 프로젝트 설정으로 훅을 끄면 장치가 한꺼번에 꺼진다 |
| 실행 기록, 원문 기록, 열람 기록 | 검사의 근거 — 고치면 자기신고가 된다 |
| `bench.json`, 이전 케이스 수 파일 | 시험 결과와 "케이스 수가 줄었는지"의 기준 |
| 코드 지문(검토·시험을 마친 시점의 트리 해시) | 커밋 관문이 "지금 코드"에 대한 통과인지 확인하는 기준 |

**설치본은 저장소와 직접 연결하지 않는다.** 장치의 원본은 이 저장소의 `harness/`지만, 설치본은 **버전을 고정한 복사본**이다.
이 저장소를 `/일`로 고치는 날 구현자가 손대는 파일이 바로 자기를 막고 있는 훅이기 때문이다. 새 버전 설치는 승인 관문을 거친 뒤
점검 스크립트가 등록 상태를 확인할 때만 한다.
