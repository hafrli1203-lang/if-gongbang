# IF 공방 v2 — 장치 2: 훅 표·상태·케이스·보호 목록

정의(지문 쌍·범위·허용 경로·기록·사본)는 `v2-devices.md` §정의 한 곳에만 있다. 이 문서의 표가 훅 동작의 기준이다. 자리 표시는 {이름}, 기호는 말로 적는다.

## 울타리 — 막는 훅 (단일 기준표)

| 훅 | 언제 | 무엇을 하나 |
|---|---|---|
| 일 열기 | `/일 {이름}` — 대표 입력만 | 열린 일이 있으면 거부. **대기열이 비어 있지 않으면 거부**(지적부터). 상태 파일을 「열림」으로, ⓪ 또는 ① 칸 |
| 일 닫기·포기·복구 | `일 닫기 {이름} {사유}`, `포기 {이름} {사유}`, `일 복구 {프로젝트}` — 대표 입력만 | **닫기**는 ⑧까지 간 일의 정상 종료, **포기**는 중간 종료(승인). 둘 다 궤도 스크립트가 작업 트리를 **마지막 커밋 상태로 되돌리고** 남은 변경은 일 폴더 `leftover/`에 보관한다(다음 일의 사본에 섞이지 않게). **복구**는 깨진 상태 파일을 「닫힘」으로 다시 만들 뿐 변경은 건드리지 않는다(그 뒤 대표가 닫기나 포기를 고른다). 닫기·포기가 처리되면 훅이 대기열 맨 앞 지적으로 ⓪ 일을 연다 |
| 지적 | `지적 {내용}` — 대표 입력만 | 원문 기록에 번호로 남고 대기열에 들어간다. **닫힘 상태면 즉시** ⓪ 일을 연다. 열린 일이 있으면 대기열에만 넣는다 |
| 편집 | 편집·쓰기 도구 | 허용 경로 안만. `tests/bench/` 케이스 본체: 시험자 ∧ ⓪ 칸 ∧ 다음 번호 이름. `tests/bench/scenes/`: 시험자 ∧ (③ 칸 또는 명령 오류 되돌림) ∧ 다음 번호 이름. 보호 파일은 누구도 못 씀. 작업 일지는 기존 내용이 앞부분에 그대로 남을 때만 |
| 터미널 | 직원의 터미널 명령 | 명령을 연결 기호(세미콜론, 이중 앰퍼샌드, 이중 수직선, 앰퍼샌드, 수직선, 출력 돌림 기호와 덧붙임 돌림 기호, 달러 괄호, 백틱, 줄바꿈, 입력 돌림 괄호, 히어독) 단위로 **쪼개 하나씩** 허용 목록과 대조하고, 쪼갤 수 없으면 거부. **명령 앞 변수 대입은 전부 불허**(예시: GIT_CONFIG_COUNT, GIT_CONFIG_KEY_0, GIT_DIR, NODE_OPTIONS, PYTHONPATH, LD_PRELOAD — 예시이지 목록이 아니다). `git`은 **바로 뒤에 오는 옵션 전부 불허**, 어디서든 `--no-verify` 불허. 허용 목록에 없는 것: claude, bash -c, sh -c, xargs, find -exec, env, eval, exec, git commit, git push, 패키지 설치 명령. 명령 뒤에는 칸 시작 사본과 해시로 비교해 허용 경로 밖 변경을 복원한다. 벽은 샌드박스 |
| 커밋 | 궤도 스크립트만 | 기록된 지문 쌍 = 지금 지문 쌍일 때만, 커밋 트리 규칙으로 커밋. 다르거나 없으면 ⑥으로. git 자체의 pre-commit 훅에도 같은 검사 |
| 배포 | 배포 스크립트 + 서버 쪽 자동 검사(main push로 배포되는 프로젝트) | ⑥⑦ 산출물·지문 쌍 일치·교차 점검 결과 도착 전엔 차단 |
| 공개 저장소 push | `git push`(AI 쪽 훅) **와 git 자체의 pre-push 훅**(대표 터미널에도) | 원격에 없는 **모든 커밋**의 파일 내용·경로·메시지와 꼬리말·브랜치·태그 이름과 메시지·이미지와 문서(PDF 등) 메타데이터를 금지 목록으로 검사. 커밋 신원은 **공개용 고정 이름·메일만 허용**. 날짜는 커밋 시각 칸을 빼고 메시지·파일 내용에서만. 고지 예외는 문단 단위, 목록은 설정에 |
| 작업조 | 작업조 생성 | ⑤⑥ 칸에서 역할 직원이 아닌 범용 작업조 거부 |
| 상태 줄 | 답이 끝날 때 | 일이 열려 있으면 "현재 칸 ④ · 미검증" 같은 줄을 자동으로 붙인다. 금지어 검사는 없다 |
| 반장 터미널 | 일이 열린 동안 | 반장의 터미널 명령 전부 거부, 호출 수 초과 거부 |
| 승인 범위 | `승인 {이름}` | 열린 일·프로젝트와 이름이 맞지 않으면 거절. 배포·삭제는 짧은 창(설정값) |
| v1 유지 | — | 승인 관문, 위험 명령, 비밀 파일, 훅 자체 보호 |

## 상태 파일·대표 입력·대기열

- 적용 프로젝트 목록(§정의)에 있는 프로젝트는 상태 파일이 늘 있어야 한다. 값이 「닫힘」일 때만 v2 훅이 쉰다. **없거나 못 읽으면 막는다.** 목록 밖 프로젝트는 v2가 꺼져 있다. 넣는 승인 동작이 「닫힘」 파일을 만들고, 깨졌을 때는 `일 복구`.
- **대표 입력만 인정하는 명령**: `/일`, `일 닫기`, `포기`, `일 복구`, `승인`, `지적`. 명령 파일에 모델 호출 금지 설정을 넣고, 훅이 원문 기록으로 대표 입력인지 확인한다.
- **대기열** = 원문 기록의 `지적` 메시지 중 번호 > 상태 파일의 "마지막 처리 번호". 열린 일이 닫히거나 포기되면 맨 앞으로 ⓪ 일을 열고 번호를 올린다. 닫힘 상태에서 온 지적은 즉시 연다. `/일`은 대기열이 비어 있을 때만 열린다. 표시는 `state/queue.md`를 훅이 만든다(일지가 아니다).

## 케이스 관리

- 케이스는 두 종류다. **지적 케이스**(⓪ 칸, 고치기 전 실패·고친 뒤 통과 둘 다 필요)와 **장면 케이스**(③ 칸에서 계획자가 고른 통과 장면을 시험자가 `tests/bench/scenes/`에 쓰고 ⑦에서 통과 기록만 필요). 수는 따로 센다. 지적이 아닌 `/일`에서도 장면 케이스는 늘어난다.
- 이름은 **다음 번호**만(쓰는 순간 훅이 허용). 실행기는 번호 형식 파일만 모은다.
- 실행기는 하네스 쪽 고정 설정으로 전용 샌드박스에서 돈다: 프로젝트 설정·`conftest.py` 무시(pytest는 `--noconftest -c {하네스 설정}`), **설치된 패키지의 플러그인 자동 로드 끔**(pytest는 자동 로드 끄기 환경값), 다른 도구도 같은 뜻의 옵션. 케이스는 공용 준비 코드 없이 돌아가게 쓴다. 실제 동작은 첫 시험에서 확인.
- **케이스 교체**: 케이스 본체를 고치는 길은 교체뿐이다. 새 번호 케이스가 옛 번호를 "대체"로 가리키고 **옛 번호의 실패 기록을 이어받는다**(코드가 이미 고쳐져 실패를 다시 만들 수 없으므로). 교체는 대표 승인(원문 번호)과 묶이고, 수에서는 옛 번호를 대체된 것으로 세어 줄지 않는다. 불안정이 케이스 쪽이면 시험자가 이 길로 고친다.
- 케이스마다 출처 지적 번호와 묶인 도면. 도면 변경과 케이스 정리는 한 묶음으로 대표 승인. 케이스 수가 줄면 실패(승인 번호와 맞는 정리·교체만 예외). 수동 케이스 수도 같다.
- **불안정** 판정은 실행기가 **같은 실행 전 지문 쌍**으로 여러 번(설정값, 처음 5회) 돌려 결과가 갈릴 때만. 통과 수에서 빼되 ⑦은 막는다. 면제는 승인 번호와 유효 기한이 있을 때만. 불안정이 나면 시험자에게(케이스 쪽이면 교체, 코드 쪽이면 재현 조건을 적어 ⑤로).
- **⓪ 시험 등록**: 시험자가 케이스를 쓰고 실행 사본에서 실패한 실행 기록을 남겨야 ①이 열린다. 자동 재현이 불가능한 지적은 대표가 "자동 시험 불가"를 고르면 수동 케이스(고치기 전 캡처·고친 뒤 캡처·검토자 판정 줄 + 묶인 파일 경로 패턴)로 등록되고 ⓪이 닫힌다. 수동 케이스는 바뀐 파일이 패턴과 겹치는 일에서 판정표에 자동으로 다시 올라온다(패턴이 비면 매번).

## 되돌림 두 가지

- **검토 불통과**: ⑥ → ⑤. 바퀴 상한(설정값)을 넘으면 멈추고 대표에게. 두 바퀴 연속이면 다른 계열 점검 1회.
- **명령 오류**: 구현자가 표시하고 시험자가 확인하면 ⑤ → ③. 계획자가 plan.md의 장면↔스크립트 연결을 고치고 시험자가 다음 번호로 스크립트를 쓴다. 되돌림 횟수에도 상한.

## 작업 사본 합치기 (직원별 사본 모드)

훅 입력에 직원 식별이 없어 경로로 역할을 구분하는 모드에서는 **칸 경계마다** 궤도 스크립트가 각 사본을 기준 트리로 합친다(⑥ 뒤에만이 아니다 — ⓪의 케이스와 ⑤의 코드가 다른 사본에 있으면 ⑤~⑥에서 함께 돌릴 수 없다). 합친 기준 트리의 지문 쌍이 기록값과 다르면 자동으로 ⑥, 충돌이 나면 풀지 않고 멈춘다.

## 상한값·역할 구분

- 호출 상한·바퀴 상한·되돌림 상한·시간 상한·소형 궤도 파일 수·불안정 반복 수는 설정에 있고, 바꾼 날과 이유를 적는다. 터미널 비율은 계기판 지표다.
- 직원 식별이 훅 입력에 들어오는지 첫 시험에서 확인하고, 없으면 직원별 사본 모드. 확인 전까지 역할별 훅은 "추정".

## 보호 파일 목록

두 부류다. **장치 기록**은 훅·궤도 스크립트만 쓰고(직원·반장 불가), **설정**은 대표 승인 관문으로만 바뀐다(바꾼 날·이유 기록). 설치본 복사는 대표가 본인 터미널에서.

| 부류 | 파일 | 왜 |
|---|---|---|
| 장치 기록 | 일 폴더 `state/` `records/` `bench/` `snapshots/` `leftover/` `queue.md` | 칸·대기열·검사 근거·시험 결과·복원 기준·닫을 때 남은 변경 |
| 장치 기록 | 작업 일지(덧붙이기만 — 터미널 덮어쓰기는 보호 경로라 막히고, 덧붙이기는 궤도 스크립트에 요청) | 케이스가 근거로 가리키는 곳 |
| 장치 기록 | `.git/` 전체(직원 읽기 전용, 커밋은 궤도 스크립트) | 훅 경로·가지 위치를 바꾸는 자리 |
| 설정 | 설정 파일(임계값·훅별 모드·제외 목록·적용 프로젝트 목록·고지 예외 문단·공개용 커밋 신원·허용 목록·금지 목록) | 느슨하게 고치면 모든 관문이 느슨해진다 |
| 설정 | 훅 스크립트 폴더, 훅 등록 전역 설정, 하네스 설치 폴더(버전 고정 복사본, 링크 금지), 프로젝트 `.claude/`, 서버 쪽 자동 검사 설정 | 훅을 고치거나 끄는 자리 |
| 설정 | 도면 | 케이스 정리의 근거 — 변경은 케이스 정리와 한 묶음으로 승인 |
| 쓰기 거부 | 의존성 폴더(모든 직원 샌드박스), 작업 트리 밖 비밀 파일·운영 키(읽기도 거부) | 시험 결과와 외부 호출을 바꾸는 자리 |

## 첫 시험에서 확인할 항목 (확인 전까지 "추정")

1. 훅 입력에 직원 식별이 들어오는가.
2. 실행기·설치가 전용 샌드박스에서 돌고, 궤도 스크립트는 결과만 읽는가. 설치 스크립트 실행이 꺼져 있는가.
3. 모델 호출 금지 설정이 설치 버전에서 작동하는가(`/일`·닫기·포기·복구·승인·지적).
4. 칸마다 도는 확인: 보호 경로 쓰기 거부, 운영 키 위치 읽기 거부, 허용 외 주소 통신 차단, 설치본 지문 = 고정 버전.
5. 실행기가 프로젝트 시험 설정·`conftest.py`·**설치된 플러그인**을 읽지 않는가(케이스 하나를 빼는 설정·플러그인을 넣고도 그 케이스가 도는가).
6. 메일·문자 서비스의 시험 모드/중계가 수신처를 실제로 강제하는가.
7. 실행 사본에서 돌린 뒤 원본의 감시 지문이 그대로인가(캐시·로그가 원본에 생기지 않는가).
8. 뚫리는 장면 재현: 상태 파일 손상 / 옛 bench.json으로 커밋 / `conftest.py` 새 파일 / 변수 접두 / `git -c`·`--config-env` / `claude` 재호출 / 대기 줄 위조 / 허용 명령 뒤 출력 돌림 쓰기 / 무시 파일이 커밋에 들어가는가.
