## 막는 규칙마다 — 원래 하던 주체 → 이제 누가, 어느 칸에서, 어떤 권한으로

| 막은 일 | 원래 | 이제 |
|---|---|---|
| bench.json·케이스 수·지문 쓰기 | 시험 스크립트(직원) | 처리기, 일 폴더 `gates/`에 ⑥(검토 지문)·⑦(시험대 지문·케이스 수), 프로젝트 state의 마지막 케이스 수 |
| 범위·HEAD를 바꾸는 설정 변경 | 승인 즉시 | 「닫힘」이면 승인 관문이 즉시, 아니면 기록 뒤 「닫는 중」에서 처리기가 미뤄 둔 승인 커밋으로 |
| 시험·장면·실측·설치 실행 | 직원 터미널 | 요청 파일(⓪·③ 시험자, ② 실측자, ⑤ 구현자) → 처리기가 실행 사본에서, 결과는 `records/requests/` |
| 요청 처리 | 훅 | 상주 처리기(훅은 접수만) |
| 커밋 | 구현자 | 처리기가 ⑦ 통과 직후, 세 지문 관문, `git commit`(pre-commit은 처리기만 통과) |
| 배포 빌드·산출물 커밋 | 배포 스크립트 | 처리기가 실행 사본에서 빌드, 배포 관문(산출물 경로 뺀 지문) |
| 의존성 추가 | 구현자 터미널 | 설치 요청(이름·버전) → 처리기가 manifest·잠금 반영, 새 칸 시작 사본 |
| manifest·잠금 수정 | 구현자 소유 | 소유 불가, 장치만 |
| 다음 일 열기 | 반장 | 처리기, 닫기·포기 시점 또는 「닫힘」의 지적 즉시, 가장 작은 번호 |
| 마지막 처리 번호 갱신 | 닫기 때 무조건 | 지적 일 닫기만, 포기는 대표 선택 |
| 대기열·상태·번호·원문·케이스 수·보관본 | 일 폴더 | 프로젝트 폴더 |
| 쓰기 권한 | 주인이면 언제나 | 주인 × 칸(쓰기 창) |
| 시안 승인 | AI 표시·파일 해시 | 대표 입력 `이거다`, design 폴더 해시, ④와 ⑤ 입구 대조 |
| 장면 스크립트 | 계획자/구현자 | 시험자, ③ 또는 명령 오류 되돌림 |
| plan.md 수정 | 계획자 ③만 | 계획자 ③ 또는 명령 오류 되돌림 |
| tools.md · coverage · report | 주인 없음 | 계획자 · 구현자별 파일(처리기가 합침) · 반장(report.md만) |
| probe 로그 | 작업 트리 | 일 폴더 `records/probe/`(처리기가 옮김) |
| 케이스 수정 | 시험자 자유 | 교체 경로만 |
| 실행기 설정 | 프로젝트 파일 | 하네스 고정 설정 |
| 상태 파일 생성·복구 | — | 등록 승인 / 대표 `일 복구 {프로젝트} {일 이름}` → 「복구 중 {일 이름}」 |

| 닫은 일의 남은 변경 | 작업 트리에 그대로 | HEAD 차이 → `archive/`, 삭제는 대표만 |
| 일지 덧붙이기 | 편집 도구·터미널 | 요청(반장·검토자) |

| 직원별 사본 합치기 | ⑥ 뒤 한 번, 지문 비교 | 칸 경계마다, 충돌 0·사본별 허용 밖 변경 0 |
| `.gitignore`·링크·하위 저장소 | 아무나 | `.gitignore`는 보호 설정(모든 깊이), 링크·하위 저장소는 소유 불가·지문 거부 |

## 정의 단일화 확인

범위·지문·세 지문·사본·요청·처리기·쓰기 창·상태 넷·보관·마지막 처리 번호·산출물 주인·보호 부류는 `v2-devices.md` §정의에만 있다. 범위는 커밋 트리 하나. 프로젝트 단위 것(상태·번호·케이스 수·원문·대기열·도면·일지·보관본)과 일 단위 것(산출물·요청·기록·gates·사본)은 전부 작업 트리 밖. 요청 경로는 `requests/{직원}/{번호}.md` 하나, 결과는 `records/requests/` 하나.

# IF 공방 v2 — 모든 개발에 걸기, 한계, 다음 목적지

읽는 순서는 `v2.md` 맨 위 표.

## 모든 개발에서 먹히게 — 장치는 전역, 데이터만 프로젝트

| 전역(하네스 홈, 이 저장소의 `harness/`) | 프로젝트 안(데이터) |
|---|---|
| 막는 훅과 설정 파일 | `tests/bench/` 시험 케이스 |
| 스킬(크래시 아웃·아우라 파밍·육칠·화면 품질 점검·계획 쓰기…) | `scripts/probe/` 실측 로그 |
| AI 직원 7명(⓪~⑥) 파일 | 도면(결정 문서) |
| 궤도 스크립트, `/일` 명령 | 프로젝트 안내 한 줄 |
| 공통 규칙 2장(안전 + 이 문서) 자동 로드 | 미리보기 스크립트(템플릿에서 생성) |

- 설치: 저장소를 받아 설치 절차 한 번 → 다른 컴퓨터에도 같은 훅·스킬·직원·명령.
- `/일 {이름} 루트={폴더} [소형] [화면]`: 어느 폴더든 처음이면 `tests/bench/`·`scripts/probe/`·도면을
  만들고 프로젝트 목록에 등록한다. 그 순간부터 같은 궤도다.
- **자동으로 읽히는 절차 문서는 두 장**(안전 규칙 + 궤도 요약)으로 유지한다. v2 문서 여섯 개는 설계 문서라 자동으로 읽히지
  않는다. 자동 로드 문서가 늘어나면 실패 신호다.
  "이 프로젝트에서만"이라는 말이 설계에 나오면 설계가 틀린 것이다.
