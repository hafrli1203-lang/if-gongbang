# v2 검토용 묶음 3/10

(v2-devices · v2-devices-2 · v2-walkthrough · v2-rollout를 순서대로 이어 붙여 나눈 것. 정의는 묶음 1의 §정의.)

| **보관** | 닫기·포기 때 처리기가 **마지막 커밋(HEAD)과 지금 트리의 차이**만 `projects/{프로젝트}/archive/{일 이름}/{시각}/`에 보관하고, 보관이 실패하면 「열림」에 머물고 멈춘다. 보관이 성공하면 상태는 「닫는 중」이 되고 마무리는 보관 → 「닫는 중」 → HEAD 맞춤 → 미뤄 둔 승인 커밋 → 트리 = HEAD 재확인 → 「닫힘」 → 대기열 순서다. 재확인에서 트리가 HEAD와 다르면(예: `.gitignore` 변경으로 무시되던 파일이 범위에 들어옴) 「닫는 중」에 멈추고 대표에게 알린다. 그 뒤 어느 단계가 실패해도 「닫는 중」에 머문다. 차이는 커밋 트리 범위 안에서 재고, HEAD에 없는 새 파일도 보관한 뒤 지우며, 무시 파일과 제외 목록 경로는 건드리지 않는다. 커밋된 내용은 닫기가 건드리지 않는다. 보관본 삭제는 대표만 |
| **상태 넷** | 「닫힘」: 대표 입력 훅(일 열기·지적·일 복구·승인)과 상주 처리기만 깨어 있고 나머지 v2 훅은 쉰다. 지적이 오면 가장 작은 대기 번호로 즉시 연다. 「닫는 중 {일 이름}」: 보관이 성공하면 처리기가 만든다. 직원 쓰기와 직원 훅은 거부하고, 지적은 대기열에만 쌓으며, 대표의 `일 닫기` 재시도와 `포기`만 받는다. 재시도는 끝난 단계를 건너뛴다(보관본이 있으면 보관 생략, 트리가 HEAD와 같으면 맞춤 생략, 커밋된 승인은 생략). 마무리 끝에 「닫힘」이 된다. 상태 파일이 없거나 읽히지 않으면 일 복구를 뺀 모든 v2 훅과 처리기 작업을 거부한다. 「열림 {일 이름}」: 한 일만. 「복구 중 {일 이름}」: `일 복구 {프로젝트} {일 이름}`이 만든다(상태 파일이 읽히면 거부, 그 이름의 일 폴더가 있고 `archive/`에 그 일의 보관본이 없을 때만). 이 상태에서는 `일 닫기`는 그 일의 ⑧ 통과 기록이 있을 때만, 없으면 `포기`만 받고, 지적은 대기열에만 쌓인다 |
| **보호 파일 — 장치 기록** | 훅·처리기만 쓴다: 프로젝트 `state/`·`records/`·`일지.jsonl`·`archive/`, 일 폴더 `records/`·`gates/`·`snapshots/`, `.git/` |
| **보호 파일 — 설정** | 승인 관문으로만: 설정 파일(임계값·훅별 모드·제외 목록·적용 목록·배포 산출물 경로·고지 예외·공개용 신원·허용 목록·금지 목록), 훅 스크립트 폴더·훅 등록 전역 설정·설치 폴더·프로젝트 `.claude/`·서버 쪽 검사 설정, 도면, 모든 깊이의 `.gitignore`. **범위나 HEAD를 바꾸는 승인**(`.gitignore`, 제외 목록, 배포 산출물 경로, `.claude/` 따로 커밋)은 「닫힘」에서 승인되면 승인 관문이 바로 적용·커밋한다. 「열림」·「복구 중」·「닫는 중」에서 승인되면 기록만 하고(미뤄 둔 승인 기록), 닫기·포기 마무리 단계에서 처리기가 **미뤄 둔 승인 커밋**으로 적용한다. 미뤄 둔 승인 커밋 = `.claude/`·추적 중인 `.gitignore`·배포 산출물 경로 설정처럼 범위나 HEAD를 바꾸는 승인의 커밋 전부 |
| **기준 트리** | 직원별 작업 사본 모드에서 칸 경계마다 처리기가 각 사본을 합친 트리. 합치기 검사는 **충돌 0과 사본별 허용 밖 변경 0**만 본다(지문 비교가 아니다) |
| **적용 프로젝트 목록** | v2가 켜진 프로젝트(설정). 넣고 빼는 것은 승인 관문 |

## 검사 원칙 — 자기신고를 믿지 않는다

- **실행 기록**: "돌렸다"와 보고의 「실측」 절은 plan.md가 고른 `tests/bench/scenes/` 스크립트의 실행 기록이 조건을 만족해야 인정된다. 실행은 요청으로만, 전용 샌드박스의 실행 사본에서.
- **칸 끝 비교**: 허용 경로 밖 변경이 있으면 다음 칸을 열지 않고 복원. 검토자 칸에서 변경이 있으면 판정 무효.
- **벽은 샌드박스**: 터미널이 있는 칸은 샌드박스에서 돌아 허용 경로 밖 쓰기가 파일 시스템 단위로 거부된다. 쓰기 창이 닫힌 직원은 아무 경로도 못 쓴다. 검토자는 일회용 사본에서 일하고, 판정 근거는 사본 지문 = 원본 지문일 때만.
- **소유표 = 샌드박스 허용 경로**: 공용 파일은 구현자 한 명에게 배정돼야 계획이 통과되고, 미배정 파일이 필요하면 ③으로.
- **대표 원문 인용**: "이거다", 채점표 선택, 건너뛰기 사유는 원문 기록의 번호와 글자 그대로 맞아야 한다. "이거다"는 여기에 더해 제시 줄보다 뒤여야 칸이 열린다.
- **출처는 열람 기록과 대조**: facts.md 「통과」 줄 출처 ∈ 열람 기록, 줄마다 출처, 외부 값은 probe 로그(일 폴더 `records/probe/`)의 같은 키와 스크립트 대조.
- **세 지문과 커밋**: 처리기가 ⑦ 통과 직후 검토 지문 = 시험대 지문 = 지금 지문일 때만 임시 인덱스를 지정한 `git commit`으로 친다(pre-commit 훅이 돈다). 하나라도 다르면 **커밋하지 않고 칸을 멈춘다** — ⑥부터 구현자 쓰기 창이 닫혀 있으니 지문이 바뀌었다면 장치 밖에서 고친 것이다. 대표가 (가) ⑦ 칸 시작 사본으로 되돌리고 ⑦부터 (나) 지금 트리를 받아들이고 ⑥부터 중 고른다. 자동으로 ⑥에 넘기지 않는다.
- **배포 관문**: 배포 산출물 경로를 뺀 지금 지문 = 시험대 지문, 교차 점검 결과 도착. 빌드는 처리기가 실행 사본에서 하고 산출물만 그 경로에 두어 따로 커밋한다.
- **의존성**: 구현자는 설치 요청만. manifest·잠금은 장치가 쓴다.
