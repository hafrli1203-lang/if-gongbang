## 상태·대표 입력·대기열

- 상태·마지막 처리 번호·마지막 케이스 수·queue.md·원문 기록은 프로젝트 폴더에 있어 일이 없어도 존재한다. 적용 목록 프로젝트는 상태 파일이 없거나 못 읽으면 막는다.
- 대표 입력만 인정하는 명령: `/일`, `지적`, `이거다`, 채점 선택, `일 닫기`, `포기`, `일 복구`, `승인`. 명령 파일에 모델 호출 금지 설정, 훅이 원문 기록으로 대표 입력인지 확인.
- 대기열 = 원문 기록의 `지적` 중 번호 > 마지막 처리 번호, 가장 작은 번호부터. 표시 `queue.md`는 훅이 만든다. `/일`은 대기열이 비어 있을 때만.

## 케이스 관리

- 두 종류: **지적 케이스**(⓪, 실패→통과)와 **장면 케이스**(③ 장면 스크립트, ⑦ 통과 기록). 수는 따로 세고 **이전 값은 프로젝트 `state/`의 마지막 케이스 수**(⑦ 통과 때 처리기가 갱신).
- 이름은 다음 번호만. 실행기는 번호 형식 파일만 모은다.
- 실행기는 하네스 고정 설정으로 전용 샌드박스에서: 프로젝트 시험 설정·`conftest.py` 무시(pytest는 `--noconftest -c {하네스 설정}`), 플러그인 자동 로드 끔.
- **케이스 교체**: 새 번호가 옛 번호를 "대체"로 가리키고 실패 기록을 이어받는다. 승인 번호와 묶이고 수에서 줄지 않는다.
- 케이스마다 출처 지적 번호와 묶인 도면. 수가 줄면 실패(승인 번호와 맞는 정리·교체만 예외).
- **불안정**: 같은 실행 전 지문으로 여러 번(설정값) 돌려 갈릴 때만. ⑦을 막고 시험자에게.
- **⓪ 시험 등록**: 시험자가 케이스를 쓰고 시험대 실행 요청으로 실패 기록을 남겨야 ①. 자동 재현 불가는 대표가 고르면 수동 케이스(캡처 전후·검토자 판정 줄·파일 경로 패턴)로 등록.

## 되돌림 두 가지

- **검토 불통과**: ⑥ → ⑤, 구현자 쓰기 창 다시 열림. 바퀴 상한, 2연속이면 다른 계열 1회.
- **명령 오류**: 구현자 표시 + 시험자 확인 → ⑤ → ③. 계획자가 plan.md, 시험자가 다음 번호 스크립트. 되돌림 상한.

## 작업 사본 합치기 (직원별 사본 모드)

훅 입력에 직원 식별이 없는 모드에서는 칸 경계마다 처리기가 각 사본을 기준 트리로 합친다. 검사는 **충돌 0, 사본별 허용 밖 변경 0**. 충돌이면 풀지 않고 멈춘다.

## 상한값·역할 구분

- 호출·바퀴·되돌림·시간·소형 파일 수·불안정 반복 수·요청 처리 시간 상한은 설정에, 바꾼 날과 이유를 적는다.
- 직원 식별이 훅 입력에 들어오는지 첫 시험에서 확인, 없으면 직원별 사본 모드.

## 첫 시험에서 확인할 항목 (확인 전까지 "추정")

1. 훅 입력에 직원 식별이 들어오는가.
2. 실행기·설치·probe가 전용 샌드박스에서 돌고 처리기는 결과만 읽는가. 설치 스크립트·플러그인 자동 로드 꺼짐.
3. 모델 호출 금지 설정이 대표 입력 명령 전부에서 작동하는가.
4. 칸마다: 보호 경로 쓰기 거부, 운영 키 읽기 거부, 허용 외 주소 차단, 설치본 지문 = 고정 버전, **닫힌 쓰기 창의 직원이 자기 파일도 못 쓰는가**.
5. 실행기가 프로젝트 시험 설정·conftest·플러그인을 읽지 않는가.
6. 메일·문자 시험 모드/중계가 수신처를 강제하는가.
7. 실행 사본에서 돌린 뒤 원본 지문 그대로인가. 무시 파일에 기대는 코드가 사본에서 실패로 드러나는가.
8. 임시 인덱스 `git commit`에서 pre-commit이 실제로 도는가.
9. **오래 걸리는 요청**(전체 시험대·설치)이 훅 시간 제한과 무관하게 처리기에서 끝나는가.
10. 뚫리는 장면 재현: 상태 파일 손상 / 옛 bench.json으로 커밋 / `conftest.py` 새 파일 / 변수 접두 / `git -c`·`--config-env` / `claude` 재호출 / 대기 줄 위조 / 허용 명령 뒤 출력 돌림 쓰기 / 맨 위 `.gitignore` 한 줄 추가 / **하위 폴더에 새 `.gitignore`** / **작업 트리 밖을 가리키는 링크 파일** / 전역 무시 설정이 다른 두 컴퓨터에서 지문 비교 / **대기열에 옛 지적이 있는데 복구 직후 새 지적** / **커밋 뒤 닫았을 때 보관본이 비어 있는가** / **⑥ 통과 뒤 구현자가 파일을 고치고 커밋 요청** / **대소문자만 다른 결과 파일 이름** / 설치 요청 전 허용 밖 변경을 남겨 두기 / design 폴더의 다른 파일을 "이거다" 뒤에 고치기.
