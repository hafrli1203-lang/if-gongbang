## 상태·대표 입력·대기열

- 상태 파일·마지막 처리 번호·queue.md·원문 기록은 **프로젝트 폴더**에 있어 일이 없어도 존재한다. 적용 목록에 있는 프로젝트는 상태 파일이 없거나 못 읽으면 막는다. 목록 밖은 v2가 꺼져 있다.
- 대표 입력만 인정하는 명령: `/일`, `지적`, `일 닫기`, `포기`, `일 복구`, `승인`. 명령 파일에 모델 호출 금지 설정을 넣고, 훅이 원문 기록으로 대표 입력인지 확인한다.
- 대기열 = 원문 기록의 `지적` 메시지 중 번호 > 마지막 처리 번호. 표시는 `queue.md`를 훅이 만든다(일지가 아니다). `/일`은 대기열이 비어 있을 때만 열린다.

## 케이스 관리

- 케이스는 두 종류: **지적 케이스**(⓪ 칸, 고치기 전 실패·고친 뒤 통과 둘 다)와 **장면 케이스**(③ 칸의 통과 장면 스크립트, ⑦에서 통과 기록만). 수는 따로 센다.
- 이름은 다음 번호만(쓰는 순간 훅이 허용). 실행기는 번호 형식 파일만 모은다.
- 실행기는 하네스 고정 설정으로 전용 샌드박스에서 돈다: 프로젝트 설정·`conftest.py` 무시(pytest는 `--noconftest -c {하네스 설정}`), 설치된 패키지의 플러그인 자동 로드 끔, 다른 도구도 같은 뜻의 옵션. 케이스는 공용 준비 코드 없이 쓴다.
- **케이스 교체**: 케이스 본체를 고치는 유일한 길. 새 번호 케이스가 옛 번호를 "대체"로 가리키고 옛 번호의 실패 기록을 이어받는다. 교체는 대표 승인(원문 번호)과 묶이고, 수에서는 옛 번호를 대체된 것으로 세어 줄지 않는다.
- 케이스마다 출처 지적 번호와 묶인 도면. 도면 변경과 케이스 정리는 한 묶음으로 대표 승인. 케이스 수가 줄면 실패(승인 번호와 맞는 정리·교체만 예외). 수동 케이스 수도 같다.
- **불안정** 판정은 실행기가 같은 실행 전 지문으로 여러 번(설정값, 처음 5회) 돌려 결과가 갈릴 때만. 통과 수에서 빼되 ⑦은 막는다. 면제는 승인 번호와 유효 기한이 있을 때만. 불안정이 나면 시험자에게(케이스 쪽이면 교체, 코드 쪽이면 재현 조건을 적어 ⑤로).
- **⓪ 시험 등록**: 시험자가 케이스를 쓰고 시험대 실행 요청으로 실패 기록을 남겨야 ①이 열린다. 자동 재현이 불가능한 지적은 대표가 "자동 시험 불가"를 고르면 수동 케이스(고치기 전 캡처·고친 뒤 캡처·검토자 판정 줄 + 묶인 파일 경로 패턴)로 등록되고 ⓪이 닫힌다. 수동 케이스는 바뀐 파일이 패턴과 겹치는 일에서 판정표에 자동으로 다시 올라온다(패턴이 비면 매번).

## 되돌림 두 가지

- **검토 불통과**: ⑥ → ⑤. 바퀴 상한(설정값)을 넘으면 멈추고 대표에게. 두 바퀴 연속이면 다른 계열 점검 1회.
- **명령 오류**: 구현자가 표시하고 시험자가 확인하면 ⑤ → ③. 계획자가 plan.md의 장면↔스크립트 번호를 고치고(편집 행의 조건) 시험자가 다음 번호로 스크립트를 쓴다. 되돌림 횟수에도 상한.

## 작업 사본 합치기 (직원별 사본 모드)

훅 입력에 직원 식별이 없어 경로로 역할을 구분하는 모드에서는 **칸 경계마다** 궤도 스크립트가 각 사본을 기준 트리로 합친다. 합친 기준 트리의 지문이 기록값과 다르면 자동으로 ⑥, 충돌이 나면 풀지 않고 멈춘다.

## 상한값·역할 구분

- 호출 상한·바퀴 상한·되돌림 상한·시간 상한·소형 궤도 파일 수·불안정 반복 수는 설정에 있고, 바꾼 날과 이유를 적는다. 터미널 비율은 계기판 지표다.
- 직원 식별이 훅 입력에 들어오는지 첫 시험에서 확인하고, 없으면 직원별 사본 모드. 확인 전까지 역할별 훅은 "추정".

## 보호 파일 목록

두 부류(§정의): **장치 기록**은 훅·궤도 스크립트만 쓰고, **설정**은 대표 승인 관문으로만 바뀐다(바꾼 날·이유 기록). 설치본 복사는 대표가 본인 터미널에서.

| 부류 | 파일 | 왜 |
|---|---|---|
| 장치 기록 | 프로젝트 폴더 `state/` `records/` `일지.jsonl` | 상태·대기열·대표 입력 근거·케이스가 가리키는 일지 |
| 장치 기록 | 일 폴더 `records/` `bench/` `snapshots/` `leftover/` `requests/*.result` | 검사 근거·시험 결과·복원 기준·남은 변경·요청 결과 |
| 장치 기록 | `.git/` 전체(직원 읽기 전용, 커밋·push는 궤도 스크립트) | 훅 경로·가지 위치 |
| 설정 | 설정 파일(임계값·훅별 모드·제외 목록·적용 프로젝트 목록·배포 산출물 경로·고지 예외 문단·공개용 커밋 신원·허용 목록·금지 목록) | 느슨하게 고치면 모든 관문이 느슨해진다 |
| 설정 | 훅 스크립트 폴더, 훅 등록 전역 설정, 설치 폴더(버전 고정 복사본, 링크 금지), 프로젝트 `.claude/`, 서버 쪽 자동 검사 설정 | 훅을 고치거나 끄는 자리 |
| 설정 | 도면, `.gitignore` | 케이스 정리의 근거 / 커밋 범위를 바꾸는 자리 |
| 쓰기 거부 | 의존성 폴더(설치는 궤도 스크립트), 시험 설정 파일·`conftest.py`(소유 불가), 작업 트리 밖 비밀 파일·운영 키(읽기도 거부) | 시험 결과와 외부 호출을 바꾸는 자리 |

## 첫 시험에서 확인할 항목 (확인 전까지 "추정")

1. 훅 입력에 직원 식별이 들어오는가.
2. 실행기·설치가 전용 샌드박스에서 돌고, 궤도 스크립트는 결과만 읽는가. 설치 스크립트·플러그인 자동 로드가 꺼져 있는가.
3. 모델 호출 금지 설정이 설치 버전에서 작동하는가(`/일`·지적·닫기·포기·복구·승인).
4. 칸마다 도는 확인: 보호 경로 쓰기 거부, 운영 키 위치 읽기 거부, 허용 외 주소 통신 차단, 설치본 지문 = 고정 버전.
5. 실행기가 프로젝트 시험 설정·`conftest.py`·설치된 플러그인을 읽지 않는가(케이스 하나를 빼는 설정·플러그인을 넣고도 그 케이스가 도는가).
6. 메일·문자 서비스의 시험 모드/중계가 수신처를 실제로 강제하는가.
7. 실행 사본에서 돌린 뒤 원본의 지문이 그대로인가. 커밋 트리 범위로 뜬 사본에서 무시 파일에 기대는 코드가 실패로 드러나는가.
8. 임시 인덱스 `git commit`에서 pre-commit 훅이 실제로 도는가.
9. 뚫리는 장면 재현: 상태 파일 손상 / 옛 bench.json으로 커밋 / `conftest.py` 새 파일 / 변수 접두 / `git -c`·`--config-env` / `claude` 재호출 / 대기 줄 위조 / 허용 명령 뒤 출력 돌림 쓰기 / `.gitignore`에 한 줄 추가 / 무시 파일이 커밋에 들어가는가.
