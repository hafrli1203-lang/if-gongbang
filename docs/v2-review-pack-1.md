# IF 공방 v2 — 장치 1: 정의와 검사

`v2.md`의 궤도 표와 직원 표가 "무엇을 막는가"라면, 이 문서는 "어떻게 막는가"다. 원칙은 하나: **AI가 적은 글을 믿지 않고, 훅이 따로 남긴 기록과 대조한다.** 여러 곳에서 쓰는 정의는 **이 문서 §정의에만** 두고, 다른 문서는 여기를 가리킨다. 자리 표시는 {이름}처럼 중괄호로 쓴다.

## 정의 (단일 출처)

| 용어 | 정의 |
|---|---|
| **작업 트리** | 프로젝트 폴더. 직원이 코드를 고치는 곳. **비밀 파일(.env 등)과 운영 키는 작업 트리 안에 두지 않는다** — 작업 트리 밖 보호 위치에만 있고, 샌드박스에는 테스트 값이 환경으로 주입된다 |
| **하네스 홈** | 작업 트리 밖. `jobs/{일 이름}/`(일 폴더), `projects/{프로젝트}/`(도면·작업 일지·대기 화면), 설정·훅·설치본 |
| **일 폴더** | `jobs/{일 이름}/` 하위: `state/`(상태 파일, 마지막 처리 번호), `records/`(실행·원문·열람·편집 기록), `outputs/`(facts.md·plan.md·tools.md·design/·coverage.md·review.md·report.md — 직원별 자기 파일 하나만), `bench/`(bench.json·케이스 수·지문), `snapshots/`(칸 시작 사본), `leftover/`(닫을 때 남은 변경). 직원 쓰기 파일(`outputs/`)과 장치 기록은 **다른 하위 폴더** |
| **도면·작업 일지** | `projects/{프로젝트}/도면.md`, `일지.jsonl` — 작업 트리 밖(안에 두면 덧붙일 때마다 지문이 바뀐다). 일지는 덧붙이기만. 대기열 표시는 일지가 아니라 `state/queue.md`를 훅이 만든다 |
| **보호 파일 — 장치 기록** | 훅과 궤도 스크립트가 **늘 쓰는** 것: `state/`·`records/`·`bench/`·`snapshots/`·`leftover/`·`queue.md`, 작업 일지(덧붙이기), `.git/`(커밋 때 궤도 스크립트가 씀). 직원과 반장은 못 쓴다 |
| **보호 파일 — 설정** | **대표 승인 관문으로만** 바뀌는 것: 설정 파일(임계값·모드·제외 목록·적용 프로젝트 목록·고지 예외·공개용 커밋 신원·허용 목록), 훅 스크립트 폴더, 훅 등록 전역 설정, 하네스 설치 폴더(버전 고정 복사본, 링크 금지), 프로젝트 `.claude/`, 서버 쪽 자동 검사 설정, 도면, 공개 push 금지 목록 |
| **허용 경로** | 직원이 쓸 수 있는 경로. 구현자 = plan.md 소유표, 시험자 = `tests/bench/`(번호 이름만), 실측자 = `scripts/probe/`, 시안자 = `outputs/design/`, 사실확정자·계획자·검토자 = `outputs/` 안 자기 파일 하나. **샌드박스 쓰기 허용 = 편집 도구 허용 = 이 표**. 의존성 폴더는 누구도 못 쓴다 |
| **제외 목록** | 보호된 설정에 있는 세 가지: 의존성 폴더(잠금 파일은 제외하지 않음), 빌드 산출물, `.claude/` |
| **감시 지문** | 변화 감시용. 작업 트리 전체(추적·미추적·무시 파일 포함) − 제외 목록을 임시 인덱스에 담아 `git write-tree`. 객체는 임시 저장소에 썼다 버린다 |
| **커밋 트리** | 커밋용. `.gitignore`를 따르는 범위(추적 + 무시되지 않은 미추적) − 제외 목록. 제외 경로 가운데 HEAD가 추적 중인 것은 **HEAD의 트리 항목을 그대로 옮긴다**(빼면 삭제로 남는다). 무시 파일(.env·로그·캐시)은 커밋에 들어가지 않는다 |
| **지문 쌍** | 감시 지문과 커밋 트리를 **같은 순간, 같은 사본에서** 궤도 스크립트가 함께 뽑은 값. 검토·시험 기록에는 둘 다 적히고, 커밋 관문은 **둘 다** 기록값과 같을 때만 연다 |
| **사본·비교·복원 범위** | 감시 지문 범위와 **같다**. 칸 시작 때 그 범위의 내용 사본을 `snapshots/`에 뜨고, 명령 뒤·칸 끝 비교는 사본과 해시로 하며, 복원은 사본에서 허용 경로 밖 파일을 되돌리고 칸 시작 때 없던 파일을 지운다. HEAD 기준이 아니다 |
| **실행 사본** | 장면 스크립트·시험·설치를 돌리는 **일회용 사본**. 원본은 실행으로 바뀌지 않는다(캐시·로그는 사본에 생기고 버려진다). 실행 기록에는 **실행 전** 지문 쌍을 적는다 |
| **기준 트리** | 직원별 작업 사본 모드(역할을 경로로 구분할 때)에서, 칸 경계마다 궤도 스크립트가 각 사본을 합쳐 만든 트리. 그 모드에서는 지문·사본·실행 사본을 **기준 트리 기준**으로 정의한다 |
| **원문 기록** | 입력 훅이 대표 메시지를 번호와 함께 그대로 쌓는 파일. 출력 훅은 **시안·채점표를 보여 준 시점**도 같은 번호 열에 줄로 남긴다 — 인용 순서 검사의 근거 |
| **실행 기록** | 훅이 쌓는 줄: 명령, 종료 코드, 시각, 실행 전 지문 쌍, 실행 주체, 실행 사본 식별 |
| **열람 기록 · 편집 기록** | 훅이 쌓는 줄: 열어 본 웹 문서·곳간 검색·probe 로그 / 어느 직원이 어느 파일을 언제 고쳤나 |
| **적용 프로젝트 목록** | v2가 켜진 프로젝트 목록(설정). 넣고 빼는 것은 승인 관문. 넣는 동작이 상태 파일을 「닫힘」으로 만들고 `projects/{프로젝트}/`를 만든다 |
| **전용 샌드박스(실행기·설치)** | 궤도 스크립트가 시험 실행기와 의존성 설치를 띄우는 샌드박스. 쓰기는 실행 사본의 결과 폴더와 의존성 폴더만, 운영 키 없음, 통신은 허용 주소만, 설치 스크립트(postinstall 등) 실행은 기본 꺼짐. 궤도 스크립트는 결과 파일만 읽어 `bench/`로 옮긴다 |

## 검사 원칙 — 자기신고를 믿지 않는다

- **실행 기록**: 구현 칸의 "돌렸다"와 보고의 「실측」 절은 실행 기록에 plan.md가 통과 장면마다 고른 `tests/bench/scenes/` 스크립트가 글자 그대로, 종료 코드 0으로, **실행 전 지문 쌍 = 지금 지문 쌍**으로 있어야 인정된다. 실행은 실행 사본에서, 실행기는 전용 샌드박스에서 돈다 — "실행기는 밖, 코드는 안"이 아니라 **둘 다 전용 샌드박스 안**이고 궤도 스크립트는 결과만 읽는다. 실행기 설정은 하네스 쪽 고정 설정(플러그인 자동 로드 끔 포함, `v2-devices-2.md` 케이스 관리).
- **칸 끝 비교**: 사본과 비교해 허용 경로 밖 변경이 있으면 다음 칸을 열지 않고 복원한다. 검토자 칸에서 변경이 있으면 판정 무효.
- **벽은 샌드박스**: 터미널이 있는 칸은 샌드박스에서 돌아 허용 경로 밖 쓰기가 파일 시스템 단위로 거부된다. 명령 검사와 칸 끝 비교는 뒤에서 확인하는 장치다. 검토자는 일회용 작업 사본(운영 키 없음 — 비밀 파일이 작업 트리 밖이라 사본과 원본의 지문이 같다)에서 일하고, 판정 근거 실행은 사본 지문 쌍 = 원본 지문 쌍일 때만 인정한다.
- **소유표 = 샌드박스 허용 경로**: 구현자는 터미널로도 남의 파일을 못 고친다. 공용 파일은 구현자 한 명에게 배정돼야 계획이 통과되고, 미배정 파일이 필요하면 ③으로 되돌려 소유표를 고친다(민감 영역 파일만 대표 승인). `conftest.py`와 시험 설정 파일은 소유표에 배정할 수 없다.
- **대표 원문 인용**: "이거다", 채점표 선택, 건너뛰기 사유는 원문 기록의 **메시지 번호**와 글자 그대로 맞고, 그 번호가 출력 훅이 남긴 **시안·채점표 제시 줄보다 뒤**여야 칸이 열린다.
- **출처는 열람 기록과 대조**: facts.md 「통과」 줄의 출처는 열람 기록에 있어야 인정된다. 「통과」 줄마다 출처가 있어야 하고, 외부 값은 probe 로그의 같은 키와 스크립트가 대조한다(표 형식 `키 | 값 | 판정 | 출처`, 키는 `{대상}.{필드}`).
- **소형 궤도 재판정**: 계획의 파일 수로 한 번, ⑤가 끝날 때 실제 변경분(감시 지문 범위)으로 한 번 더. 민감 영역 기준은 설정 파일의 경로·패키지·외부 주소·명령 패턴이다(`v2.md`).
