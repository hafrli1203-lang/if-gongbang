# IF 공방 v2 — 장치 1: 정의와 검사

`v2.md`의 궤도 표와 직원 표가 "무엇을 막는가"라면, 이 문서는 "어떻게 막는가"다. 원칙은 하나: **AI가 적은 글을 믿지 않고, 훅이 따로 남긴 기록과 대조한다.** 여러 곳에서 쓰는 정의는 **이 문서 §정의에만** 두고, 다른 문서는 여기를 가리킨다. 자리 표시는 {이름}처럼 중괄호로 쓴다.

모형은 세 줄이다. ① 장치가 쓰는 것과 비밀은 작업 트리 밖에 둔다. ② 범위는 하나 — **커밋 트리 범위**다. 지문·사본·실행·검토·비교·복원이 전부 이 범위를 쓴다. ③ 직원이 장치에 시키는 일은 전부 **요청** 한 길로 간다.

## 정의 (단일 출처)

| 용어 | 정의 |
|---|---|
| **작업 트리** | 프로젝트 폴더. 코드·`tests/bench/`·`scripts/probe/`·추적 설정만 있다. **비밀 파일(.env 등)·운영 키·장치 기록·일 산출물은 작업 트리 안에 두지 않는다.** 샌드박스에는 테스트 값이 환경으로 주입된다 |
| **하네스 홈** | 작업 트리 밖. 아래 프로젝트 폴더·일 폴더·설정·훅·설치본이 있다 |
| **프로젝트 폴더** | `projects/{프로젝트}/` — 일을 넘어 이어지는 것: `state/`(상태 파일: 열린 일 이름 또는 「닫힘」, **마지막 처리 번호**, `queue.md`), `records/원문.jsonl`(대표 메시지와 출력 훅의 제시 줄, **프로젝트 단위 일련번호**), `도면.md`, `일지.jsonl`(덧붙이기만). 적용 프로젝트 목록에 넣는 승인 동작이 이 폴더와 「닫힘」 상태 파일을 만든다 |
| **일 폴더** | `jobs/{프로젝트}/{일 이름}/` — 그 일만의 것: `outputs/`(산출물, 아래 주인 표), `requests/`(요청 파일과 결과), `records/`(실행·열람·편집 기록), `bench/`(bench.json·케이스 수·지문), `snapshots/`(칸 시작 사본), `leftover/`(닫을 때 남은 변경). 지적에서 자동으로 열리는 일의 이름은 `지적-{번호}` |
| **산출물 주인** | `outputs/facts.md` 사실확정자 · `outputs/plan.md`·`outputs/tools.md` 계획자 · `outputs/design/`(폴더) 시안자 · `outputs/coverage-{구현자}.md` 각 구현자(궤도 스크립트가 합침) · `outputs/review.md` 검토자 · `outputs/report.md` 반장(편집 도구로 이 파일만) · `outputs/requests/` 요청을 낼 수 있는 모든 직원(자기 요청 파일만). 그 밖의 쓰기: 구현자 = plan.md 소유표, 시험자 = `tests/bench/`(번호 이름), 실측자 = `scripts/probe/` |
| **허용 경로** | 위 「산출물 주인」 표 그대로. **샌드박스 쓰기 허용 = 편집 도구 허용 = 이 표.** 의존성 폴더·`.gitignore`·시험 설정 파일·`conftest.py`는 누구의 소유도 될 수 없다 |
| **제외 목록** | 설정에 있는 세 가지: 의존성 폴더, 빌드 산출물, `.claude/`. 적용 프로젝트에 넣을 때 이 경로가 저장소에 **추적 중인지 검사**해, 추적 중이면 (가) 추적 해제 (나) 「배포 산출물 경로」로 등록(궤도 스크립트가 배포 단계에서 새로 빌드해 따로 커밋) 중 하나를 고르게 한다. `.claude/`가 추적 중이면 설정 변경은 승인 관문이 승인 번호를 메시지에 적어 **따로 커밋**한다 |
| **커밋 트리 범위** | `.gitignore`를 따르는 범위(추적 + 무시되지 않은 미추적) − 제외 목록. **이 하나의 범위가** 지문·사본·실행 사본·검토자 사본·비교·복원·소형 재판정·leftover 전부의 범위다 |
| **지문** | 커밋 트리 범위를 임시 인덱스에 담아 `git write-tree`로 뽑은 트리 해시(객체는 임시 저장소). 제외 경로 가운데 HEAD가 추적 중인 것은 HEAD의 트리 항목을 그대로 옮긴다(배포 산출물 경로는 배포 커밋에서 갱신) |
| **사본** | 커밋 트리 범위로 뜬다 + 의존성은 설치로 + 테스트 값은 환경 주입으로. 칸 시작 사본(`snapshots/`), 실행 사본(일회용, 장면·시험·설치가 돈다), 검토자 사본(일회용), 직원별 작업 사본 — 전부 같은 규칙. **시험한 것 = 검토한 것 = 커밋하는 것** |
| **비교·복원** | 칸 끝과 명령 뒤에 지금 커밋 트리와 칸 시작 사본을 비교해 허용 경로 밖 변경을 찾고, 사본에서 되돌리며 칸 시작 때 없던 파일을 지운다. HEAD 기준이 아니다. **무시 파일에 AI가 쓰는 것은 비교가 아니라 샌드박스 거부만이 막는다**(한계로 적어 둔다) |
| **소형 재판정** | ⑤가 끝날 때 **커밋 트리와 HEAD의 차이**(파일 수·경로)로 승격 조건을 다시 본다 |
| **실행 기록** | 훅이 쌓는 줄: 요청 번호, 명령, 종료 코드, 시각, **실행 전 지문**, 실행 주체, 사본 식별. 판정 근거로 인정되는 조건: 실행 전 지문 = 지금 지문, 종료 코드 0 |
| **열람 기록 · 편집 기록** | 훅이 쌓는 줄: 열어 본 웹 문서·곳간 검색·probe 로그 / 어느 직원이 어느 파일을 언제 고쳤나 |
| **제시 줄** | 출력 훅이 원문 기록에 남기는 줄. 조건은 AI 표시가 아니라 **답 본문에 `outputs/design/` 파일 경로가 있고 그 파일이 편집 기록에 있을 때**이며, 훅이 파일 해시를 줄에 함께 적는다. "이거다"·채점표 선택 인용은 이 줄보다 뒤 번호여야 한다 |
| **요청** | 직원이 `outputs/requests/{번호}.md`에 쓰는 파일. 종류: 장면 실행, 시험대 실행, 설치, 일지 덧붙이기, 커밋, 합치기. 궤도 스크립트만 처리하고 결과를 `requests/{번호}.result`와 실행 기록에 남긴다. 터미널 명령이 아니라 **파일 쓰기**이므로 허용 목록에 명령이 없어도 된다. 종류별 허용 칸·주체는 `v2-devices-2.md` 훅 표 「요청」 |
| **전용 샌드박스** | 궤도 스크립트가 실행기·설치를 띄우는 곳. 쓰기는 실행 사본의 결과 폴더와 그 사본의 의존성 폴더만, 운영 키 없음, 통신은 허용 주소만, 설치 스크립트(postinstall 등) 실행 기본 꺼짐, 플러그인 자동 로드 꺼짐. 궤도 스크립트는 결과 파일(bench 결과·잠금 파일)만 읽어 옮긴다 |
| **설치** | 설치 요청 → 전용 샌드박스에서 잠금 파일 생성과 설치 → 궤도 스크립트가 잠금 파일을 작업 트리에 반영(장치가 쓴 것이라 허용 경로 밖 변경이 아니다) → **칸 시작 사본을 새로 뜨고** 구현 칸 재개 |
| **보호 파일 — 장치 기록** | 훅·궤도 스크립트만 쓴다: 프로젝트 폴더 `state/`·`records/`·`일지.jsonl`, 일 폴더 `records/`·`bench/`·`snapshots/`·`leftover/`·`requests/*.result`, `.git/`(커밋은 궤도 스크립트) |
| **보호 파일 — 설정** | 대표 승인 관문으로만 바뀐다: 설정 파일(임계값·훅별 모드·제외 목록·적용 프로젝트 목록·배포 산출물 경로·고지 예외·공개용 커밋 신원·허용 목록·금지 목록), 훅 스크립트 폴더·훅 등록 전역 설정·설치 폴더(버전 고정 복사본, 링크 금지)·프로젝트 `.claude/`·서버 쪽 자동 검사 설정, 도면, `.gitignore`(민감 영역 경로이기도 하다) |
| **기준 트리** | 직원별 작업 사본 모드에서 칸 경계마다 궤도 스크립트가 각 사본을 합쳐 만든 트리. 그 모드에서 지문·사본은 기준 트리 기준 |
| **적용 프로젝트 목록** | v2가 켜진 프로젝트(설정). 넣고 빼는 것은 승인 관문 |

## 검사 원칙 — 자기신고를 믿지 않는다
