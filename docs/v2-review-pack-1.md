# IF 공방 v2 — 장치 1: 정의와 검사

`v2.md`의 궤도 표와 직원 표가 "무엇을 막는가"라면, 이 문서는 "어떻게 막는가"다. 원칙은 하나: **AI가 적은 글을 믿지 않고, 훅이 따로 남긴 기록과 대조한다.** 여러 곳에서 쓰는 정의는 **이 문서 §정의에만** 두고, 다른 문서는 여기를 가리킨다.

## 정의 (단일 출처)

| 용어 | 정의 |
|---|---|
| **작업 트리** | 프로젝트 폴더. 직원이 코드를 고치는 곳 |
| **일 폴더** | 하네스 홈 `jobs/<일 이름>/` — **작업 트리 밖**이다. 하위 폴더: `state/`(상태 파일, 마지막 처리 메시지 번호), `records/`(실행 기록·원문 기록·열람 기록·편집 기록 — 훅만 씀), `outputs/`(facts.md·plan.md·tools.md·design/·coverage.md·review.md·report.md — 직원별로 자기 파일 하나씩만 씀), `bench/`(bench.json·케이스 수·코드 지문 — 궤도 스크립트만 씀), `snapshots/`(칸 시작 사본 — 훅만 씀). 보호 파일과 직원 쓰기 파일은 **다른 하위 폴더**에 있어 폴더 단위로 열어도 섞이지 않는다 |
| **보호 파일** | `state/`·`records/`·`bench/`·`snapshots/` 전체, 설정 파일, 훅 스크립트 폴더, 훅 등록 전역 설정, 하네스 설치 폴더, 프로젝트 `.claude/`, `.git/` 전체(읽기 전용), 서버 쪽 자동 검사 설정, 도면, 작업 일지(덧붙이기만). 쓰기·편집 도구와 샌드박스 양쪽에서 거부. 고치는 길은 대표 승인 관문 하나(표: `v2-devices-2.md` 「보호 파일 목록」) |
| **허용 경로** | 직원이 쓸 수 있는 경로. 구현자는 plan.md 소유표, 시험자는 `tests/bench/`(번호 이름만), 실측자는 `scripts/probe/`, 시안자는 `outputs/design/`, 사실확정자·계획자·검토자는 `outputs/` 안 자기 파일 하나. **샌드박스 쓰기 허용 = 편집 도구 허용 = 이 표** — 셋이 같은 표를 읽는다 |
| **지문 범위** | 작업 트리 전체(추적·미추적·무시 파일 포함) − 제외 목록. 제외 목록은 보호된 설정에 있고 셋뿐이다: 의존성 폴더(잠금 파일은 **포함**), 빌드 산출물, `.claude/`. 일 폴더는 작업 트리 밖이라 처음부터 들어가지 않는다 |
| **지문** | 지문 범위를 **임시 인덱스**에 담고 `git write-tree`로 뽑은 트리 해시. 객체는 **임시 저장소**에 썼다 버린다(`.git` 읽기 전용과 맞고 불어나지 않는다). 커밋 트리도 **같은 규칙**으로 궤도 스크립트가 만든다 — 지문 트리와 커밋 트리가 갈라질 수 없고, 제외 목록 파일이 저장소에 추적되어 있어도 커밋에 들어가지 않는다 |
| **사본·비교·복원 범위** | 지문 범위와 **같다**. 칸 시작 때 그 범위의 내용 사본을 `snapshots/`에 뜨고, 명령 뒤·칸 끝 비교는 사본과 해시로 하며(`git status`가 아니다 — 무시 파일 내용 변화를 못 본다), 복원은 사본에서 허용 경로 밖 파일을 되돌리고 칸 시작 때 없던 파일을 지운다. HEAD 기준이 아니다(앞 칸 변경은 커밋 전이다) |
| **원문 기록** | 입력 훅이 대표 메시지를 번호와 함께 그대로 쌓는 파일. 대표 인용·승인·지적·대기열은 모두 이 번호로 읽는다 |
| **실행 기록** | 훅이 쌓는 줄: 명령, 종료 코드, 시각, **그 순간의 지문**, 실행 주체 |
| **열람 기록** | 훅이 쌓는 줄: 열어 본 웹 문서 주소, 곳간 검색 결과, probe 로그 |
| **편집 기록** | 훅이 쌓는 줄: 어느 직원이 어느 파일을 언제 고쳤나 |
| **적용 프로젝트 목록** | v2가 켜진 프로젝트 목록(보호된 설정). 넣고 빼는 것은 승인 관문이고, 넣는 동작이 상태 파일을 「닫힘」으로 만든다 |

## 검사 원칙 — 자기신고를 믿지 않는다

- **실행 기록**: 구현 칸의 "돌렸다"와 보고의 「실측」 절은 실행 기록에 **plan.md가 통과 장면마다 고른 `tests/bench/scenes/` 스크립트**가 글자 그대로, 종료 코드 0으로, **지금 지문과 같은 지문**으로 있어야 인정된다("마지막 편집보다 뒤"는 시각이 아니라 지문으로 본다). 계획자는 어느 스크립트를 쓸지 고르기만 하고 내용은 시험자가 쓴다. 실행기가 읽는 설정은 **하네스 쪽 고정 설정**이다(§케이스 관리).
- **칸 끝 비교**: 칸이 끝날 때 사본과 비교해 허용 경로 밖 변경이 있으면 다음 칸을 열지 않고 복원한다. 검토자 칸에서 변경이 있으면 판정 무효.
- **벽은 샌드박스**: 터미널이 있는 칸은 샌드박스에서 돌아 허용 경로 밖 쓰기가 파일 시스템 단위로 거부된다. 명령 검사와 칸 끝 비교는 뒤에서 확인하는 장치다. 검토자는 **일회용 작업 사본**(쓰기 허용, 칸 끝 폐기, 운영 키·`.env` 없음)에서 일하고, 판정 근거 실행은 사본이 원본과 같은 지문일 때 돌린 것만 인정한다.
- **소유표 = 샌드박스 허용 경로**: 구현자는 터미널로도 남의 파일을 못 고친다. 공용 파일은 구현자 한 명에게 배정돼야 계획이 통과되고, 미배정 파일이 필요하면 ③으로 되돌려 소유표를 고친다(민감 영역 파일만 대표 승인). `conftest.py`와 시험 설정 파일은 소유표에 배정할 수 없다.
- **대표 원문 인용**: "이거다", 채점표 선택, 건너뛰기 사유는 원문 기록의 **메시지 번호**와 글자 그대로 맞고, 그 메시지가 시안·채점표를 보여 준 **뒤**에 온 것이어야 칸이 열린다.
- **출처는 열람 기록과 대조**: facts.md 「통과」 줄의 출처는 열람 기록에 있어야 인정된다. 「통과」 줄마다 출처가 있어야 하고, 외부 값은 probe 로그의 같은 키와 **스크립트가** 대조한다(표 형식 `키 | 값 | 판정 | 출처`, 키는 `<대상>.<필드>`).
- **소형 궤도 재판정**: 계획의 파일 수로 한 번, ⑤가 끝날 때 실제 변경분(지문 범위)으로 한 번 더. 민감 영역 기준은 설정 파일의 경로·패키지·외부 주소·명령 패턴이다(`v2.md`).
- **지문과 커밋**: 검토와 시험을 마친 시점에 **궤도 스크립트가** 지문을 `bench/`의 review 지문·bench.json에 적는다. 커밋 관문은 그 지문과 지금 지문이 같을 때만 열고, 다르거나 없으면 ⑥으로. 커밋은 궤도 스크립트가 지문 규칙의 트리로 친다. 직원도 대표도 작업 트리에서 `git commit`을 치지 않는다.
- **의존성**: 모든 직원 샌드박스에서 의존성 폴더 쓰기는 거부된다. 잠금 파일 해시가 바뀌면 궤도 스크립트가 **칸 사이에서** 잠금 파일 그대로 설치하고(`npm ci`·`pip sync` 방식) 실행 기록에 남긴다. 검토자 일회용 사본의 의존성도 궤도 스크립트가 같은 방식으로 갖춘다.
- **운영 키·외부 통신**: 운영 키는 작업 트리 밖, 직원 샌드박스가 읽을 수 없는 곳에만 있다(승인은 운영 키를 주지 않는다 — 테스트 계정으로 쓰기 1회가 짧은 창 동안 열릴 뿐). 구현자·검토자·실측자 샌드박스는 허용 주소로만 통신한다. 주소 차단은 수신처를 거르지 못하므로, 메일·문자류는 **서비스 쪽 시험 모드나 중계**로 테스트 수신처를 강제한다(서비스마다 그 설정이 있는지 첫 시험에서 확인).
- **같은 계열 교차**: 검토 불통과가 두 바퀴 연속이면 다른 계열 점검 1회. 검토자 통과·다른 계열 P0/P1이면 자동으로 ⑤로, P2/P3는 기록, 판정 자체가 갈리면 대표에게. 배포 관문은 그 결과가 올 때까지 닫혀 있다.
- **지적 번호**: 검토 지적은 번호를 달고 바퀴를 넘어 이어진다. 이전 번호/새 번호 표시가 없는 판정은 무효. 멈출 조건은 번호로 센다.

## 울타리 — 막는 훅 (단일 기준표)
