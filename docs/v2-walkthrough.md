# IF 공방 v2 — 흐름 한 바퀴와 우회 대조

규칙을 고칠 때마다 이 문서를 처음부터 다시 따라간다. 멈추는 곳이나 뚫리는 곳이 나오면 규칙이 틀린 것이다. 정의는 `v2-devices.md` §정의. 자리 표시는 {이름}.

## 정상 흐름 한 바퀴

| 칸 | 누가 | 무엇을 어디에 쓰나 | 검사가 무엇과 대조하나 | 막힐 수 있던 곳 → 해결 |
|---|---|---|---|---|
| 일 열기 | 대표 `/일` 또는 `지적`(닫힘 상태면 즉시, 일 이름 `지적-{번호}`) | 훅이 프로젝트 `state/`를 「열림」으로, 일 폴더 생성 | 대표 입력인지(원문 기록), 대기열 비어 있는지 | 상태 파일이 일 폴더에 있어 일이 없으면 상태도 없음 → 상태·번호·대기열·원문 기록은 프로젝트 폴더 |
| ⓪ 시험 등록(지적 일) | 시험자 | `tests/bench/{다음 번호}`; **시험대 실행 요청** → 궤도 스크립트가 전용 샌드박스의 실행 사본에서 실패를 기록 | 실패 기록의 실행 전 지문 = 지금 지문 | 실행이 원본 지문을 바꿈 → 실행 사본 |
| ① 사실확정 | 사실확정자 | `outputs/facts.md` | 통과 줄 출처 ∈ 열람 기록, 확인 필요 0 | — |
| ② 실측 | 실측자(샌드박스, 테스트 값 주입) | `scripts/probe/{대상}.log` | probe 키 = facts 키(스크립트) | 운영 키 읽기 → 작업 트리 밖 + 읽기 거부 |
| ③ 계획 | 계획자 / 시험자 | `outputs/plan.md`·`outputs/tools.md` / `tests/bench/scenes/{다음 번호}`(장면 케이스, 장면 실행 요청으로 돌려 본다) | 소유 겹침 0, 공용 파일 배정, 의존성 폴더·.gitignore·시험 설정·conftest 미배정 | tools.md 주인 없음 → 계획자 |
| ④ 시안 | 시안자 | `outputs/design/`(폴더) | "이거다" 번호 > 제시 줄 번호. 제시 줄은 **답 본문에 design/ 파일 경로가 있고 그 파일이 편집 기록에 있을 때** 훅이 해시와 함께 남긴다 | AI가 "시안 제시"라고 쓰면 줄이 생김 → 파일 경로+편집 기록 조건 |
| ⑤ 구현 | 구현자(소유표 = 샌드박스 허용 경로) | 소유 파일, `outputs/coverage-{구현자}.md`, **요청**(장면 실행·설치·커밋) | 장면 스크립트 실행 기록(종료 0, 실행 전 지문 = 지금), 명령 뒤·칸 끝 사본 비교, 커밋 트리 vs HEAD로 소형 재판정 | 새 패키지 → manifest 수정 + 설치 요청 → 잠금 파일 반영 → **칸 시작 사본 새로 뜸** → 재개. 시험 실행기가 허용 목록에 없음 → 요청으로만 |
| ⑥ 검토 | 검토자(일회용 사본, 커밋 트리 범위) → 궤도 스크립트 | `outputs/review.md`; 궤도 스크립트가 지문을 `bench/`에 | coverage 「들어감」 근거, ⓪ 재현, scenes 편집 기록, 사본 지문 = 원본 지문, 지적 번호 | 사본에 비밀 파일이 없어 지문 불일치 → 사본 범위가 커밋 트리라 비밀 파일은 애초에 범위 밖 |
| ⑦ 시험대 | 궤도 스크립트(전용 샌드박스, 실행 사본) | `bench/bench.json`(pass, 지문, 케이스 수) | 케이스 수 ≥ 이전(대체 포함), 불안정 0, 플러그인 자동 로드 꺼짐 | 캐시로 지문 변화 → 실행 사본 |
| 커밋 | 구현자 커밋 요청 → 궤도 스크립트 | 임시 인덱스 `git commit` | `bench/` 지문 = 지금 지문 | commit-tree면 pre-commit이 안 돎 → `git commit`으로 |
| 배포 | 궤도 스크립트 + 서버 쪽 검사 | 배포 산출물 경로는 새로 빌드해 따로 커밋 | 지문 일치, 교차 점검 결과 도착 | 늦은 P0 → 배포 관문만 닫음 |
| ⑧ 보고 | 반장(터미널 없음, 편집은 report.md만) | `outputs/report.md` | 「실측」 절 ∈ 실행 기록, 대조표 = ⑥ 확인본 | 상태 줄 자동 부착 |
| 일 닫기 | 대표 `일 닫기` | 훅이 「닫힘」, 마지막 처리 번호 갱신; 궤도 스크립트가 **일 시작 사본과 비교해** 이 일의 변경만 `leftover/`로 | 대표 입력인지 | 이전 일의 남은 것까지 leftover에 섞임 → 일 시작 사본 기준 |
| 다음 지적 | 훅 | 대기열 맨 앞으로 `지적-{번호}` ⓪ 일 | 번호 > 마지막 처리 번호 | — |

## 되돌림·종료

| 경우 | 누가 시작 | 어디로 | 누가 무엇을 고치나 | 상한 |
|---|---|---|---|---|
| 검토 불통과 | 검토자 판정 | ⑥ → ⑤ | 구현자, 지적 번호별 | 바퀴 상한, 2연속이면 다른 계열 1회 |
| 명령 오류 | 구현자 표시 + 시험자 확인 | ⑤ → ③ | 계획자(plan.md 장면↔번호, 편집 행 조건), 시험자(다음 번호 스크립트) | 되돌림 상한 |
| 설치 요청 | 구현자 | ⑤ 잠시 멈춤 → 재개 | 궤도 스크립트(전용 샌드박스, 잠금 반영, 칸 시작 사본 새로) | — |
| 포기 | 대표 | 종료 | 궤도 스크립트가 leftover 보관·되돌림 | 승인 |
| 복구 | 대표 | 상태 파일만 「닫힘」 | 변경은 손대지 않음, 이어서 닫기/포기 | — |

## 새 규칙마다 우회 세 가지와 막는 장치

| 규칙 | 터미널로 | 다른 도구로 | 글자·이름 변형으로 | 막는 장치 |
|---|---|---|---|---|
| 대기열 = 원문 번호 | 일지에 대기 줄 덧붙임 | 편집 도구로 queue.md | "보류" 등 | 훅은 일지·queue.md를 읽지 않음, 둘 다 보호 경로 |
| 범위 = 커밋 트리 | `.gitignore`에 한 줄 추가 | 무시 파일에 비밀·결과 넣기 | — | `.gitignore`는 보호 설정(승인), 무시 파일 쓰기는 샌드박스 거부(한계 명시), 사본은 범위 밖을 안 가져가므로 거기 기대는 코드는 ⑥⑦에서 실패 |
| 제외 경로가 추적 중 | 추적된 `.claude/` 수정 | 빌드 산출물 커밋 | — | 등록 때 검사해 해제 또는 배포 산출물 경로로, 설정 변경은 승인 번호 커밋 |
| 실행은 요청으로 | 원본에서 실행기 직접 | 허용 명령으로 실행기 흉내 | — | 실행기·설치 명령은 허용 목록 밖, 요청은 파일 쓰기, 궤도 스크립트만 띄움 |
| 전용 샌드박스 | postinstall로 키 읽기 | 플러그인 자동 로드 | 패키지 이름 위장 | 설치 스크립트 끔, 자동 로드 끔, 키는 밖, 허용 주소만 |
| 설치 뒤 사본 | 설치로 잠금 파일 바꿔 "허용 밖 변경" 유발 | — | — | 잠금 반영은 장치가 하고 칸 시작 사본을 새로 뜬다 |
| 변수 접두 불허 | 접두 대입 | `env` | — | 접두 전부 거부, `env` 목록 밖 |
| git 옵션 불허 | `git --config-env` | `git -C` | 축약형 | `git` 뒤 옵션 전부 거부, 커밋·push는 목록 밖 |
| 공개 push 검사 | 대표 터미널 push | 강제 push | 작성자 메일 변형 | pre-push 훅 + 신원 고정값 + 원격에 없는 커밋 전부 (`--no-verify`는 한계) |
| 실행기 고정 설정 | `pytest -c` | `conftest.py`, 플러그인 | 설정 파일 이름 변형 | 실행기는 궤도 스크립트만, 고정 설정, 자동 로드 끔, conftest 미배정, 번호 이름만 |
| 케이스 교체 | 옛 파일 수정 | 삭제 | 같은 번호 재사용 | ⓪ 밖 쓰기 거부, 삭제 거부, 교체는 승인 번호, 다음 번호만 |
| 닫기 leftover | 닫기 전 변경 남김 | — | — | 일 시작 사본과 비교해 보관·되돌림 |
| 운영 키 | `cat .env` | 읽기 도구 | 복사본 | 작업 트리 밖 + 읽기 거부 + 칸마다 확인 |
| 시안 제시 줄 | — | 옛 "이거다" 재사용 | 본문에 "시안 제시" 글자 | 줄은 design/ 경로+편집 기록 조건으로만, 해시 포함, 번호 순서 검사 |
| 대표 터미널 | 일 열린 중 직접 커밋 | — | — | 훅·pre-commit 거부(`--no-verify`는 한계) |

## 막는 규칙마다 — 원래 하던 주체 → 이제 누가, 어느 칸에서, 어떤 권한으로

| 막은 일 | 원래 | 이제 |
|---|---|---|
| bench.json·케이스 수·지문 쓰기 | 시험 스크립트(직원) | 궤도 스크립트, ⑦·⑥, 결과 파일을 읽어 `bench/`에 |
| 시험 실행·장면 실행·설치 | 직원 터미널 | 직원이 요청 파일(⓪·③ 시험자, ⑤ 구현자) → 궤도 스크립트가 전용 샌드박스의 실행 사본에서, 결과는 `requests/{번호}.result` |
| 커밋 | 구현자 | 구현자 커밋 요청(⑤ 끝) → 궤도 스크립트, 지문 관문, 임시 인덱스 `git commit` |
| 의존성 추가 | 구현자 터미널 | 구현자 manifest + 설치 요청 → 궤도 스크립트가 잠금 반영·칸 시작 사본 새로 → 재개 |
| 다음 일 열기 | 반장 | 훅, 닫기·포기 시점 또는 닫힘 상태의 지적 즉시 |
| 대기열·상태·번호·원문 기록 | 일 폴더 | 프로젝트 폴더(일이 없어도 존재) |
| 장면 스크립트 | 계획자/구현자 | 시험자, ③ 또는 명령 오류 되돌림, 다음 번호 |
| plan.md 수정 | 계획자 ③만 | 계획자 ③ 또는 명령 오류 되돌림 |
| tools.md · coverage · report | 주인 없음 | 계획자 · 구현자별 파일(장치가 합침) · 반장(편집 도구, 이 파일만) |
| 시안 폴더 | design.md 한 파일 | 시안자가 `outputs/design/` 폴더 |
| 케이스 수정 | 시험자 자유 | 교체 경로만 |
| 실행기 설정 | 프로젝트 파일 | 하네스 고정 설정 |
| 상태 파일 생성·복구 | — | 등록 승인 / 대표 전용 `일 복구` |
| 복원 기준 | HEAD / git status | 칸 시작 사본(커밋 트리 범위) |
| 소형 재판정 | 터미널 diff | 궤도 스크립트가 커밋 트리 vs HEAD |
| 닫은 일의 남은 변경 | 작업 트리에 그대로 | 일 시작 사본 기준 `leftover/` + 마지막 커밋으로 |
| 일지 덧붙이기 | 편집 도구·터미널 | 요청(반장·검토자) |
| 공개 push 검사 | AI 쪽 훅 | AI 쪽 훅 + git pre-push 훅 |
| 직원별 사본 합치기 | ⑥ 뒤 한 번 | 칸 경계마다 기준 트리로 |
| `.gitignore` 수정 | 아무나 | 보호 설정, 승인 관문 |

## 정의 단일화 확인

범위·지문·사본·요청·기록·산출물 주인·보호 부류는 `v2-devices.md` §정의에만 있다. 범위는 커밋 트리 하나, 다른 지문은 없다. 프로젝트 단위 것(상태·번호·원문·대기열·도면·일지)과 일 단위 것(산출물·요청·기록·bench·사본·leftover)은 전부 작업 트리 밖.
