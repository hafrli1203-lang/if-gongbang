# IF 공방 v2 — 흐름 한 바퀴와 우회 대조

규칙을 고칠 때마다 이 문서를 처음부터 다시 따라간다. 멈추는 곳이나 뚫리는 곳이 나오면 규칙이 틀린 것이다. 정의는 `v2-devices.md` §정의.

## 정상 흐름 한 바퀴

| 칸 | 누가 | 무엇을 어디에 쓰나 | 검사가 무엇과 대조하나 | 막힐 수 있던 곳 → 해결 |
|---|---|---|---|---|
| 일 열기 | 대표 `/일` 또는 `지적`(닫힘 상태면 즉시) | 훅이 `state/`를 「열림」으로 | 대표 입력인지(원문 기록), 대기열 비어 있는지 | 쉬는 상태의 지적을 열 계기가 없음 → 닫힘 상태면 지적이 즉시 연다 |
| ⓪ 시험 등록(지적 일) | 시험자 | `tests/bench/{다음 번호}`; 궤도 스크립트가 전용 샌드박스에서 실행기를 띄워 **실행 사본**의 실패를 기록 | 실패 기록의 실행 전 지문 쌍 = 지금 | 실행이 원본 지문을 바꿈 → 실행 사본에서 돌리고 실행 전 지문을 적는다 |
| ① 사실확정 | 사실확정자 | `outputs/facts.md` | 통과 줄 출처 ∈ 열람 기록, 확인 필요 0 | — |
| ② 실측 | 실측자(샌드박스, 테스트 값 주입) | `scripts/probe/{대상}.log` | probe 키 = facts 키(스크립트) | 운영 키 읽기 → 작업 트리 밖 + 읽기 거부 |
| ③ 계획 | 계획자 / 시험자 | `outputs/plan.md`·`tools.md` / `tests/bench/scenes/{다음 번호}`(장면 케이스) | 소유 겹침 0, 공용 파일 배정, conftest·시험 설정 미배정 | 지적 아닌 일은 케이스를 못 더함 → 장면 케이스(통과 기록만) |
| ④ 시안 | 시안자 | `outputs/design/design.md` | "이거다" 번호 > 출력 훅의 시안 제시 줄 | 제시 시점 근거 없음 → 출력 훅이 원문 기록에 제시 줄을 남긴다 |
| ⑤ 구현 | 구현자(소유표 = 샌드박스 허용 경로) | 소유 파일, `outputs/coverage.md`, 설치 요청, 커밋 요청 | 장면 스크립트 실행 기록(exit 0, 실행 전 지문 쌍 = 지금), 칸 끝 사본 비교, 실제 변경분 승격 재판정 | 새 패키지를 못 씀 → manifest만 고치고 설치 요청 → 궤도 스크립트가 전용 샌드박스에서 잠금·설치 → 구현 칸 재개 |
| ⑥ 검토 | 검토자(일회용 사본) → 궤도 스크립트 | `outputs/review.md`; 궤도 스크립트가 지문 쌍을 `bench/`에 | coverage "들어감" 근거, ⓪ 재현 여부, scenes 편집 기록, 사본 지문 쌍 = 원본, 지적 번호 | 사본에 .env가 없어 지문이 안 맞음 → 비밀 파일은 작업 트리 밖 |
| ⑦ 시험대 | 궤도 스크립트(전용 샌드박스, 실행 사본) | `bench/bench.json`(pass, 지문 쌍, 케이스 수) | 케이스 수 ≥ 이전(대체 포함), 불안정 0, 플러그인 자동 로드 꺼짐 | 캐시 생성으로 지문 변화 → 실행 사본 |
| 커밋 | 궤도 스크립트 | 커밋 트리 규칙으로 커밋 | 기록 지문 쌍 = 지금 지문 쌍(둘 다) | 무시 파일이 커밋에 들어감 → 커밋 트리는 gitignore 범위, 제외 경로는 HEAD 항목 유지 |
| 배포 | 궤도 스크립트 + 서버 쪽 검사 | — | 지문 쌍 일치, 교차 점검 결과 도착 | 늦은 P0 → 배포 관문만 닫음 |
| ⑧ 보고 | 반장(터미널 없음) | `outputs/report.md` | 「실측」 절 명령 ∈ 실행 기록, 대조표 = ⑥ 확인본 | 상태 줄 자동 부착 |
| 일 닫기 | 대표 `일 닫기` | 훅이 「닫힘」, 마지막 처리 번호 갱신; 궤도 스크립트가 남은 변경을 `leftover/`로 보관하고 작업 트리를 마지막 커밋으로 | 대표 입력인지 | 남은 변경이 다음 일에 섞임 → leftover 보관 + 되돌림 |
| 다음 지적 | 훅 | 대기열 맨 앞으로 ⓪ 일 | 번호 > 마지막 처리 번호 | — |

## 되돌림·종료

| 경우 | 누가 시작 | 어디로 | 누가 무엇을 고치나 | 상한 |
|---|---|---|---|---|
| 검토 불통과 | 검토자 판정 | ⑥ → ⑤ | 구현자, 지적 번호별 | 바퀴 상한, 2연속이면 다른 계열 1회 |
| 명령 오류 | 구현자 표시 + 시험자 확인 | ⑤ → ③ | 계획자(연결), 시험자(다음 번호 스크립트) | 되돌림 상한 |
| 설치 요청 | 구현자 | ⑤ 잠시 멈춤 → 재개 | 궤도 스크립트(전용 샌드박스, 잠금·설치) | — |
| 포기 | 대표 | 종료 | 궤도 스크립트가 leftover 보관·되돌림 | 승인 |
| 복구 | 대표 | 상태 파일만 「닫힘」 | 변경은 손대지 않음, 이어서 닫기/포기 | — |

## 새 규칙마다 우회 세 가지와 막는 장치

| 규칙 | 터미널로 | 다른 도구로 | 글자·이름 변형으로 | 막는 장치 |
|---|---|---|---|---|
| 대기열 = 원문 번호 | 일지에 대기 줄 덧붙임 | 편집 도구로 queue.md | "보류" 등 | 훅은 일지·queue.md를 읽지 않음(원문 번호만), 둘 다 보호 경로 |
| 커밋 트리 ≠ 감시 지문 | 추적된 `.claude/` 수정 | 무시 파일에 비밀 넣기 | — | 커밋 트리는 gitignore 범위, 제외 경로는 HEAD 항목, 관문은 둘 다 대조 |
| 실행은 실행 사본 | 원본에서 직접 실행 | — | — | 실행기는 궤도 스크립트만 띄움, 직원 터미널에 실행기 없음 |
| 전용 샌드박스 | postinstall로 키 읽기 | 플러그인 자동 로드 | 패키지 이름 위장 | 설치 스크립트 끔, 플러그인 자동 로드 끔, 키는 샌드박스 밖, 통신 허용 주소 |
| 의존성 쓰기 거부 | 설치 명령 | 패키지 매니저 도구 | 폴더 이름 변형 | 샌드박스 쓰기 거부, 설치 명령은 허용 목록 밖, 설치는 궤도 스크립트 |
| 변수 접두 불허 | 접두 대입 | `env` | — | 접두 전부 거부, `env` 허용 목록 밖 |
| git 옵션 불허 | `git --config-env` | `git -C` | 축약형 | `git` 뒤 옵션 전부 거부 |
| 공개 push 검사 | 대표 터미널 push | 강제 push | 작성자 메일 변형 | pre-push 훅 + 신원 고정값만 + 원격에 없는 커밋 전부 |
| 실행기 고정 설정 | `pytest -c` | `conftest.py`, 플러그인 | 설정 파일 이름 변형 | 실행기는 궤도 스크립트만, 고정 설정, 자동 로드 끔, conftest 미배정, 번호 이름만 |
| 케이스 교체 | 옛 파일 수정 | 삭제 | 같은 번호 재사용 | ⓪ 밖 쓰기 거부, 삭제 거부, 교체는 승인 번호와 묶음, 다음 번호만 |
| 닫기 leftover | 닫기 전 변경 남김 | — | — | 닫기·포기 때 궤도 스크립트가 보관·되돌림 |
| 운영 키 | `cat .env` | 읽기 도구 | 복사본 | 작업 트리 밖 + 읽기 거부 + 칸마다 확인 |
| 시안 제시 순서 | — | 옛 "이거다" 재사용 | — | 제시 줄 번호 < 인용 번호 검사 |

## 막는 규칙마다 — 원래 하던 주체 → 이제 누가, 어느 칸에서, 어떤 권한으로

| 막은 일 | 원래 | 이제 |
|---|---|---|
| bench.json·케이스 수·지문 쌍 쓰기 | 시험 스크립트(직원) | 궤도 스크립트, ⑦·⑥, 결과 파일을 읽어 일 폴더 `bench/`에 |
| 시험 실행·설치 실행 | 직원 터미널 | 궤도 스크립트가 **전용 샌드박스**에서, 실행 사본 위에서 |
| 커밋 | 구현자 | 궤도 스크립트, 커밋 관문, 커밋 트리 규칙 |
| 의존성 추가 | 구현자 터미널 | 구현자는 manifest + 설치 요청, 궤도 스크립트가 잠금·설치, 구현 칸 재개 |
| 다음 일 열기 | 반장 | 훅, 닫기·포기 처리 시점 또는 닫힘 상태의 지적 즉시 |
| 대기열 기록 | AI가 일지에 | 훅, 원문 번호, 표시는 queue.md |
| 장면 스크립트 | 계획자/구현자 | 시험자, ③ 또는 명령 오류 되돌림, 다음 번호 |
| 케이스 수정 | 시험자 자유 | 교체 경로만(승인 번호, 옛 실패 기록 승계) |
| 실행기 설정 | 프로젝트 파일 | 하네스 고정 설정, 아무도 못 고침 |
| 상태 파일 생성·복구 | — | 목록 등록 승인 / 대표 전용 `일 복구` |
| 복원 기준 | HEAD / git status | 칸 시작 사본(감시 지문 범위) |
| 닫은 일의 남은 변경 | 작업 트리에 그대로 | 궤도 스크립트가 `leftover/` 보관 + 마지막 커밋으로 되돌림 |
| 일지 덧붙이기 | 편집 도구·터미널 | 편집 도구(보존 검사) 또는 궤도 스크립트에 요청 |
| 공개 push 검사 | AI 쪽 훅 | AI 쪽 훅 + git pre-push 훅 |
| 직원별 사본 합치기 | ⑥ 뒤 한 번 | 칸 경계마다 궤도 스크립트가 기준 트리로 |

## 정의 단일화 확인

지문 쌍·범위·사본·실행 사본·기준 트리·허용 경로·기록·보호 부류는 `v2-devices.md` §정의에만 있다. 지문을 적는 `bench/`와 기록·일지·도면은 작업 트리 밖. 커밋 트리와 감시 지문은 같은 순간 같은 사본에서 뽑고 관문은 둘 다 대조한다.
