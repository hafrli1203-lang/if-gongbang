# IF 공방 v2 — 흐름 한 바퀴와 우회 대조

규칙을 고칠 때마다 이 문서를 처음부터 다시 따라간다. 멈추는 곳이나 뚫리는 곳이 나오면 규칙이 틀린 것이다.

## 정상 흐름 한 바퀴

| 칸 | 누가 | 무엇을 어디에 쓰나 | 검사가 무엇과 대조하나 | 막힐 수 있던 곳 → 해결 |
|---|---|---|---|---|
| 일 열기 | 대표 `/일` | 훅이 `state/` 생성(「열림」, ⓪ 또는 ①) | 입력이 대표에게서 왔는지(원문 기록) | 적용 목록에 처음 넣은 프로젝트에 상태 파일이 없음 → 목록 등록 승인이 「닫힘」 파일을 만든다 |
| ⓪ 시험 등록(지적 일만) | 시험자 | `tests/bench/<다음 번호>` + 궤도 스크립트가 실행기를 띄워 실패를 실행 기록에 | 실패 기록의 지문 = 지금 지문 | 시험자가 실행기를 못 띄움(샌드박스) → 요청만 하고 궤도 스크립트가 밖에서 띄움 |
| ① 사실확정 | 사실확정자 | `outputs/facts.md` 한 파일 | 통과 줄 출처 ∈ 열람 기록, 확인 필요 0 | 쓰기 도구가 없었음 → 자기 파일 하나만 쓰기 허용 |
| ② 실측 | 실측자(샌드박스, 테스트 키만) | `scripts/probe/<대상>.log`(훅이 실제 실행에서 남김) | probe 키 = facts 키(스크립트 대조) | 운영 키를 읽을 길 → 작업 트리 밖에 두고 읽기 거부 |
| ③ 계획 | 계획자 / 시험자 | `outputs/plan.md`·`tools.md`(계획자), `tests/bench/scenes/<다음 번호>`(시험자) | 소유 겹침 0, 공용 파일 배정됨, conftest·시험 설정 미배정, 갈림길 코드 조건 | 장면 스크립트를 누가 언제 쓰나 → 시험자 ∧ ③ 칸 |
| ④ 시안(화면 일) | 시안자 | `outputs/design/design.md` | "이거다" = 원문 기록 번호, 시안 제시 뒤 | design.md가 허용 경로 밖 → `design/` 안으로 |
| ⑤ 구현 | 구현자(여러 명, 각자 사본, 소유표 = 샌드박스 허용 경로) | 소유 파일, `outputs/coverage.md` 초안, 커밋 **요청** | 통과 장면 스크립트 실행 기록(exit 0, 지문 일치), 칸 끝 사본 비교, 실제 변경분 승격 재판정 | 잠금 파일이 바뀌면 의존성이 옛것 → 궤도 스크립트가 칸 사이에서 잠금대로 설치 |
| ⑥ 검토 | 검토자(일회용 사본) → 궤도 스크립트 | `outputs/review.md`; 궤도 스크립트가 사본 합치기 + 지문을 `bench/`에 | coverage "들어감"의 근거 열기, ⓪ 재현 여부, scenes 편집 기록, 사본 지문 = 원본 지문, 지적 번호 | 사본에서 고친 뒤 돌린 기록 → 지문 다르면 무효 |
| ⑦ 시험대 | 궤도 스크립트(샌드박스 밖) | `bench/bench.json`(pass, 지문, 케이스 수) | 케이스 수 ≥ 이전, 불안정 0, 지문 = 지금 | bench.json이 작업 트리 안이면 적는 순간 지문이 바뀜 → 일 폴더 `bench/`로 |
| 커밋 | 궤도 스크립트 | 지문 규칙의 트리로 커밋 | review 지문 = bench 지문 = 지금 지문 | 지문 없음 → ⑥으로(시험만 재실행하지 않음) |
| 배포 | 궤도 스크립트 + 서버 쪽 검사 | — | 지문 일치, 교차 점검 결과 도착 | 교차 점검이 늦음 → 배포 관문만 닫고 작업은 진행 |
| ⑧ 보고 | 반장(터미널 없음) | `outputs/report.md` | 「실측」 절 명령 ∈ 실행 기록, 대조표 = ⑥ 확인본 | "완료" 글자 검사 없음 → 상태 줄 자동 부착 |
| 일 닫기 | 대표 `일 닫기` | 훅이 「닫힘」, 마지막 처리 번호 갱신 | 입력이 대표에게서 왔는지 | 반장이 다음 일을 열 수 없음 → 훅이 대기열 맨 앞으로 ⓪ 일을 연다 |

## 되돌림 두 가지

| 되돌림 | 누가 시작 | 어디로 | 누가 무엇을 고치나 | 상한 |
|---|---|---|---|---|
| 검토 불통과 | 검토자 판정 | ⑥ → ⑤ | 구현자가 지적 번호별로 고침 | 바퀴 상한, 2바퀴 연속이면 다른 계열 1회 |
| 명령 오류 | 구현자 표시 + 시험자 확인 | ⑤ → ③ | 계획자가 plan.md 연결, 시험자가 다음 번호 스크립트 | 되돌림 상한 |

## 새 규칙마다 우회 세 가지와 막는 장치

| 규칙 | 터미널로 | 다른 도구로 | 글자·이름 변형으로 | 막는 장치 |
|---|---|---|---|---|
| 대기열은 원문 기록 번호 | 일지에 「대기」 줄 `>>` | 편집 도구로 「대기」 줄 | "대 기"·"보류" 등 | 훅은 일지를 읽지 않는다(원문 기록 번호만) + 일지는 보호 경로 |
| 지문·커밋 트리 동일 | 추적된 `.claude/` 파일 수정 | — | — | 커밋 트리를 지문 규칙으로 궤도 스크립트가 만듦 |
| 의존성 쓰기 거부 | `npm install` | 패키지 매니저 도구 | `node_modules2/` | 샌드박스 쓰기 거부 + 지문 제외는 설정 목록의 폴더만 |
| 환경 변수 접두 불허 | `GIT_CONFIG_COUNT=… git commit` | — | `env GIT_DIR=…` | 접두 전부 거부, `env`는 허용 목록 밖 |
| git 옵션 불허 | `git --config-env …` | `git -C …` | 축약형 | `git` 바로 뒤 옵션 전부 거부(이름 안 셈) |
| 공개 push 검사 | 대표 터미널 push | 강제 push | 작성자 메일 변형 | git pre-push 훅 + 신원 고정값만 허용 + 범위 = 원격에 없는 커밋 전부 |
| 실행기 고정 설정 | `pytest -c 내설정` | `conftest.py` 추가 | 설정 파일 이름 변형 | 실행기는 궤도 스크립트만 띄움(`--noconftest -c 하네스`), conftest·설정 미배정, 번호 이름만 |
| 사본에서 복원 | `git checkout HEAD` | — | — | 복원 기준은 사본, 직원은 `git`을 못 침 |
| 운영 키 읽기 거부 | `cat .env` | 읽기 도구 | 복사본 | 키가 작업 트리 밖 + 샌드박스 읽기 거부 + 칸마다 확인 |

## 정의 단일화 확인

지문·범위·사본·허용 경로·기록은 `v2-devices.md` §정의에만 있다. 지문을 적는 파일(`bench/`)은 지문 범위 밖(일 폴더)이다. 커밋 트리 = 지문 트리(같은 규칙, 궤도 스크립트).

## 막는 규칙마다 — 원래 하던 주체 → 이제 누가, 어느 칸에서, 어떤 권한으로

| 막은 일 | 원래 | 이제 |
|---|---|---|
| bench.json·케이스 수·지문 쓰기 | 시험 스크립트(직원이 띄움) | 궤도 스크립트, ⑦·⑥, 샌드박스 밖, 일 폴더 `bench/` |
| 커밋 | 구현자 | 궤도 스크립트, 커밋 관문, 지문 규칙 트리 |
| 의존성 설치 | 구현자 터미널 | 궤도 스크립트, 칸 사이, 잠금 파일 그대로 |
| 다음 일 열기 | 반장 | 훅, `일 닫기` 처리 시점, 대기열 맨 앞 |
| 대기열 기록 | AI가 일지에 적음 | 훅이 원문 기록 번호로 유지, 일지 표시는 훅 생성 |
| 장면 스크립트 작성·수정 | 계획자/구현자 | 시험자, ③ 또는 명령 오류 되돌림, 다음 번호만 |
| 실행기 설정 | 프로젝트 파일(구현자) | 하네스 고정 설정, 아무도 못 고침 |
| 상태 파일 생성·복구 | — | 목록 등록 승인(생성), 대표 전용 `일 복구`(복구) |
| 복원 기준 | HEAD / git status | 칸 시작 사본(지문 범위), 궤도 훅 |
| 일지 덧붙이기 | 편집 도구·터미널 | 편집 도구(보존 검사) 또는 궤도 스크립트에 요청 |
| 공개 push 검사 | AI 쪽 훅 | AI 쪽 훅 + git pre-push 훅(대표 터미널 포함) |
