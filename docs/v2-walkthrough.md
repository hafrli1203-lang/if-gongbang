# IF 공방 v2 — 흐름 한 바퀴와 우회 대조

규칙을 고칠 때마다 이 문서를 처음부터 다시 따라간다. 멈추는 곳이나 뚫리는 곳이 나오면 규칙이 틀린 것이다. 정의는 `v2-devices.md` §정의. 자리 표시는 {이름}.

## 정상 흐름 한 바퀴

| 칸 | 누가 | 무엇을 어디에 쓰나 | 검사가 무엇과 대조하나 | 막힐 수 있던 곳 → 해결 |
|---|---|---|---|---|
| 일 열기 | 대표 `/일` 또는 `지적`(「닫힘」이면 즉시, 가장 작은 번호, 이름 `지적-{번호}`) | 훅이 상태를 「열림」으로, 처리기가 일 폴더·일 시작 사본 | 대표 입력인지, 상태 「닫힘」인지, 대기열, 같은 이름 일 폴더 없음 | 「복구 중」에 지적이 오면 더러운 트리로 열림 → 복구 중에는 대기열에만 |
| ⓪ 시험 등록(지적 일) | 시험자 | `tests/bench/{다음 번호}`; 시험대 실행 요청 → 처리기가 실행 사본에서 실패 기록 | 실행 전 지문 = 지금 지문 | 요청을 훅이 처리하면 시간 제한 → 처리기 |
| ① 사실확정 | 사실확정자(쓰기 창 ①) | `outputs/facts.md` | 통과 줄 출처 ∈ 열람 기록, 확인 필요 0 | — |
| ② 실측 | 실측자(쓰기 창 ②; 소형 궤도면 계획자가 ③에서) | `scripts/probe/{대상}` 스크립트; **실측 실행 요청** → 처리기가 실행 사본에서 돌려 로그를 `records/probe/`에 | probe 키 = facts 키 | 로그가 작업 트리에 남아 범위에 들어감 → 기록으로 옮김 |
| ③ 계획 | 계획자 / 시험자 | `outputs/plan.md`·`outputs/tools.md` / `tests/bench/scenes/{다음 번호}` | 소유 겹침 0, 공용 파일 배정, 소유 불가 파일 미배정 | manifest 주인 한 명 → manifest는 소유 불가, 설치 요청으로 |
| ④ 시안 | 시안자(쓰기 창 ④) | `outputs/design/` | "이거다"(대표 입력) 번호 > 제시 줄 번호, 제시 줄 해시(design 폴더 전체) = 지금 해시 | 파일 하나 해시면 다른 파일이 승인 없이 들어감 → 폴더 해시 |
| ⑤ 구현 | 구현자(쓰기 창 ⑤, 소유표 = 샌드박스 허용) | 배정된 파일, `outputs/coverage-{구현자}.md`, 요청(장면 실행·설치) | 입구에서 design 해시 재대조; 장면 실행 기록; 명령 뒤·칸 끝 비교; 커밋 트리 vs HEAD 재판정 | 설치가 허용 밖 변경을 흡수 → 설치 전 비교 0 확인 뒤 새 사본 |
| ⑥ 검토 | 검토자(일회용 사본) → 처리기 | `outputs/review.md`; 처리기가 **검토 지문**을 `gates/`에 | coverage 근거, ⓪ 재현, scenes 편집 기록, 사본 지문 = 원본, 검토 항목 번호 | 구현자가 ⑥ 뒤에 고침 → 쓰기 창 닫힘 |
| ⑦ 시험대 | 처리기(실행 사본) | `gates/bench.json`(pass, **시험대 지문**, 케이스 수) | 케이스 수 ≥ 프로젝트 `state/` 마지막 케이스 수, 불안정 0 | 새 일에 비교값 없음 → 프로젝트 state |
| 커밋 | 처리기, ⑦ 통과 직후 스스로 | 임시 인덱스 `git commit`(pre-commit은 처리기 커밋만 통과) | **검토 지문 = 시험대 지문 = 지금 지문**; 다르면 멈추고 대표가 ⑦ 사본 복원 또는 지금 트리 수용(⑥부터) | ⑥ 뒤 지문이 바뀌면 장치 밖 변경 → 자동으로 ⑥에 넘기지 않음 |
| 배포 | 처리기 + 서버 쪽 검사 | 실행 사본에서 빌드, 산출물 경로만 따로 커밋(pre-commit 통과 조건 (나)) | 산출물 경로를 뺀 지문 = 시험대 지문, 바뀐 경로는 산출물 경로 안만, 교차 점검 도착 | 빌드 뒤 지문이 달라 관문에 걸림 → 배포 관문 별도 |
| ⑧ 보고 | 반장(쓰기 창 ⑧, report.md만) | `outputs/report.md` | 「실측」 절 ∈ 실행 기록, 대조표 = ⑥ 확인본 | 상태 줄 자동 부착 |
| 일 닫기 | 대표 `일 닫기` | 훅이 닫기 접수; 처리기가 「닫는 중」 → **HEAD와의 차이만** `archive/{일 이름}/{시각}/`에 보관(실패면 원래 상태) → HEAD로 맞춤 → 미뤄 둔 승인 적용·커밋 → 트리 = HEAD 재확인 → 지적 일이면 번호 갱신 → **「닫힘」** → 대기열 | 대표 입력인지, 보관 성공 | 일 시작 기준이면 커밋분까지 보관 → HEAD 기준. `/일` 일 닫기가 번호를 올려 지적이 사라짐 → 지적 일만 갱신 |
| 다음 지적 | 처리기 | 가장 작은 대기 번호로 `지적-{번호}` ⓪ | 번호 > 마지막 처리 번호 | — |

## 되돌림·종료

| 경우 | 누가 시작 | 어디로 | 누가 무엇을 고치나 | 상한 |
|---|---|---|---|---|
| 검토 불통과 | 검토자 판정 | ⑥ → ⑤(구현자 창 다시 열림) | 구현자, 검토 항목 번호별 | 바퀴 상한, 2연속이면 다른 계열 1회 |
| 명령 오류 | 구현자 표시 + 시험자 확인 | ⑤ → ③ | 계획자(plan.md), 시험자(다음 번호 스크립트) | 되돌림 상한 |
| 설치 요청 | 구현자 | ⑤ 잠시 멈춤 → 재개 | 처리기(비교 0 확인 → 샌드박스 설치 → manifest·잠금 반영 → 새 칸 시작 사본) | — |
| 포기 | 대표(지적 일은 다시 넣기 / 버리기, `/일` 일은 선택 없음) | 종료 | 처리기가 HEAD 차이 보관·되돌림·미뤄 둔 승인 적용. 다시 넣기면 그 뒤 같은 번호가 ⓪부터 다시 열림 | 승인 |
| 복구 | 대표 `일 복구 {프로젝트} {일 이름}` | 상태 「복구 중 {일 이름}」 | 변경은 손대지 않음, 닫기는 ⑧ 통과 기록 있을 때만·아니면 포기, 지적은 대기열에만 | — |
| 마무리 실패 | 처리기 | 보관 실패면 원래 상태(「열림」/「복구 중」), 그 뒤 실패면 「닫는 중 {일 이름}」에 머묾 | 대표가 `일 닫기` 재시도(끝난 단계 생략) 또는 `포기`; 직원 훅·승인은 거부 | — |

## 새 규칙마다 우회 세 가지와 막는 장치

| 규칙 | 터미널로 | 다른 도구로 | 글자·이름 변형으로 | 막는 장치 |
|---|---|---|---|---|
| 대기열 = 원문 번호 | 일지에 대기 줄 | 편집 도구로 queue.md | "보류" 등 | 훅은 원문 번호만 읽음, 둘 다 보호 경로 |
| 범위 = 커밋 트리 | 맨 위 `.gitignore` 수정 | **하위 폴더 새 `.gitignore`** | 전역 무시 설정 | 모든 깊이 `.gitignore` 보호(생성 포함), 전역 무시·info/exclude 끄고 계산 |
| 범위 밖 읽기 | `ln -s` 밖 경로 | 하위 저장소 | — | `ln`·`git submodule` 목록 밖, 링크·하위 저장소 소유 불가, 지문 계산 거부 |
| 제외 경로가 추적 중 | 추적된 `.claude/` 수정 | 빌드 산출물 커밋 | — | 등록 때 해제 또는 배포 산출물 경로, 설정 변경은 승인 번호 커밋 |
| 실행은 요청으로 | 원본에서 실행기 직접 | 허용 명령으로 흉내 | — | 실행기·설치 명령 목록 밖, 요청은 파일 쓰기, 처리기만 띄움 |
| 요청 결과 | `.RESULT` 미리 만들기 | 같은 번호 중복 | 대소문자 | 결과는 `records/requests/`(직원 쓰기 불가), 요청은 직원별 폴더 |
| 쓰기 창 | ⑥ 뒤 소유 파일 수정 | 편집 도구 | — | 칸이 넘어가면 편집·샌드박스 쓰기 함께 닫힘, 커밋은 ⑦ 뒤 세 지문 |
| 일 중 설정 변경 | — | 승인으로 `.gitignore`·제외 목록 변경 | — | 범위·HEAD를 바꾸는 승인은 「닫힘」에서만 적용 |
| 처리기 커밋 | pre-commit이 처리기도 막음 | — | — | pre-commit은 실행 기록의 세 지문 일치 기록 = 임시 인덱스 해시인 커밋만 통과 |
| 전용 샌드박스 | postinstall로 키 읽기 | 플러그인 자동 로드 | 패키지 이름 위장 | 설치 스크립트 끔, 자동 로드 끔, 키는 밖, 허용 주소만 |
| 설치 뒤 사본 | 허용 밖 변경 남겨 두고 설치 요청 | — | — | 새 사본 전에 옛 사본과 비교 0 확인, 차이는 manifest·잠금만 인정 |
| 변수 접두 불허 | 접두 대입 | `env` | — | 접두 전부 거부, `env` 목록 밖 |
| git 옵션 불허 | `git --config-env` | `git -C` | 축약형 | `git` 뒤 옵션 전부 거부 |
| 공개 push 검사 | 대표 터미널 push | 강제 push | 작성자 메일 변형 | pre-push 훅 + 신원 고정값 + 원격에 없는 커밋 전부(`--no-verify` 한계) |
| 실행기 고정 설정 | `pytest -c` | `conftest.py`, 플러그인 | 설정 파일 이름 변형 | 처리기만 띄움, 고정 설정, 자동 로드 끔, conftest 소유 불가 |
| 케이스 교체 | 옛 파일 수정 | 삭제 | 같은 번호 재사용 | ⓪ 밖 쓰기 거부, 삭제 거부, 승인 번호, 다음 번호만 |
| 닫기 보관 | 닫기 전 변경 남김 | — | — | HEAD 차이 보관 성공 뒤에만 되돌림 |
| 운영 키 | `cat .env` | 읽기 도구 | 복사본 | 작업 트리 밖 + 읽기 거부 + 칸마다 확인 |
| 시안 승인 | — | 옛 "이거다" 재사용, 승인 뒤 design 다른 파일 수정 | 본문에 "시안 제시" 글자 | 제시 줄은 경로+편집 기록 조건, 폴더 해시, 번호 순서, ⑤ 입구 재대조 |
| 복구 | — | 복구 직후 지적 | 상태 파일 못 읽는 틈 | 「복구 중」은 닫기·포기만, 지적은 대기열; 상태 파일이 없거나 못 읽으면 일 복구 외 전부 거부 |
| 세 지문 불일치 | 대표 터미널 편집 뒤 ⑦ 재실행 | — | — | 멈추고 대표 선택(⑦ 사본 복원 / 수용 후 ⑥), 자동 재검토 없음 |
| 대표 터미널 | 일 열린 중 직접 커밋 | — | — | 훅·pre-commit 거부(`--no-verify` 한계) |

## 막는 규칙마다 — 원래 하던 주체 → 이제 누가, 어느 칸에서, 어떤 권한으로

| 막은 일 | 원래 | 이제 |
|---|---|---|
| bench.json·케이스 수·지문 쓰기 | 시험 스크립트(직원) | 처리기, 일 폴더 `gates/`에 ⑥(검토 지문)·⑦(시험대 지문·케이스 수), 프로젝트 state의 마지막 케이스 수 |
| 범위·HEAD를 바꾸는 설정 변경 | 승인 즉시 | 「닫힘」이면 승인 관문이 즉시; 「열림」·「복구 중」이면 기록 뒤 「닫는 중」의 미뤄 둔 승인 적용·커밋 단계에서 처리기가; 「닫는 중」이면 거부 |
| 시험·장면·실측·설치 실행 | 직원 터미널 | 요청 파일(⓪·③ 시험자, ② 실측자, ⑤ 구현자) → 처리기가 실행 사본에서, 결과는 `records/requests/` |
| 요청 처리 | 훅 | 상주 처리기(훅은 접수만) |
| 커밋 | 구현자 | 처리기가 ⑦ 통과 직후, 세 지문 관문, `git commit`(pre-commit은 처리기만 통과) |
| 배포 빌드·산출물 커밋 | 배포 스크립트 | 처리기가 실행 사본에서 빌드, 배포 관문(산출물 경로 뺀 지문) |
| 의존성 추가 | 구현자 터미널 | 설치 요청(이름·버전) → 처리기가 manifest·잠금 반영, 새 칸 시작 사본 |
| manifest·잠금 수정 | 구현자 소유 | 소유 불가, 장치만 |
| 다음 일 열기 | 반장 | 처리기, 닫기·포기 시점 또는 「닫힘」의 지적 즉시, 가장 작은 번호 |
| 마지막 처리 번호 갱신 | 닫기 때 무조건 | 지적 일 닫기만, 포기는 대표 선택 |
| 대기열·상태·번호·원문·케이스 수·보관본 | 일 폴더 | 프로젝트 폴더 |
| 쓰기 권한 | 주인이면 언제나 | 주인 × 칸(쓰기 창) |
| 시안 승인 | AI 표시·파일 해시 | 대표 입력 `이거다`, design 폴더 해시, ④와 ⑤ 입구 대조 |
| 장면 스크립트 | 계획자/구현자 | 시험자, ③ 또는 명령 오류 되돌림 |
| plan.md 수정 | 계획자 ③만 | 계획자 ③ 또는 명령 오류 되돌림 |
| tools.md · coverage · report | 주인 없음 | 계획자 · 구현자별 파일(처리기가 합침) · 반장(report.md만) |
| probe 로그 | 작업 트리 | 일 폴더 `records/probe/`(처리기가 옮김) |
| 케이스 수정 | 시험자 자유 | 교체 경로만 |
| 실행기 설정 | 프로젝트 파일 | 하네스 고정 설정 |
| 상태 파일 생성·복구 | — | 등록 승인 / 대표 `일 복구 {프로젝트} {일 이름}` → 「복구 중 {일 이름}」 |
| 복원 기준 | HEAD / git status | 칸 시작 사본(커밋 트리 범위) |
| 소형 재판정 | 터미널 diff | 처리기가 커밋 트리 vs HEAD |
| 닫은 일의 남은 변경 | 작업 트리에 그대로 | HEAD 차이 → `archive/`, 삭제는 대표만 |
| 일지 덧붙이기 | 편집 도구·터미널 | 요청(반장·검토자) |
| 공개 push 검사 | AI 쪽 훅 | AI 쪽 훅 + git pre-push 훅 |
| 직원별 사본 합치기 | ⑥ 뒤 한 번, 지문 비교 | 칸 경계마다, 충돌 0·사본별 허용 밖 변경 0 |

## 정의 단일화 확인

범위·지문·세 지문·사본·요청·처리기·쓰기 창·상태 넷·보관·마지막 처리 번호·산출물 주인·보호 부류는 `v2-devices.md` §정의에만 있다. 범위는 커밋 트리 하나. 프로젝트 단위 것(상태·번호·케이스 수·원문·대기열·도면·일지·보관본)과 일 단위 것(산출물·요청·기록·gates·사본)은 전부 작업 트리 밖. 요청 경로는 `requests/{직원}/{번호}.md` 하나, 결과는 `records/requests/` 하나.
