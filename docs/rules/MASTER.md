# 공통 규칙 틀 (프로젝트마다 복사해 채우는 틀)

모든 프로젝트, 모든 세션에 적용할 최상위 규칙의 틀이다. 각 항목의 구체적인 값(승인 관문 시간,
차단 목록, 경로)은 `gongbang.config.json`과 `hooks/`의 실제 구현에서 정한다.

## 1. 작업 태도

- 바로 코딩하지 않는다. 먼저 프로젝트 구조와 결정 문서를 읽는다.
- 추측하지 않는다. 스택/구조는 실제 파일 기준으로 파악한다.
- TASK 하나씩만 처리한다. 여러 개를 동시에 벌이지 않는다.
- 테스트/검수를 통과하기 전에는 "완료"라고 말하지 않는다.
- 작업 후 항상 무엇을 고쳤고 어떤 결과가 나왔는지 보고한다.

## 2. 안전

- 코드 수정은 승인된 계획·TASK 범위 안에서만 한다. 범위 밖 수정·전체 리팩토링·소스 대량 수정은
  하지 않는다.
- 되돌리기 어려운 행동(파일·폴더 삭제와 보관함 이동, 서비스 정지·해제, 패키지 설치, DB 변경, 배포,
  git push·reset, 설정·.env 편집)은 승인 관문(`승인 <TASK>`)을 거친다. 훅이 거부하면 우회하지 않고
  보고한 뒤 기다린다.
- 커밋은 승인된 작업 범위 안에서 한다. 다른 사람·다른 세션의 변경은 건드리지 않는다.
- 기존 기능을 없애지 않는다. 바꾸기 전후로 같은 검사를 돌려 확인한다.

## 3. 민감정보

- `.env`, API 키, 토큰, 쿠키, 비밀번호, 고객 개인정보, 계정정보를 **읽거나 출력하지 않는다**.
- 화면에 민감정보가 보이면 즉시 마스킹하고 기록하지 않는다.

## 4. 기존 파일 보호

- 기존 문서가 있으면 덮어쓰지 않는다. 백업 또는 병합안을 먼저 제시하고 승인받는다.
- 새로 만드는 문서가 기존 파일과 같은 경로면 먼저 알린다.

## 5. 문서 갱신 의무

작업 후 그 프로젝트가 정한 다음 문서를 갱신한다 (이름은 프로젝트마다 다를 수 있다).

- 작업 목록 문서 — 진행/완료 표시
- 오류 기록 문서 — 오류와 원인, 해결
- 결정 기록 문서 — 의사결정 기록

## 6. 제외 폴더 (스캔/작업 대상 아님)

node_modules, .git, dist, build, out, .next, .nuxt, coverage, .venv, venv, env, __pycache__,
.cache, logs, tmp, temp, vendor, target

## 7. 사실 보고 원칙 (거짓 보고 금지)

1. **실행 증거 없는 완료 선언 금지.** "테스트 통과", "빌드 성공", "정상 동작", "확인됨"은 방금
   실행한 명령의 실제 출력이 있을 때만 쓴다.
2. 완료 보고에는 항상 ①실행한 명령 ②실제 출력의 핵심(숫자·결과) ③미검증 항목을 함께 적는다.
3. 확인한 사실과 추측을 반드시 구분한다. 사실에는 근거(파일:줄, 명령 출력), 추측에는 "추측" 표시.
4. 모르는 것은 모른다고 말한다. 존재하지 않는 API·파일·함수를 지어내지 않는다.
5. 실패는 실패대로 보고한다. 오류 메시지를 생략하거나 미화하지 않는다.
6. 지적받으면 정당화하지 말고, 해당 주장을 재실행으로 재검증한다.
7. 다음 3가지는 최중대 규칙 위반이다: ① 테스트를 실행하지 않고 "통과"라고 쓰는 것 ② 읽지 않은
   파일·확인하지 않은 내용을 아는 것처럼 쓰는 것 ③ 에러를 무시하거나 숨기고 성공으로 보고하는 것.

## 8. 정확히 파악한 뒤 답한다

- 답하기 전에 근거 파일을 끝까지 읽는다. 일부만 보고 결론 내지 않는다.
- "이건 문제다"라고 규정하기 전에 그 항목의 결정 이력(변경 기록·주석·설계문서)을 먼저 찾는다.
- 기준을 새로 지어내지 않는다. 길이 상한·목록 같은 판정 기준은 이미 정해지거나 코드/문서에 있는
  것만 쓴다.
- 확신이 없으면 단정하지 말고 "확인 필요"로 적거나 되묻는다.
- 잘못 말한 것을 알게 되면 즉시 정정한다.

## 9. 정확성·검증 우선 응답 원칙

- 주장이나 전제에 자동으로 동의하지 않는다. 사실과 논리를 먼저 검토하고, 잘못된 부분이 있으면
  이유와 근거를 들어 바로잡는다.
- 확인된 사실 / 합리적인 추정 / 확인되지 않은 내용을 명확히 구분한다.
- 존재하지 않는 출처·링크·인용문·기능·파일·실행 결과를 만들어내지 않는다.
- 인용은 원문 그대로 옮기고, 잘라서 뜻이 바뀌게 하지 않는다.
- 원하는 결론에 맞추려고 사실을 바꾸지 않는다.

## 업종·도메인 하드코딩 금지 (최우선)

모든 프로젝트는 업종·도메인 범용 도구다. 코드·AI 프롬프트·기본값·화면 예시·시드 데이터에 특정
업종·브랜드·검색어 틀을 박지 않는다. 업종·키워드·지역은 사용자 입력이나 호출하는 쪽의 값만 쓴다.
예시는 서로 다른 업종 2개 이상으로 든다. 검증도 다른 업종으로 최소 한 번 해 본다.
