# IF 공방 v2 — 장치 1: 정의와 검사

`v2.md`의 궤도 표와 직원 표가 "무엇을 막는가"라면, 이 문서는 "어떻게 막는가"다. 원칙은 하나: **AI가 적은 글을 믿지 않고, 훅이 따로 남긴 기록과 대조한다.** 여러 곳에서 쓰는 정의는 **이 문서 §정의에만** 두고, 다른 문서는 여기를 가리킨다. 자리 표시는 {이름}처럼 중괄호로 쓴다.

모형은 다섯 줄이다. ① 장치가 쓰는 것과 비밀은 작업 트리 밖. 프로젝트 단위와 일 단위를 가른다. ② 범위는 하나 — **커밋 트리 범위**. 지문·사본·실행·검토·비교·복원이 전부 이 범위. ③ 직원이 장치에 시키는 일은 **요청** 한 길. 훅은 접수만 하고 **상주 처리기**가 처리한다. ④ 쓰기 권한은 칸에 묶인다 — 구현자는 ⑤에서만 쓴다. ⑤ 관문은 둘 — 커밋 관문(검토·시험대·지금 세 지문 일치)과 배포 관문.

## 정의 (단일 출처)

| 용어 | 정의 |
|---|---|
| **작업 트리** | 프로젝트 폴더. 코드·`tests/bench/`·`scripts/probe/`·추적 설정만. **비밀 파일·운영 키·장치 기록·일 산출물은 안에 두지 않는다.** 샌드박스에는 테스트 값이 환경으로 주입된다 |
| **하네스 홈** | 작업 트리 밖. 프로젝트 폴더·일 폴더·설정·훅·설치본·상주 처리기 |
| **프로젝트 폴더** | `projects/{프로젝트}/` — 일을 넘어 이어지는 것. `state/`: 상태(「닫힘」·「열림 {일 이름}」·「복구 중 {일 이름}」), **마지막 처리 번호**, **마지막 케이스 수**(지적 케이스·장면 케이스 따로), `queue.md`(훅이 만드는 표시). `records/원문.jsonl`: 대표 메시지와 제시 줄, **프로젝트 단위 일련번호**. `도면.md`, `일지.jsonl`(덧붙이기만), `archive/`(닫기·포기 보관본). 적용 목록 승인이 이 폴더와 「닫힘」을 만든다 |
| **일 폴더** | `jobs/{프로젝트}/{일 이름}/` — 그 일만의 것. `outputs/`(산출물, 주인 표), `requests/{직원}/{번호}.md`(요청, 직원별 폴더라 번호가 겹치지 않음), `records/`(실행·열람·편집 기록, `records/probe/` 실측 로그, **`records/requests/{직원}/{번호}.result`** 요청 결과 — 직원 쓰기 불가 폴더라 이름 규칙에 기대지 않음), `bench/`(bench.json·지문), `snapshots/`(일 시작·칸 시작 사본). 지적에서 자동으로 열리는 일의 이름은 `지적-{번호}` |
| **산출물 주인** | `outputs/facts.md` 사실확정자 · `outputs/plan.md`·`outputs/tools.md` 계획자 · `outputs/design/`(폴더) 시안자 · `outputs/coverage-{구현자}.md` 각 구현자(처리기가 합침) · `outputs/review.md` 검토자 · `outputs/report.md` 반장(편집 도구로 이 파일만). 그 밖의 쓰기: 구현자 = plan.md 소유표, 시험자 = `tests/bench/`(번호 이름), 실측자 = `scripts/probe/`(스크립트만, 실행과 로그는 요청·기록). 요청 파일은 각자 자기 폴더 |
| **쓰기 창** | 주인이라도 **자기 칸에서만** 쓸 수 있다: 시험자 ⓪·③, 사실확정자 ①, 실측자 ②, 계획자 ③(과 명령 오류 되돌림), 시안자 ④, 구현자 ⑤, 검토자 ⑥, 반장 ⑧. 칸이 넘어가면 편집 도구와 샌드박스 쓰기가 함께 닫힌다. ⑥→⑤ 되돌림은 구현자 창을 다시 연다 |
| **허용 경로** | 「산출물 주인」 × 「쓰기 창」. **샌드박스 쓰기 허용 = 편집 도구 허용 = 이 교차.** 누구도 소유할 수 없는 것: 의존성 폴더, **모든 깊이의 `.gitignore`(새로 만들기 포함)**, 패키지 목록(manifest)과 잠금 파일(설치 요청으로만 바뀜), 시험 설정 파일·`conftest.py`, 링크 파일, 하위 저장소 |
| **제외 목록** | 설정의 세 가지: 의존성 폴더, 빌드 산출물, `.claude/`. 적용 등록 때 추적 중인지 검사해, 추적 중이면 (가) 추적 해제 (나) 「배포 산출물 경로」 등록 중 택일. `.claude/`가 추적 중이면 설정 변경은 승인 관문이 승인 번호를 메시지에 적어 따로 커밋 |
| **커밋 트리 범위** | `.gitignore`를 따르는 범위(추적 + 무시되지 않은 미추적) − 제외 목록. 계산은 **전역 무시 설정과 `.git/info/exclude`를 끈 상태**로 고정(컴퓨터가 달라도 같은 범위). 범위 안에 **작업 트리 밖을 가리키는 링크 파일이나 하위 저장소가 있으면 지문 계산을 거부**하고 칸을 멈춘다. 이 하나의 범위가 지문·사본·실행 사본·검토자 사본·비교·복원·소형 재판정·보관 전부의 범위 |
| **지문** | 커밋 트리 범위를 임시 인덱스에 담아 `git write-tree`로 뽑은 트리 해시. 제외 경로 가운데 HEAD가 추적 중인 것은 HEAD 항목을 그대로 옮긴다 |
| **세 지문** | 검토 지문(⑥ 통과 때 처리기가 `bench/`에), 시험대 지문(⑦ 통과 때), 지금 지문. 커밋 관문은 **셋이 같을 때만** 연다 |
| **사본** | 커밋 트리 범위로 뜬다 + 의존성은 설치로 + 테스트 값은 환경 주입. 일 시작 사본, 칸 시작 사본, 실행 사본(일회용), 검토자 사본(일회용), 직원별 작업 사본 — 전부 같은 규칙. **시험한 것 = 검토한 것 = 커밋하는 것** |
| **비교·복원** | 명령 뒤와 칸 끝에 지금 커밋 트리와 칸 시작 사본을 비교해 허용 경로 밖 변경을 찾고, 사본에서 되돌리며 칸 시작 때 없던 파일을 지운다. **무시 파일에 AI가 쓰는 것은 샌드박스 거부만이 막는다**(한계) |
| **소형 재판정** | ⑤ 끝에 커밋 트리와 HEAD의 차이(파일 수·경로)로 승격 조건을 다시 본다 |
| **실행 기록** | 훅·처리기가 쌓는 줄: 요청 번호, 명령, 종료 코드, 시각, 실행 전 지문, 주체, 사본 식별. 판정 근거 조건: 실행 전 지문 = 지금 지문, 종료 코드 0 |
| **열람 기록 · 편집 기록** | 열어 본 웹 문서·곳간 검색·probe 로그 / 어느 직원이 어느 파일을 언제 고쳤나 |
| **제시 줄** | 출력 훅이 원문 기록에 남기는 줄. 조건: **답 본문에 `outputs/design/` 경로가 있고 그 폴더에 편집 기록이 있을 때.** 훅은 **design 폴더 전체의 트리 해시**를 함께 적는다. "이거다"는 대표 입력 명령이며 제시 줄보다 뒤 번호여야 하고, **⑤ 입구에서 지금 design 폴더 해시 = 승인된 제시 줄 해시**를 대조한다 |
| **요청** | 직원이 `requests/{직원}/{번호}.md`에 쓰는 파일. 종류: 장면 실행, 시험대 실행, **실측 실행**, 설치(패키지 이름·버전), 일지 덧붙이기, 커밋. 훅은 접수(기록)만 하고 **상주 처리기**가 가져가 처리한다(훅 시간 제한과 무관). 결과는 `records/requests/`와 실행 기록. 종류별 주체·칸은 `v2-devices-2.md` 훅 표 「요청」 |
| **상주 처리기** | 하네스 홈의 궤도 스크립트 프로세스. 요청 처리, 전용 샌드박스 띄우기, 사본·지문·합치기·커밋·배포·보관·일 열기를 맡는다. 훅은 짧게 끝나는 검사·접수·상태 전환만 |
| **전용 샌드박스** | 처리기가 실행기·설치·probe를 띄우는 곳. 쓰기는 실행 사본의 결과 폴더와 의존성 폴더만, 운영 키 없음, 허용 주소만, 설치 스크립트 끔, 플러그인 자동 로드 끔. 처리기는 결과 파일만 읽어 옮긴다 |
| **설치** | 설치 요청(이름·버전) → 처리기가 **먼저 지금 트리와 칸 시작 사본을 비교해 허용 밖 변경 0을 확인**(아니면 거절·복원) → 전용 샌드박스에서 manifest·잠금 갱신과 설치 → manifest·잠금을 작업 트리에 반영(장치가 쓴 것) → 칸 시작 사본을 새로 뜨고 ⑤ 재개. 구현자 누구나 요청할 수 있다 |
| **마지막 처리 번호** | 지적 일을 **닫을 때만** 그 지적 번호로 올린다. `/일`로 연 일을 닫을 때는 바꾸지 않는다. 지적 일을 포기하면 대표가 「다시 넣기」(번호 유지)·「버리기」(그 번호로 올림) 중 고른다. 대기열은 번호 > 마지막 처리 번호인 지적이며 **항상 가장 작은 번호부터** 연다 |
| **보관** | 닫기·포기 때 처리기가 **마지막 커밋(HEAD)과 지금 트리의 차이**만 `projects/{프로젝트}/archive/{일 이름}-{시각}/`에 보관하고, 보관이 성공했을 때만 작업 트리를 HEAD로 맞춘다. 실패하면 닫기를 멈춘다. 커밋된 내용은 닫기가 건드리지 않는다. 보관본 삭제는 대표만 |
| **상태 셋** | 「닫힘」: v2 훅 쉼, 지적이 오면 가장 작은 대기 번호로 즉시 연다. 「열림」: 한 일만. 「복구 중」: `일 복구`가 깨진 상태 파일을 이 값으로 만들며, 이 상태에서는 `일 닫기`·`포기`만 받고 지적은 대기열에만 쌓인다 |
| **보호 파일 — 장치 기록** | 훅·처리기만 쓴다: 프로젝트 `state/`·`records/`·`일지.jsonl`·`archive/`, 일 폴더 `records/`·`bench/`·`snapshots/`, `.git/` |
| **보호 파일 — 설정** | 승인 관문으로만: 설정 파일(임계값·훅별 모드·제외 목록·적용 목록·배포 산출물 경로·고지 예외·공개용 신원·허용 목록·금지 목록), 훅 스크립트 폴더·훅 등록 전역 설정·설치 폴더·프로젝트 `.claude/`·서버 쪽 검사 설정, 도면, 모든 깊이의 `.gitignore` |
| **기준 트리** | 직원별 작업 사본 모드에서 칸 경계마다 처리기가 각 사본을 합친 트리. 합치기 검사는 **충돌 0과 사본별 허용 밖 변경 0**만 본다(지문 비교가 아니다) |
| **적용 프로젝트 목록** | v2가 켜진 프로젝트(설정). 넣고 빼는 것은 승인 관문 |

## 검사 원칙 — 자기신고를 믿지 않는다

- **실행 기록**: "돌렸다"와 보고의 「실측」 절은 plan.md가 고른 `tests/bench/scenes/` 스크립트의 실행 기록이 조건을 만족해야 인정된다. 실행은 요청으로만, 전용 샌드박스의 실행 사본에서.
- **칸 끝 비교**: 허용 경로 밖 변경이 있으면 다음 칸을 열지 않고 복원. 검토자 칸에서 변경이 있으면 판정 무효.
- **벽은 샌드박스**: 터미널이 있는 칸은 샌드박스에서 돌아 허용 경로 밖 쓰기가 파일 시스템 단위로 거부된다. 쓰기 창이 닫힌 직원은 아무 경로도 못 쓴다. 검토자는 일회용 사본에서 일하고, 판정 근거는 사본 지문 = 원본 지문일 때만.
- **소유표 = 샌드박스 허용 경로**: 공용 파일은 구현자 한 명에게 배정돼야 계획이 통과되고, 미배정 파일이 필요하면 ③으로.
- **대표 원문 인용**: "이거다", 채점표 선택, 건너뛰기 사유는 원문 기록의 번호와 글자 그대로 맞고, 제시 줄보다 뒤여야 칸이 열린다.
- **출처는 열람 기록과 대조**: facts.md 「통과」 줄 출처 ∈ 열람 기록, 줄마다 출처, 외부 값은 probe 로그(일 폴더 `records/probe/`)의 같은 키와 스크립트 대조.
- **세 지문과 커밋**: 커밋 요청은 검토 지문 = 시험대 지문 = 지금 지문일 때만 처리기가 임시 인덱스를 지정한 `git commit`으로 친다(pre-commit 훅이 돈다). 하나라도 다르면 ⑥으로. ⑥부터 구현자 쓰기 창이 닫혀 있으므로 "검토 뒤 고치고 ⑦만 다시"는 성립하지 않는다.
- **배포 관문**: 배포 산출물 경로를 뺀 지금 지문 = 시험대 지문, 교차 점검 결과 도착. 빌드는 처리기가 실행 사본에서 하고 산출물만 그 경로에 두어 따로 커밋한다.
- **의존성**: 구현자는 설치 요청만. manifest·잠금은 장치가 쓴다.
- **운영 키·외부 통신**: 운영 키는 작업 트리 밖, 승인은 키를 주지 않음(테스트 계정 쓰기 1회), 모든 샌드박스는 허용 주소만, 메일·문자류는 시험 모드/중계.
- **같은 계열 교차**: 불통과 두 바퀴 연속이면 다른 계열 1회. P0/P1이면 ⑤로, P2/P3 기록, 갈리면 대표에게. 배포 관문은 결과 도착까지 닫힘.
- **지적 번호**: 검토 지적은 번호를 달고 바퀴를 넘어 이어진다. 번호 표시가 없는 판정은 무효.

## 대표 터미널에 대하여

닫힘 상태에서는 v2 훅이 쉰다. 일이 열린 동안 대표가 작업 트리에서 치는 `git commit`·`git push`는 거부된다. git pre-commit·pre-push 훅에도 같은 검사를 두지만 대표 터미널의 `--no-verify`는 막지 못한다 — 한계.
