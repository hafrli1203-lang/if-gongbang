# 검토용 2/6 — 검사·훅·케이스·설치 (14차 반영판)

- **파일 소유 겹침**: ③ 계획 칸이 구현자들의 소유 범위가 겹치는지 코드로 검사하고, 겹치면 계획이 통과되지
  않는다. 여러 명이 함께 건드리게 되는 파일(설정, 패키지 목록, 공용 타입)은 반드시 **구현자 한 명**에게 배정해야 계획이 통과된다. 배정되지 않은 파일이 구현 중에 필요해지면 두 길뿐이다: ③ 계획 칸으로 되돌려 소유표를 고치거나(보통 길, 코드가 허용), 민감 영역 파일이면 대표 승인(`승인 <이름>`). 반장 승인은 AI가 AI에게 주는 승인이라 쓰지 않는다.
- **시험 결과와 코드 지문**: `bench.json`은 보호 파일이라 시험 실행기(궤도 스크립트)만 쓴다(`scripts/probe/`의 스크립트도 못 쓴다). 검토와
  시험을 마친 시점에 **궤도 스크립트가** 코드 지문을 review.md와 bench.json에 적고(검토자·시험자가 적는 것이 아니다), 커밋 관문은 지금 올라갈 코드의 지문과 같을 때만 연다.
  지문 계산은 스크립트에 고정한다: **임시 준비 영역(인덱스)에 작업 폴더 전체**(추적·미추적 파일 모두)를 담은 뒤 `git write-tree`.
  제외하는 것은 셋뿐이고 보호된 설정에 적는다 — ① **일 폴더 전체와 `.claude/`**(일 폴더는 애초에 **작업 폴더 밖**, 하네스 홈에 둔다:
  원문 기록은 대표가 메시지를 칠 때마다, 열람 기록은 문서를 열 때마다 늘어나므로 안에 두면 승인을 치는 순간 지문이 바뀌어 커밋
  관문이 ⑥으로 되돌린다), ② **의존성 폴더**(수만 개 파일을 매번 인덱스에 담으면 느리고 `.git`이 불어난다 — 대신 **잠금 파일은
  넣고**, 의존성 폴더 쓰기는 모든 직원 샌드박스에서 막는다), ③ 빌드 산출물. 지문 계산에 쓰는 객체는 **임시 저장소**에 썼다가
  버린다 — `.git`이 불어나지 않고 `.git` 읽기 전용과도 맞는다. 검토 뒤 한 줄이라도 고치면 ⑥으로 되돌아간다.
  구현 칸에서는 `tests/bench/`를 편집할 수 없다 — 테스트를 약하게 고쳐 통과시키는 길을 막는다.
- **같은 계열이 같이 놓치는 것**: 구현자와 검토자가 같은 계열이라 같은 실수를 같이 놓칠 수 있다. 고위험 일 외에도
  **검토 불통과가 두 바퀴 연속이면** 다른 계열 점검을 한 번 자동으로 넣는다.
- **교차 점검이 갈릴 때**: 검토자는 통과, 다른 모델 계열은 문제 제기인 경우 — 심각도 상(P0·P1)이면 대표를 거치지
  않고 구현 칸으로 자동으로 되돌리고, 하(P2·P3)이면 기록하고 보고에 표시한다. 「통과/불통과」 판정 자체가 갈리면
  멈추고 대표에게 올린다.
- **지적에는 번호가 있다**: 검토자의 지적은 번호를 달고 바퀴를 넘어 이어진다. 다음 바퀴의 검토자는 이전 번호
  목록을 받아 각 지적에 "이전 번호" 또는 "새 번호"를 붙여야 하고, 그것이 없는 판정은 무효다. 멈출 조건의
  "같은 지적이 남음"은 사람의 느낌이 아니라 이 번호로 센다 — 표현만 바꾼 지적이 새 지적으로 잡혀 상한을 피해
  가지 못한다.


# IF 공방 v2 — 장치 상세 2: 케이스 관리 · 상한값 · 막는 훅

앞부분은 `v2-devices.md`. 읽는 순서는 `v2.md` 맨 위 표.

## 울타리 — 막는 훅

| 훅 | 언제 | 무엇을 막나 |
|---|---|---|
| 일 시작·닫기 | `/일 <이름>` · `일 닫기 <이름> <사유>` | 이미 열린 일이 있으면 두 번째 일 폴더 생성 차단. 열린 동안 들어온 대표 지적(`지적 ` 머리말)은 훅이 원문 그대로 작업 일지에 「대기」로 적고, 대표가 `일 닫기`를 치는 순간 훅이 대기열 맨 앞 지적으로 ⓪ 일을 연다. 비정상 종료로 열린 채 남은 일은 **대표만** 사유를 적어 닫는다 |
| 편집 | 편집·쓰기 | 소스 폴더는 ⑤ 칸에서 소유표 안만. `scripts/probe/`는 ② 칸의 실측자만. `tests/bench/`는 둘로 나뉜다 — 케이스 본체는 **시험자 ∧ ⓪ 칸 ∧ 새 파일**일 때만(번호는 실행기가 자동 부여), `tests/bench/scenes/`(통과 장면 스크립트)는 **시험자 ∧ (③ 칸 또는 「명령 오류」 되돌림 중)**일 때만, **다음 번호 이름으로만** 쓰기 허용. 고친 이력은 AI가 적은 글이 아니라 **훅의 편집 기록**과 ⑥에서 대조. 보호 파일은 누구도 못 씀 |
| 커밋 | 커밋(글자가 아니라 git 자체의 **pre-commit 훅**에도 같은 검사; 터미널 허용 목록은 `--no-verify`와 `git -c`를 통과시키지 않는다) | review.md 통과 + bench.json pass **+ 두 파일에 적힌 코드 지문(트리 해시)이 지금 올라갈 코드의 지문과 같을 것**. 다르거나 지문이 없으면 ⑥으로(시험만 다시 돌려도 검토는 다시 되지 않는다). bench.json과 지문은 보호 파일이라 믿는다. 커밋은 **궤도 스크립트**가 친다 — 직원은 못 치고, 대표는 배포 승인만 한다 |
| 배포 | 배포 스크립트, 그리고 main push로 배포가 자동 실행되는 프로젝트는 PC 쪽 push 훅이 아니라 **서버 쪽 자동 검사**(CI/서버 훅 — 그 설정 파일도 보호 목록)에 | ⑥⑦ 산출물 + 코드 지문 일치 + 교차 점검 결과 도착 전엔 차단 |
| 작업조 | 작업조 생성 | ⑤⑥ 칸에서 역할 직원이 아닌 범용 작업조 차단 |
| 상태 줄 | 답이 끝날 때 | 금지어 검사는 쓰지 않는다("끝났습니다"로 피해 간다). 일이 열려 있으면 훅이 답 끝에 **"현재 칸 ④ · 미검증"** 같은 상태 줄을 자동으로 붙인다 — 어떤 표현을 쓰든 실제 상태가 같이 보인다 |
| 반장 터미널 | 일이 열린 동안 | 반장의 터미널 명령 전부 차단, 호출 수 초과 시 차단("새 창" 안내) |
| 터미널 | 직원의 터미널 명령 | 금지 목록이 아니라 **허용 목록**(화이트리스트)에 있는 명령만 통과(`python -c`·`node -e`·`perl -i`·`git checkout <파일>`·`git apply`·`curl -o` 같은 우회는 목록에 없으므로 막힘). 명령이 끝나면 `git status`로 허용 경로 밖 변경을 보고, 있으면 되돌린 뒤 막는다. 벽은 샌드박스 |
| 공개 저장소 push | `git push` | 금지 목록(빌려온 이름·사람 이름·내부 주소·경로·메일·계정명·날짜·일지 번호·승인 예시)에 걸리면 차단 |
| 시험대 보호 | 편집·쓰기 | 구현 칸에서 `tests/bench/` 편집 차단, `bench.json` 직접 쓰기 차단(시험 실행기만 씀 — 시험자가 고치는 것은 케이스·장면 스크립트이지 실행기가 아니다) |
| 승인 범위 | `승인 <이름>` | 이름이 열린 일·프로젝트와 맞지 않으면 거절하고 다시 입력받음. 배포·삭제는 짧은 창을 따로 둠(설정값) |
| v1 유지 | — | 승인 관문(`승인 <이름>`), 위험 명령, 비밀 파일, 훅 자체 보호 |

- 임계값과 민감 영역 패턴은 훅이 읽는 **설정 파일**에 둔다. 고치는 것은 승인 관문이다(아래 「보호 파일 목록」).
- v2를 적용할 **프로젝트 목록**이 보호된 설정에 있다. 목록에 있는 프로젝트는 상태 파일이 **늘 있어야** 하고, 그 값이 「닫힘」일
  때만 v2 훅이 쉬며, **파일이 없거나 못 읽으면 막는다**("열린 일 없음"으로 읽지 않는다). 목록에 없는 프로젝트에서는 v2가 꺼져 있다.
  목록에서 빼는 것도 승인 관문으로만 한다. 되돌리기는 설정에서 훅 몇 줄을 빼는 것이다.
