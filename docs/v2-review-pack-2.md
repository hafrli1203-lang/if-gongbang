# v2 검토용 묶음 2/9

(v2-devices · v2-devices-2 · v2-walkthrough · v2-rollout를 순서대로 이어 붙여 나눈 것. 정의는 묶음 1의 §정의.)

| **세 지문** | 검토 지문(⑥ 통과 때 처리기가 `gates/`에), 시험대 지문(⑦ 통과 때), 지금 지문. 커밋은 처리기가 **⑦ 통과 직후** 셋이 같을 때만 친다. 소형 궤도도 ⑥·⑦을 거치며 조건은 같다 |
| **사본** | 커밋 트리 범위로 뜬다 + 의존성은 설치로 + 테스트 값은 환경 주입. 일 시작 사본, 칸 시작 사본, 실행 사본(일회용), 검토자 사본(일회용), 직원별 작업 사본 — 전부 같은 규칙. **시험한 것 = 검토한 것 = 커밋하는 것** |
| **비교·복원** | 명령 뒤와 칸 끝에 지금 커밋 트리와 칸 시작 사본을 비교해 허용 경로 밖 변경을 찾고, 사본에서 되돌리며 칸 시작 때 없던 파일을 지운다. **무시 파일에 AI가 쓰는 것은 샌드박스 거부만이 막는다**(한계). 비교·복원의 범위는 작업 트리의 커밋 트리 범위뿐이고, 그 안에서 허용 경로 밖 변경을 되돌린다. 일 폴더는 이 범위 밖이다 — `outputs/`와 `requests/`는 쓰기 창과 편집 기록으로, `records/`·`gates/`·`snapshots/`는 직원 쓰기 불가로 지킨다 |
| **소형 재판정** | ⑤ 끝에 커밋 트리와 HEAD의 차이(파일 수·경로)로 승격 조건을 다시 본다. 소형 궤도의 합친 파일은 `outputs/plan.md` 하나(주인 계획자, 쓰기 창 ③, 사실확정·실측은 그 안의 절). 전체 궤도로 올라가면 구현 결과를 보관(「보관」 규칙)하고 HEAD로 맞춘 뒤 ①부터 다시 연다. 승격할 때 `outputs/plan.md`도 함께 보관하고 비운다 — ①은 빈 facts.md에서 시작하고, 보관한 plan.md는 사실확정자가 읽기만 한다 |
| **실행 기록** | 훅·처리기가 쌓는 줄: 요청 번호, 명령, 종료 코드, 시각, 실행 전 지문, 주체, 사본 식별. 판정 근거 조건: 실행 전 지문 = 지금 지문, 종료 코드 0 |
| **열람 기록 · 편집 기록** | 열어 본 웹 문서·곳간 검색·probe 로그 / 어느 직원이 어느 파일을 언제 고쳤나 |
| **제시 줄** | 출력 훅이 원문 기록에 남기는 줄. 조건: **답 본문에 `outputs/design/` 경로가 있고 그 폴더에 편집 기록이 있을 때.** 훅은 **design 폴더 전체의 트리 해시**를 함께 적는다. "이거다"는 대표 입력 명령이며 제시 줄보다 뒤 번호여야 하고, **⑤ 입구에서 지금 design 폴더 해시 = 승인된 제시 줄 해시**를 대조한다 |
| **요청** | 직원이 `requests/{직원}/{번호}.md`에 쓰는 파일. 종류: 장면 실행, 시험대 실행(⓪ 실패 기록용, 시험자만 — ⑦은 처리기가 스스로), **실측 실행**, 설치(패키지 이름·버전), 일지 덧붙이기. **커밋은 요청이 아니며** 처리기가 ⑦ 통과 뒤 스스로 한다. 훅은 접수(기록)만 하고 **상주 처리기**가 가져가 처리한다(훅 시간 제한과 무관). 결과는 `records/requests/`와 실행 기록. 종류별 주체·칸은 `v2-devices-2.md` 훅 표 「요청」 |
| **상주 처리기** | 하네스 홈의 궤도 스크립트 프로세스. 요청 처리, 전용 샌드박스 띄우기, 사본·지문·합치기·커밋·배포·보관·일 열기를 맡는다. 훅은 짧게 끝나는 검사·접수·상태 전환만 |
| **전용 샌드박스** | 처리기가 실행기·설치·probe를 띄우는 곳. 쓰기는 실행 사본의 결과 폴더와 의존성 폴더만(설치 요청일 때만 실행 사본의 manifest·잠금 파일을 더함), 운영 키 없음, 허용 주소만, 설치 스크립트 끔, 플러그인 자동 로드 끔. 처리기는 결과 파일만 읽어 옮긴다 |
| **설치** | 설치 요청(이름·버전) → 처리기가 **먼저 지금 트리와 칸 시작 사본을 비교해 허용 밖 변경 0을 확인**(아니면 거절·복원) → 전용 샌드박스에서 manifest·잠금 갱신과 설치 → manifest·잠금을 작업 트리에 반영(장치가 쓴 것) → 칸 시작 사본을 새로 뜨고 ⑤ 재개. 구현자 누구나 요청할 수 있다 |
| **마지막 처리 번호** | 지적 일을 **닫을 때만** 그 지적 번호로 올린다. `/일`로 연 일을 닫을 때는 바꾸지 않는다. 지적 일을 포기하면 대표가 「다시 넣기」(번호 유지)·「버리기」(그 번호로 올림) 중 고른다. 다시 넣기는 미뤄 둔 승인을 적용한 뒤 같은 번호를 ⓪부터 다시 연다 — 다른 일을 먼저 하려면 버리기를 고르고 나중에 새 지적으로 올린다. `/일`로 연 일의 포기는 선택 없이 받고 번호를 바꾸지 않는다. 대기열은 번호 > 마지막 처리 번호인 지적이며 **항상 가장 작은 번호부터** 연다 |
| **보관** | 닫기·포기 때 처리기가 **마지막 커밋(HEAD)과 지금 트리의 차이**만 `projects/{프로젝트}/archive/{일 이름}/{시각}/`에 보관하고, 보관이 성공했을 때만 작업 트리를 HEAD로 맞춘다. 실패하면 닫기를 멈춘다. 그 뒤 미뤄 둔 승인을 적용·커밋하고, **그것까지 끝난 다음에 상태를 「닫힘」으로 바꾸고** 대기열을 연다(어느 단계든 실패하면 상태는 「열림」에 머물고 대기열을 열지 않고 대표에게). 차이는 커밋 트리 범위 안에서 재고, HEAD에 없는 새 파일도 보관한 뒤 지우며, 무시 파일과 제외 목록 경로는 건드리지 않는다. 커밋된 내용은 닫기가 건드리지 않는다. 보관본 삭제는 대표만 |
