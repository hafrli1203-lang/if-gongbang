# v2 검토용 묶음 2/6

(v2-devices · v2-devices-2 · v2-walkthrough · v2-rollout를 순서대로 이어 붙여 나눈 것. 정의는 묶음 1의 §정의.)

| **설치** | 설치 요청(이름·버전) → 처리기가 **먼저 지금 트리와 칸 시작 사본을 비교해 허용 밖 변경 0을 확인**(아니면 거절·복원) → 전용 샌드박스에서 manifest·잠금 갱신과 설치 → manifest·잠금을 작업 트리에 반영(장치가 쓴 것) → 칸 시작 사본을 새로 뜨고 ⑤ 재개. 구현자 누구나 요청할 수 있다 |
| **마지막 처리 번호** | 지적 일을 **닫을 때만** 그 지적 번호로 올린다. `/일`로 연 일을 닫을 때는 바꾸지 않는다. 지적 일을 포기하면 대표가 「다시 넣기」(번호 유지)·「버리기」(그 번호로 올림) 중 고른다. 다시 넣기는 같은 번호를 ⓪부터 즉시 다시 연다 — 다른 일을 먼저 하려면 버리기를 고르고 나중에 새 지적으로 올린다. 대기열은 번호 > 마지막 처리 번호인 지적이며 **항상 가장 작은 번호부터** 연다 |
| **보관** | 닫기·포기 때 처리기가 **마지막 커밋(HEAD)과 지금 트리의 차이**만 `projects/{프로젝트}/archive/{일 이름}-{시각}/`에 보관하고, 보관이 성공했을 때만 작업 트리를 HEAD로 맞춘다. 실패하면 닫기를 멈춘다. 차이는 커밋 트리 범위 안에서 재고, HEAD에 없는 새 파일도 보관한 뒤 지우며, 무시 파일과 제외 목록 경로는 건드리지 않는다. 커밋된 내용은 닫기가 건드리지 않는다. 보관본 삭제는 대표만 |
| **상태 셋** | 「닫힘」: 대표 입력 훅(일 열기·지적·일 복구)과 상주 처리기만 깨어 있고 나머지 v2 훅은 쉰다. 지적이 오면 가장 작은 대기 번호로 즉시 연다. 「열림 {일 이름}」: 한 일만. 「복구 중 {일 이름}」: `일 복구 {프로젝트} {일 이름}`이 만든다(상태 파일이 읽히면 거부, 그 이름의 일 폴더가 있고 `archive/`에 그 일의 보관본이 없을 때만). 이 상태에서는 `일 닫기`는 그 일의 ⑧ 통과 기록이 있을 때만, 없으면 `포기`만 받고, 지적은 대기열에만 쌓인다 |
| **보호 파일 — 장치 기록** | 훅·처리기만 쓴다: 프로젝트 `state/`·`records/`·`일지.jsonl`·`archive/`, 일 폴더 `records/`·`gates/`·`snapshots/`, `.git/` |
| **보호 파일 — 설정** | 승인 관문으로만: 설정 파일(임계값·훅별 모드·제외 목록·적용 목록·배포 산출물 경로·고지 예외·공개용 신원·허용 목록·금지 목록), 훅 스크립트 폴더·훅 등록 전역 설정·설치 폴더·프로젝트 `.claude/`·서버 쪽 검사 설정, 도면, 모든 깊이의 `.gitignore`. **범위나 HEAD를 바꾸는 승인**(`.gitignore`, 제외 목록, 배포 산출물 경로, `.claude/` 따로 커밋)은 「닫힘」에서만 적용하고, 일이 열린 동안 승인되면 기록만 해 두고 닫기 뒤 적용한다 |
| **기준 트리** | 직원별 작업 사본 모드에서 칸 경계마다 처리기가 각 사본을 합친 트리. 합치기 검사는 **충돌 0과 사본별 허용 밖 변경 0**만 본다(지문 비교가 아니다) |
| **적용 프로젝트 목록** | v2가 켜진 프로젝트(설정). 넣고 빼는 것은 승인 관문 |

## 검사 원칙 — 자기신고를 믿지 않는다

- **실행 기록**: "돌렸다"와 보고의 「실측」 절은 plan.md가 고른 `tests/bench/scenes/` 스크립트의 실행 기록이 조건을 만족해야 인정된다. 실행은 요청으로만, 전용 샌드박스의 실행 사본에서.
- **칸 끝 비교**: 허용 경로 밖 변경이 있으면 다음 칸을 열지 않고 복원. 검토자 칸에서 변경이 있으면 판정 무효.
- **벽은 샌드박스**: 터미널이 있는 칸은 샌드박스에서 돌아 허용 경로 밖 쓰기가 파일 시스템 단위로 거부된다. 쓰기 창이 닫힌 직원은 아무 경로도 못 쓴다. 검토자는 일회용 사본에서 일하고, 판정 근거는 사본 지문 = 원본 지문일 때만.
- **소유표 = 샌드박스 허용 경로**: 공용 파일은 구현자 한 명에게 배정돼야 계획이 통과되고, 미배정 파일이 필요하면 ③으로.
- **대표 원문 인용**: "이거다", 채점표 선택, 건너뛰기 사유는 원문 기록의 번호와 글자 그대로 맞아야 한다. "이거다"는 여기에 더해 제시 줄보다 뒤여야 칸이 열린다.
- **출처는 열람 기록과 대조**: facts.md 「통과」 줄 출처 ∈ 열람 기록, 줄마다 출처, 외부 값은 probe 로그(일 폴더 `records/probe/`)의 같은 키와 스크립트 대조.
- **세 지문과 커밋**: 처리기가 ⑦ 통과 직후 검토 지문 = 시험대 지문 = 지금 지문일 때만 임시 인덱스를 지정한 `git commit`으로 친다(pre-commit 훅이 돈다). 하나라도 다르면 ⑥으로. ⑥부터 구현자 쓰기 창이 닫혀 있으므로 "검토 뒤 고치고 ⑦만 다시"는 성립하지 않는다.
- **배포 관문**: 배포 산출물 경로를 뺀 지금 지문 = 시험대 지문, 교차 점검 결과 도착. 빌드는 처리기가 실행 사본에서 하고 산출물만 그 경로에 두어 따로 커밋한다.
- **의존성**: 구현자는 설치 요청만. manifest·잠금은 장치가 쓴다.
- **운영 키·외부 통신**: 운영 키는 작업 트리 밖, 승인은 키를 주지 않음(테스트 계정 쓰기 1회), 모든 샌드박스는 허용 주소만, 메일·문자류는 시험 모드/중계.
- **같은 계열 교차**: 불통과 두 바퀴 연속이면 다른 계열 1회. P0/P1이면 ⑤로, P2/P3 기록, 갈리면 대표에게. 배포 관문은 결과 도착까지 닫힘.
- **검토 항목 번호**: 검토자의 지적 항목은 번호를 달고 바퀴를 넘어 이어진다(대표의 `지적` 명령 번호와 다른 번호). 번호 표시가 없는 판정은 무효.

## 대표 터미널에 대하여

닫힘 상태에서는 대표 입력 훅 말고는 v2 훅이 쉰다. 일이 열린 동안 대표가 작업 트리에서 치는 `git commit`·`git push`는 거부된다. 일이 열린 동안 pre-commit 훅은 **처리기의 커밋만** 통과시킨다: 실행 기록에 이번 커밋에 대한 처리기의 세 지문 일치 기록이 있고 그 지문이 임시 인덱스의 트리 해시와 같을 때. 그 밖의 커밋은 거부한다. pre-push에도 같은 검사를 두지만 대표 터미널의 `--no-verify`는 막지 못한다 — 한계.

## 울타리 — 막는 훅 (단일 기준표)

| 훅 | 언제 | 무엇을 하나 |
|---|---|---|
| 일 열기 | `/일 {이름}` — 대표 입력만 | 상태가 「닫힘」이 아니면 거부. 대기열이 비어 있지 않으면 거부(지적부터). 「열림」으로, 일 폴더 생성, 처리기가 일 시작 사본, ① 칸 |
| 지적 | `지적 {내용}` — 대표 입력만 | 원문 기록에 번호로 남고 대기열에 들어간다. 「닫힘」이면 처리기가 **대기열의 가장 작은 번호**로 `지적-{번호}` 일을 ⓪ 칸으로 즉시 연다. 「열림」·「복구 중」이면 대기열에만 |
| 이거다 · 채점 | `이거다 {시안 파일}` 등 — 대표 입력만 | 원문 기록에 번호로. 제시 줄보다 뒤이고 그 제시 줄의 design 폴더 해시가 지금 해시와 같을 때만 ④ 통과. ⑤ 입구에서 다시 대조 |
