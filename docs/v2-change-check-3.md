# v2 변경 확인용 3/5

## docs/v2-devices.md
이전: 닫힘 상태에서는 대표 입력 훅 말고는 v2 훅이 쉰다. 일이 열린 동안 대표가 작업 트리에서 치는 `git commit`·`git push`는 거부된다. 일이 열린 동안 pre-commit 훅이 통과시키는 커밋은 셋이다. (가) 실행 기록에 세 지문 일치 기록이 있고 그 지문이 임시 인덱스의 트리 해시와 같은 처리기 커밋. (나) 배포 관문 통과 기록이 있고, 임시 인덱스 트리에서 배포 산출물 경로를 뺀 해시가 시험대 지문과 같으며, 바뀐 경로가 배포 산출물 경로 안에만 있는 처리기 커밋. (다) 닫기·포기 마무리 단계에서 승인 번호가 메시지에 있고 바뀐 경로가 그 승인의 설정 경로 안에만 있는 처리기 커밋. 그 밖의 커밋은 거부한다. pre-push에도 같은 검사를 두지만 대표 터미널의 `--no-verify`는 막지 못한다 — 한계.
이후: 닫힘 상태에서는 대표 입력 훅 말고는 v2 훅이 쉰다. 일이 열린 동안 대표가 작업 트리에서 치는 `git commit`·`git push`는 거부된다. 일이 열린 동안 pre-commit 훅이 통과시키는 커밋은 셋이다. (가) 실행 기록에 세 지문 일치 기록이 있고 그 지문이 임시 인덱스의 트리 해시와 같은 처리기 커밋. (나) 배포 관문 통과 기록이 있고, 임시 인덱스 트리에서 배포 산출물 경로를 뺀 해시가 시험대 지문과 같으며, 바뀐 경로가 배포 산출물 경로 안에만 있는 처리기 커밋. (다) 미뤄 둔 승인 커밋: 상태가 「닫는 중」이고 그 일의 보관 기록이 있으며, 메시지의 승인 번호가 미뤄 둔 승인 기록에 있고, 바뀐 경로가 그 승인이 다루는 경로 안에만 있는 처리기 커밋. 그 밖의 커밋은 거부한다. 「닫힘」에서는 v2 pre-commit 검사가 쉬므로 승인 관문의 즉시 커밋은 그대로 통과한다. pre-push에도 같은 검사를 두지만 대표 터미널의 `--no-verify`는 막지 못한다 — 한계.
