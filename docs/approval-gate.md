# 승인 관문

되돌리기 어려운 행동(서비스 정지·해제, git push·되돌리기·삭제, 재귀 삭제, 패키지 설치, sudo,
프로세스 강제 종료, 설정/.env 편집, 작업판 완료 표시 등)은 `hooks/scope_guard.py`가 가로막고,
대표가 채팅에 `승인 <TASK>`를 입력했는지 확인한다.

## 근거: 대표의 실제 대화 기록

승인 여부는 파일에 저장되지 않는다. 모델이 쓸 수 있는 파일은 모델이 위조할 수 있는 파일이기
때문이다. 대신 `scope_guard.py`가 매번 **대표의 실제 대화 기록**
(`cfg["transcripts_root"]/*/<session_id>.jsonl` — 에이전트 하네스 자신만 쓰는 파일)을 직접 읽어,
최근 `cfg["approval_window_seconds"]`(기본 4시간) 안에 대표가 실제로 입력한 `승인 <TASK>` /
`승인 취소`를 시간 순서대로 재생해서 그 순간의 관문 상태를 다시 계산한다. `approve_gate.py`는
아무것도 결정하거나 저장하지 않는다 — 지금 입력한 메시지가 어떻게 인식됐는지 안내만 출력한다.
세부 파싱 규칙(인용·코드블록 제거, 부정어 인식, 긴 공백 처리)은 `hooks/fence_parse.py`의 모듈
docstring과 주석에 있다.

## 문법

- `승인 <TASK>` — TASK는 공백 없는 1~40자(영문·숫자·한글·`-`·`_`).
- `승인 전체` — 같은 세션의 모든 관문 대상 행동에 적용한다.
- `승인 취소` 또는 `승인 해제` — 열려 있는 관문을 즉시 닫는다.

메시지 안 어디든(문장 맨 앞, 쉼표·줄바꿈 뒤) 이 형태로 나타나면 인식된다. 부정어(어간 + 어떤
어미든)가 바로 뒤따르면 승인으로 보지 않는다 — 놓치면 다시 입력하면 되므로 이 방향(과소 인식)이
안전하다. 인용(`'...'`, `"..."`) 속이나 코드블록 안의 `승인 <TASK>`는 인식하지 않는다. 같은
메시지에 여러 개가 있으면 글자 순서대로 재생해 마지막 상태를 따른다.

## 범위: 세션 단위

승인은 이 세션에만 적용된다. 다른 세션(다른 session_id)에서는 같은 대표가 같은 시각에 승인했어도
적용되지 않는다 — session_id로 정확히 일치하는 대화 기록 파일을 찾지 못하면 무조건 차단한다.

**TASK 이름은 대부분 사람이 보기 위한 라벨일 뿐, 행동 범위를 제한하지 않는다.** 어떤 이름 하나로만
승인해도 그 세션에서는 git push, 서비스 중지 등 관문 대상 행동 전체가 설정된 시간 동안 열린다.
행동별로 승인을 쪼개는 일반적인 설계는 더 큰 변경이 필요해 하지 않았다.

## 프로젝트 범위: 이름이 프로젝트 폴더와 같을 때

딱 한 가지 예외가 있다. 승인에 쓴 이름이 `cfg["apps_root"]` 바로 아래 있는 프로젝트 폴더
이름과 대소문자 무시하고 같으면, 그 승인은 **그 폴더 안의 행동에만** 적용된다 — 대상 경로
(Edit/Write의 `file_path`) 또는 Bash 호출의 `cwd`가 그 폴더 안으로 실제 해석될 때만 열린다.
폴더 밖을 대상으로 하는 같은 세션의 다른 행동은 여전히 막힌다(다른 프로젝트 이름으로 다시
승인해야 한다). 프로젝트 폴더 이름이 아닌 그 외의 모든 이름은 위의 세션 전체 규칙을 그대로
따른다. 이 구분은 `hooks/scope_guard.py`의 `_task_grants`/`_project_dir_for`가 한다.

Claude Code는 하위 작업자(subagent)의 도구 호출에도 메인 세션의 session_id를 그대로 넘긴다(훅
기록으로 확인되며, 기록에 별도의 agent 칸이 있다) — 하위 작업자가 호출한 도구도 같은 세션의
승인을 그대로 따른다.

## 항상 막히는 것 (승인으로도 안 열림)

`cfg["installed_hooks_dir"]`(기본 `~/.claude/hooks`)와 `cfg["legacy_gate_dir"]`(기본
`~/.claude/gate`, 파일 기반 관문의 흔적 — 비워서 끌 수 있음) **실제 경로 안에 있는 파일만** 항상
차단한다. Edit/Write는 `realpath`로 실제 경로를 확인하고, Bash 명령은 그 경로의 절대 경로
리터럴이나(그 경로가 실제 홈 디렉터리 밑에 있다면) `~`·`$HOME`·`${HOME}`·`/home/<user>`·`/root`
같은 흔한 표현까지 인식한다. `cd <설치된 hooks 디렉터리> && python3 <hook 파일>`처럼 `cd`로
분리해도, 그 명령의 `cwd`가 실제 설치 경로 안이면 차단된다.

이 보호는 "같은 이름의 파일이 어딘가에 있으면 전부 차단"이 아니다. 운영 설치 경로가 아닌 곳(이
저장소의 체크아웃 폴더 등)에 같은 이름의 파일을 만들거나 고치는 것은 정상 작업이다 —
`installed_hooks_dir`/`legacy_gate_dir`이 가리키는 실제 경로만 보호한다.
