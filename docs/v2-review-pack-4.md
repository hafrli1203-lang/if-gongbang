# 검토용 4/6 — 검사·훅·케이스·설치 (14차 반영판)

## 시험대·케이스·일지·도면 보호

- **새 파일 이름은 번호 형식만**: ⓪의 케이스도, ③의 `tests/bench/scenes/` 장면 스크립트도 **다음 번호 이름으로만 쓰기를 훅이 허용**한다(이름은 쓰는 순간 정해진다). 실행기는 형식에 맞는 파일만 모은다. 시험 도구가 자동으로 읽는 이름(예: pytest의
  `conftest.py`)을 새 파일로 넣으면 기존 케이스 전부의 동작을 바꿔 통과시킬 수 있고 케이스 수 감소 검사에도 안 걸리기 때문이다.
- 구현 칸에서 고칠 수 있는 **프로젝트 시험 설정**(`package.json`의 test 줄, jest·pytest 설정)도 같은 길이다. 실행기는 프로젝트
  설정 대신 **하네스 쪽 고정 설정**으로 돌고, 프로젝트 안의 시험 설정 파일은 시험대 보호에 넣는다. 시험 실행기 파일 자체는
  **전역(하네스 설치 폴더)**에 있고 보호 파일이다.
- **도면**(결정 문서)은 보호 파일이다. 도면을 바꾸는 것은 케이스 정리와 한 묶음으로 대표 승인이다.
- **작업 일지는 덧붙이기만** 된다. 두 갈래로 막는다: 편집 도구는 기존 내용이 앞부분에 그대로 남는지 훅이 검사하고, 터미널의
  `>` 덮어쓰기는 일지를 보호 경로에 두어 막는다 — 덧붙이기는 궤도 스크립트에 **요청**하는 방식이다. 케이스가 근거로 가리키는 곳이기 때문이다.
- `scripts/probe/`의 실측 로그는 **훅이 실제 실행에서 남긴 것만** 인정한다. 직원이 손으로 쓴 로그는 "실측"이 아니다.
- **수동 케이스는 다시 올라온다**: ⓪에서 수동 케이스마다 **묶인 파일 경로 패턴**을 같이 적고, 어느 일에서든 바뀐 파일 목록이 그
  패턴과 겹치면 검토자 판정표에 그 줄이 자동으로 다시 올라온다("관련 있는지"를 AI가 판단하지 않는다). 패턴이 비어 있는 케이스는
  매번 올라온다.

## 터미널 명령 판정 — 첫 단어가 아니라 명령 전체

허용 목록은 첫 단어로 판정하지 않는다. 명령을 `&&`, `||`, `&`, `;`, `|`, `$( )`, 백틱, 줄바꿈, `<( )`, here-doc 단위로 **쪼개
하나씩** 판정하고, 쪼갤 수 없는 명령은 거부한다. **앞에 붙은 환경 변수는 떼고 보지 않는다 — 접두가 붙으면 거부**하고 꼭 필요한
변수만 허용 목록에 둔다. **거부 예시**(허용이 아니다): `GIT_CONFIG_COUNT`·`GIT_CONFIG_KEY_0=core.hooksPath`처럼 설정을 환경 변수로
넣는 것, `GIT_DIR`, `NODE_OPTIONS`, `PYTHONPATH`, `LD_PRELOAD`. `git`은 하위 명령뿐 아니라 인자까지 본다 — `--no-verify`는 통과하지 않고, **`git` 바로 뒤에 오는 옵션은 전부 불허**한다
(`-c`, `-C`, `--git-dir`, `--work-tree`, `--namespace`, `--exec-path`, `--config-env` … 이름을 세지 않는다). 쪼개는 기준의 `$( )`와
백틱은 같은 줄에 있다. `claude`(새 세션을 열면 v2 훅이 전부 쉰다), `bash -c`, `sh -c`, `xargs`,
`find -exec`, `env`, `eval`, `exec`는 허용 목록에 없다. 허용 목록 안의 `npm run`·`pytest`·`node <파일>`은 프로젝트 코드를 그대로
돌리므로 그 자체로는 아무것도 막지 못한다 — 벽은 샌드박스다.

명령 뒤의 `git status` 점검에는 보지 못하는 곳이 있다: `.git` 안의 변경, `.gitignore`에 걸린 파일, 저장소 밖 파일. 보호
목록의 `.git/hooks`와 전역 설정이 바로 이 사각지대에 있으므로, **그 자리는 샌드박스 거부 규칙만이 막는다.** 네트워크 전송·
배포처럼 되돌릴 수 없는 일은 사후 점검으로 막지 못하므로 **샌드박스의 네트워크 허용 주소**로 막는다. 되돌리기는 HEAD 기준이 아니다(직원은 커밋을 못 하므로 앞 칸의 변경이 전부 커밋 전 상태라, HEAD로 되돌리면 앞 칸 작업까지
사라진다). 칸이 시작할 때 해시만이 아니라 **내용 사본**을 떠 두고 거기서 복원한다. **칸이 시작할 때 목록에 없던 파일만** 지우는
단계까지 넣고, 명령 뒤 점검은 `git status --ignored`로 무시 목록 파일까지 본다(지문·사본 비교와 같은 범위)(`git clean`처럼 무시 목록 파일까지 지우면 `.env`나
의존성 폴더가 날아간다), 범위는 그 직원의 작업 사본 안 허용 경로 밖 변경으로 한정한다(직원은
원본이 아니라 자기 사본에서 일하므로 대표가 같은 시간에 고친 원본 파일은 건드리지 않는다).

## 꺼지는 대신 막히게 — 상태 파일과 /일

- "일 폴더가 열려 있지 않으면 아무것도 하지 않는다"는 규칙은 상태 파일이 **깨지거나 읽히지 않을 때도** 꺼진 것으로 읽는다.
  상태 파일을 못 읽으면 **막는 쪽**(fail-closed)으로 처리한다. 일 중단·포기도 궤도 스크립트를 통하며 대표 승인을 거친다.
- `/일`·`일 닫기`·`승인`·중단·포기·`지적 ` 머리말은 대표만 부른다. 명령 파일 머리에 **모델 호출 금지 설정**(`disable-model-invocation`)을
  넣고, 훅이 그 입력이 **대표에게서 왔는지** 확인한다 — 여섯 모두에. 이 설정이 설치한 버전에서 실제로 작동하는지는 첫 시험에서 확인한다.
- 커밋은 직원이 직접 치지 않는다. 구현자는 커밋을 **요청**하고, 커밋 관문 훅(궤도 스크립트)이 소유표 안 파일만 골라 커밋한다.

## 작업 사본 합치기

직원마다 작업 사본을 쓰면 **합치는 순간**이 새 통로다. 합치기는 검토자 통과 뒤 ⑥ 칸 끝에서 **궤도 스크립트만** 하고, 합친
결과의 코드 지문이 검토·시험을 마친 지문과 같은지 대조한다. 다르면 **자동으로 ⑥**으로 되돌리고, 합치다 충돌이 나면 궤도
스크립트가 직접 풀지 않고 **멈춘다**.

## 열린 일 중에 대표 지적이 오면

둘 중 하나로 정한다 — **대기열**이다. 대표가 `지적 <내용>` 머리말로 보내면 훅이 **원문 기록에서 그대로** 작업 일지에 「대기」로
덧붙인다(AI가 요약해 적지 않는다). 지금 일은 계속한다. **대기열의 일을 여는 주체는 반장이 아니다** — 대표가 `일 닫기`를 치는
순간 훅이 대기열 맨 앞 지적으로 ⓪ 일을 연다. 여는 주체가 대표 입력에 묶여 있어 모델이 일을 여는 길이 없다. 훅은 대기열을 **일지가 아니라 원문 기록의 메시지 번호로만**
읽는다 — 일지의 「대기」 줄은 보는 용도일 뿐이고, 편집 도구로 「대기」 모양의 줄을 쓰는 것은 막는다(AI가 「대기」 줄을 덧붙여 다음
일을 여는 길을 없앤다). 지금 일을 멈추고 지적부터 하려면 대표가 `일 닫기 <이름> <사유>`로 닫는다(승인).
지적이 사라지는 길은 없다: 「대기」 줄은 덧붙이기만 되는 일지에 있다.

## 첫 시험에서 확인할 항목 (확인되기 전까지 "추정")

1. 훅 입력에 직원 식별이 들어오는가(없으면 직원마다 작업 사본 = 경로로 구분).
2. 훅과 시험 스크립트가 실제로 **샌드박스 밖**에서 도는가.
3. `/일`의 모델 호출 금지 설정이 설치한 버전에서 작동하는가.
4. 세션 시작 점검이 샌드박스 켜짐·보호 경로 쓰기 거부를 실제로 확인하는가.
5. 프로젝트 안의 시험 설정을 실행기가 정말 읽지 않는가: 케이스 하나를 빼는 설정(그리고 `conftest.py` 같은 자동 실행 파일)을
   프로젝트에 넣고도 그 케이스가 도는지 본다 — 많은 테스트 도구가 프로젝트 설정을 자동으로 찾아 읽으므로 문장만으로는 보장되지 않는다.
6. 뚫리는 장면 재현: 상태 파일 손상 → 막히는가 / 예전 bench.json으로 커밋 → 막히는가 / `conftest.py` 새 파일 → 막히는가 /
   `git -c core.hooksPath=` → 막히는가 / `claude` 재호출 → 막히는가.
