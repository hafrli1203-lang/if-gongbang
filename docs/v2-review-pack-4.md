# 검토용 4/5 — 검사·훅·케이스·설치 (12차 반영판)

## 터미널 명령 판정 — 첫 단어가 아니라 명령 전체

허용 목록은 첫 단어로 판정하지 않는다. 명령을 `&&`, `;`, `|`, `$( )` 단위로 **쪼개 하나씩** 판정하고, 앞에 붙은 환경 변수는
벗겨 낸 뒤 본다. `git`은 하위 명령뿐 아니라 **인자까지** 본다 — `--no-verify`, `-c core.hooksPath=…`는 통과하지 않는다.
`claude`(새 세션을 열면 "일이 열려 있지 않음"으로 판정되어 v2 훅이 전부 쉰다), `bash -c`, `sh -c`는 허용 목록에서 뺀다.

명령 뒤의 `git status` 점검에는 보지 못하는 곳이 있다: `.git` 안의 변경, `.gitignore`에 걸린 파일, 저장소 밖 파일. 보호
목록의 `.git/hooks`와 전역 설정이 바로 이 사각지대에 있으므로, **그 자리는 샌드박스 거부 규칙만이 막는다.** 네트워크 전송·
배포처럼 되돌릴 수 없는 일은 사후 점검으로 막지 못하므로 **샌드박스의 네트워크 허용 주소**로 막는다. 되돌리기는 `checkout`만으로
끝나지 않는다 — **새로 생긴 파일을 지우는 단계**까지 넣고, 범위는 그 직원의 작업 사본 안 허용 경로 밖 변경으로 한정한다(직원은
원본이 아니라 자기 사본에서 일하므로 대표가 같은 시간에 고친 원본 파일은 건드리지 않는다).

## 꺼지는 대신 막히게 — 상태 파일과 /일

- "일 폴더가 열려 있지 않으면 아무것도 하지 않는다"는 규칙은 상태 파일이 **깨지거나 읽히지 않을 때도** 꺼진 것으로 읽는다.
  상태 파일을 못 읽으면 **막는 쪽**(fail-closed)으로 처리한다. 일 중단·포기도 궤도 스크립트를 통하며 대표 승인을 거친다.
- `/일`은 대표만 부른다. 명령 파일 머리에 **모델 호출 금지 설정**(`disable-model-invocation`)을 넣고, 일 시작 훅이 그 `/일`이
  **대표의 입력에서 왔는지** 확인한다. 이 설정이 설치한 버전에서 실제로 작동하는지는 첫 시험에서 확인한다.
- 커밋은 직원이 직접 치지 않는다. 구현자는 커밋을 **요청**하고, 커밋 관문 훅(궤도 스크립트)이 소유표 안 파일만 골라 커밋한다.

## 작업 사본 합치기

직원마다 작업 사본을 쓰면 **합치는 순간**이 새 통로다. 합치기는 검토자 통과 뒤 ⑥ 칸 끝에서 **궤도 스크립트만** 하고, 합친
결과의 코드 지문이 검토·시험을 마친 지문과 같은지 대조한다. 다르면 합치지 않고 ⑥으로 되돌린다.

## 열린 일 중에 대표 지적이 오면

둘 중 하나로 정한다 — **대기열**이다. 지적은 작업 일지에 「대기」로 덧붙이고 지금 일은 계속한다. 지금 일이 닫히면 반장이
대기열 순서대로 그 지적으로 ⓪ 일을 연다. 지금 일을 멈추고 지적부터 하려면 대표가 `일 닫기 <이름> <사유>`로 닫는다(승인).
지적이 사라지는 길은 없다: 「대기」 줄은 덧붙이기만 되는 일지에 있다.

## 첫 시험에서 확인할 항목 (확인되기 전까지 "추정")

1. 훅 입력에 직원 식별이 들어오는가(없으면 직원마다 작업 사본 = 경로로 구분).
2. 훅과 시험 스크립트가 실제로 **샌드박스 밖**에서 도는가.
3. `/일`의 모델 호출 금지 설정이 설치한 버전에서 작동하는가.
4. 세션 시작 점검이 샌드박스 켜짐·보호 경로 쓰기 거부를 실제로 확인하는가.
5. 뚫리는 장면 재현: 상태 파일 손상 → 막히는가 / 예전 bench.json으로 커밋 → 막히는가 / `conftest.py` 새 파일 → 막히는가 /
   `git -c core.hooksPath=` → 막히는가 / `claude` 재호출 → 막히는가.

## 모든 개발에서 먹히게 — 장치는 전역, 데이터만 프로젝트

| 전역(하네스 홈, 이 저장소의 `harness/`) | 프로젝트 안(데이터) |
|---|---|
| 막는 훅과 설정 파일 | `tests/bench/` 시험 케이스 |
| 스킬(크래시 아웃·아우라 파밍·육칠·화면 품질 점검·계획 쓰기…) | `scripts/probe/` 실측 로그 |
| AI 직원 7명(⓪~⑥) 파일 | 도면(결정 문서) |
| 궤도 스크립트, `/일` 명령 | 프로젝트 안내 한 줄 |
| 공통 규칙 2장(안전 + 이 문서) 자동 로드 | 미리보기 스크립트(템플릿에서 생성) |

- 설치: 저장소를 받아 설치 절차 한 번 → 다른 컴퓨터에도 같은 훅·스킬·직원·명령.
- `/일 <이름> 루트=<폴더> [소형] [화면]`: 어느 폴더든 처음이면 `tests/bench/`·`scripts/probe/`·도면을
  만들고 프로젝트 목록에 등록한다. 그 순간부터 같은 궤도다.
- **자동으로 읽히는 절차 문서는 두 장**(안전 규칙 + 궤도 요약)으로 유지한다. v2 문서 여섯 개는 설계 문서라 자동으로 읽히지
  않는다. 자동 로드 문서가 늘어나면 실패 신호다.
  "이 프로젝트에서만"이라는 말이 설계에 나오면 설계가 틀린 것이다.

## 한계 → 돌파 장치 → 그래도 남는 것

| 한계 | 돌파 장치 | 남는 것 |
|---|---|---|
| AI는 글로 적은 규칙을 안 지킨다 | 지킬 필요가 없게: 스킬 주입, 도구 화이트리스트, 순서는 코드 | 화이트리스트 안의 엉뚱한 선택 → 검토자·시험대 |
| 자료 안 보고 짐작 | 출처 없는 값 반입 차단, 실측 없이는 구현 칸 안 열림, 원문표 주입 | 출처를 잘못 읽는 경우 → 결과로 잡음 |
| 판단 오류 자체 | 육칠, 두 모델 계열 교차 판정(둘이 다르면 대표), 테스트 먼저, 지적→케이스 | **처음 보는 오류 1회** |
| 문맥 폭발 | 반장 호출 상한, 칸마다 새 문맥, 일 하나 = 창 하나 | 계기판 "반장 호출 수"·"토큰"으로 확인(시험 전) |
| "완료"를 쉽게 말함 | 답 끝에 상태 줄 자동 부착, 「미검증」은 막힘 | 계기판 "「미검증」 수용"으로 확인(시험 전) |
| 검증이 많고 못 믿음 | 검토 1 + 시험대 1, 교차 점검 1회 상한 | 새 기능 첫 회는 케이스가 없음 → 그때 만듦 |
| 화면을 숫자만 맞춤 | 캡처 옆 시안·"이거다" 관문·포트폴리오 판정 | 대표 취향은 "이거다"로만 |
| 같은 설명 반복 | 직원 파일 고정, 원문표 한 곳 | 계기판 "대표 메시지 수"로 확인(시험 전) |
| 워크플로를 켜야 함 | `/일` 자체가 승인 | 일 시작 훅이 실제로 막는지 첫 시험에서 확인 |
| 설정을 AI가 못 바꿈 | 관문 한 번, 임계값은 설정 파일 | 훅 수정은 관문(그대로가 맞음) |
| 느리고 비쌈 | 소형 궤도, 칸별 모델 등급, 동시 실행, 칸에 파일만 전달 | 첫 시험의 측정 비용 |
| 실패가 흩어져 안 보임 | 멈춘 자동화 보드(아래) | 보드는 다음 단계 |
| 칸 사이 전달 품질(파일뿐) | 산출물 형식 고정 + 검토자가 통과 장면으로 대조 | 시험으로 재는 것 |

진짜 남는 것은 둘이다. 처음 보는 오류의 첫 1회, 그리고 칸 사이 전달 품질. 전자는 미리보기와
케이스화로 두 번째를 없애고, 후자는 시험으로 숫자로 확인한다.
