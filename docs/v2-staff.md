# IF 공방 v2 — 식구와 직원

`v2.md`의 궤도 위에서 누가 무엇을 맡는가. 읽는 순서는 `v2.md` 맨 위 표.

## 부품 9개 — v1에서 무엇이 바뀌나

| 부품 | v1 | v2 | 왜 이러면 작동하나 |
|---|---|---|---|
| 대표 | 정하고·승인·지적 | 같음 + 시안에 "이거다", 채점표에서 고름 | 질문은 줄고 남는 질문은 비교표 |
| 반장 | 절차 수행 주체 | **비서실장**: 일 폴더 열고 궤도 시작, 결과 전달. **일이 열려 있는 동안 터미널 없음**, 호출 상한 | 건너뛸 절차도, 때울 터미널도 반장 손에 없음 |
| 작업조 | 깎는 손·보는 눈 | **AI 직원 7명(⓪~⑥)** 파일 고정 + 도구 화이트리스트 | 검토자는 편집 도구가 없어 못 고침. 설명 반복 없음 |
| 울타리 | 관문·위험 명령·완료 검증·착수 보고 경고 | 안내 훅은 두지 않고 **막는 훅만**: 소스 편집·커밋·배포·일 닫기·두 번째 일·반장 호출 상한 | 안내 훅은 무시된다 |
| 작업 일지 | 3문장·원문 | 같음 + **지적 1건 = 시험 케이스 1건** | 재발 0의 장치 |
| 도면 | 승격된 기준 | 같음 + ① 칸 자동 주입 | 읽는 것을 AI 기억에 맡기지 않음 |
| 곳간 | 자료·검색 | 같음 + ① 칸 자동 주입 + **방향 원문표**(대표가 정한 방향을 날짜·원문으로 한 곳에) | "이미 말했는데 왜"가 안 생김 |

| 다듬질 | 고리 한 바퀴 | 같음. ② 실측이 "돌려 본다"를 **강제** | 돌려 보기 전에 만드는 길이 없음 |
| 작업판 | 할 일 한 곳 | 같음 + 계기판 | 나아졌는지 숫자 |

## AI 직원 7명(⓪~⑥)

전역(하네스의 agents 폴더)에 두어 어느 프로젝트에서나 같은 사람이 같은 도구로 일한다.

| 이름 | 하는 일 | 못 하는 일(도구에서 뺌) | 모델 등급 | 박힌 스킬 |
|---|---|---|---|---|
| 사실확정자 | 기준·숫자·공식·외부 API 형식을 증거로 판정 | 코드 편집, 터미널 — 쓰기는 `facts.md` 한 파일 | 중 | 크래시 아웃, 곳간 검색 |
| 실측자 | 공식 문서 열고 실제 호출 1회 성공, 로그 | 어댑터·엔진 작성, 운영 DB, 배포 — 터미널은 **샌드박스**에서 돌고 `probe/` 밖 쓰기는 파일 시스템 단위로 거부. **외부로 쓰는 호출을 막는 벽은 명령 검사가 아니라 "운영 키를 주지 않는 것"이다**(테스트·조회 키만 — 운영 키는 프로젝트 폴더 밖, 샌드박스가 읽을 수 없는 곳에만 있고, 직원 샌드박스는 외부 통신을 허용 주소로만 연다) | 중 | — |
| 계획자 | 통과 장면(+돌릴 명령)·예외·파일 소유·도구표. 갈림길이면 여섯 안 + 심사 | 코드 편집, 터미널 — 쓰기는 `plan.md`·`tools.md` | 상 | 계획 쓰기, 육칠, 스킬 창고 검색 |
| 시안자 | 참고 캡처 옆에 누를 수 있는 시안, 방향 한 문장·서체·색·그리드 | 앱 코드 편집 — 쓰기는 일 폴더의 `design/`과 시안 파일 폴더로 제한 | 중 | 아우라 파밍, 레이아웃, 화면 품질 점검 |
| 구현자 | 소유 파일 안에서 구현, 테스트 먼저, 핵심 경로 실제 실행 | 작업조 생성, 배포, DB 변경, 설치, push, `tests/bench/` — 터미널은 샌드박스에서 돌고 소유표 밖 쓰기는 파일 시스템 단위로 거부 | 중 | — |
| 시험자 | ⓪ 시험 등록 칸: 대표 지적을 케이스로 옮기고 현재 코드에서 실패를 기록 | 소스 편집(쓰기는 `tests/bench/`만) | 중 | — |
| 검토자 | 결과물을 열어 보고 판정만 | 원본 편집 — **일회용 작업 사본**(샌드박스, 쓰기 허용, 칸 끝 폐기)에서만 실행하고 원본 쪽 쓰기는 `review.md` 하나. 테스트·빌드·임시 DB가 쓰기를 해도 됨 | 중 (+ 다른 계열 1회: 고위험 일, 또는 불통과 2바퀴 연속) | 화면 품질 점검 |

"못 하는 일"은 도구 목록만으로 막지 않는다. **벽은 샌드박스 하나다**: 터미널이 있는 직원은 하네스의 샌드박스(파일 경로 거부 규칙 — `hardening.md`의 강화 설치)에서 돌아 허용 경로 밖 쓰기가 파일 시스템 단위로 거부된다. 훅의 명령 검사와 칸 끝 해시 비교는 벽이 아니라 **뒤에서 확인하는 장치**다(`python -c`, `node -e`, `git checkout` 같은 길은 명령 목록으로 다 못 막는다). 상세: `v2-devices.md`.

반장은 직원이 아니라 비서실장이다. **일이 열려 있는 동안 반장에게는 터미널이 없다**(훅이 막음) — 반장이 하는 일은 일 폴더를 열고, 궤도를 시작하고, 결과를 전달하는 것뿐이라 터미널이 필요한 일은 전부 직원 칸의 일이다. 비율 상한은 "상한 아래에서는 터미널로 때워도 된다"를 허용하므로 쓰지 않는다.

## 스킬이 "알아서" 붙는 방식 — 고정 목록이 아니다

"반드시 부르는 스킬" 목록을 두면 에이전트는 그 목록만 채우고 끝낸다. v2는 목록 대신 네 가지 장치를 쓴다.

1. **주입**: 칸이 열릴 때 그 칸의 스킬 본문을 **훅이 문맥에 넣는다**(① 크래시 아웃, ③ 계획 쓰기,
   ④ 아우라 파밍, ⑥ 화면 품질 점검, ⑧ 보고 틀). 에이전트가 부르는 것이 아니라 들어온다.
2. **도구표**: ③ 계획 칸이 **스킬 창고 전체를 검색**해 "이 일에 쓸 스킬·연동 도구·직원" 표
   (`tools.md`)를 만든다. 일마다 다르다. 대표는 착수 보고에서 이 표를 본다.
3. **대조**: ⑧ 보고 칸이 `tools.md`와 **실제 호출 기록**(세션 기록에서 자동 집계)을 맞춰 본다.
   "쓰겠다고 적었는데 안 쓴 것 / 터미널로 대신한 것"이 숫자로 찍힌다.
4. **습관 차단**: 사실확정자·계획자·반장(일이 열린 동안)에게는 터미널이 없다. 터미널이 있는 직원의 명령 판정 규칙은 `v2-devices-2.md` 훅 표 「터미널」 한 줄이 기준이다. 벽은 샌드박스다. 터미널 비율은 계기판 지표로만 남긴다.

외부에서 들여온 생각 도구 세 가지(원본은 공개 저장소, MIT)를 우리 규칙에 맞게 고쳐 스킬로 둔다:
- **크래시 아웃**(사실): 답을 쓴 뒤 주장을 전부 뽑아 증거로 공격 → 통과/확인 필요/탈락 → 통과한
  것만으로 다시 쓴다. 핵심 주장이 탈락하면 "처음 답은 틀렸다"고 분명히 말한다.
- **육칠**(갈림길): 같은 과제를 여섯 방식(최소·풀옵션·원리부터·검증된 방식·반대편·모험)으로 끝까지
  만들고 일곱째가 채점·합친다. 비용이 크므로 결정에만 쓴다. **갈림길인지는 계획자가 정하지 않는다** — 대표가
  `/일`에서 지정하거나, 코드 조건(새 화면 구조·새 설계·민감 영역)이 맞으면 자동으로 켜진다. "계획자가 후보를 둘 이상 적음"은 자기신고라 **켜는 쪽으로만** 작동한다(하나만 적어도 끄지 못한다).
- **아우라 파밍**(화면): 그리기 전에 분위기 한 문장·서체 2·색 2·그리드를 정하고, AI 티 금지
  목록(보라 그라데이션·유리 카드·이모지 글머리·전부 가운데 정렬·똑같은 카드 나열·빈말 문구)을
  피한 뒤 "실제 디자이너가 포트폴리오에 넣겠나"로 자기 검사한다.
