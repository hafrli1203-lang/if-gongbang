# 일 — IF 공방 궤도 시작

사람가 이 명령을 쳤다 = 이 앱·이 일을 실제로 돌리라는 지시다. 다른 앱·다른 일로 넓히지 않는다.

## 1. 무엇을 할지 한 줄로 확인 (착수 확인)
「이번에 하는 것 / 안 하는 것 / 기대 수준」 한 줄을 쓴다. 사람 문장을 그대로 인용한다. 앱 이름이 없으면 그것만 묻는다.

## 2. 궤도 시작
- 새 앱: `gb2 new <앱이름> "<사람 요청 원문>"` — `$GB2_APPS_ROOT/<앱이름>`이 이미 있으면 멈추고 알린다.
- 기존 앱 수정: 처음이면 `gb2 init <앱>` 뒤 `gb2 change <앱> "<사람 요청 원문>"`.
- 요청 원문은 고쳐 쓰지 않는다. 길면 `--task-file`로 넘긴다.
- 백그라운드로 돌리고(Bash run_in_background), 진행 줄을 사람에게 짧게 알린다. 기다리는 동안 겹치지 않는 다른 일을 한다.

## 3. 멈췄을 때 (종료코드 2 = 사람 확인 필요)
- 시안 승인 대기: 시안 주소·화면을 보여 주고, 사람가 "이거다"라고 하면 `gb2 approve-design <앱>` (사람가 터미널에서 직접 입력).
- 설치 요청·실측 실패·작업자 막힘: 무엇이 왜 막혔는지 한 줄씩 보고하고 사람 결정을 받는다. 반장이 대신 코드를 고치지 않는다.
- 이어서 하기: `gb2 continue <앱>`.

## 4. 끝났을 때
- `.gongbang/<일>/report.md`를 열어 대조표·화면·숫자·도구표 대조·미검증을 그대로 보고한다(`진행-보고` 형식).
- 배포는 `gb2 ship <앱>` — 사람가 터미널에서 직접 승인한다.

## 지킬 것
- 실행 출력 없이 "완료·통과"라고 쓰지 않는다. 실패는 실패대로 보고한다.
- 비용·횟수 한도를 걸지 않는다. 작업자가 멈추면 엔진이 이어서 하게 한다.
- 업종·브랜드를 박지 않는다(요청에 있는 값만).
