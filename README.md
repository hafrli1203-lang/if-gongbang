# IF 공방

사용자(대표)의 판단을 작업 일지와 도면으로 쌓고, 그 기준과 울타리 안에서 AI 작업조가 프로젝트를 깎아
만들며, 시험대로 재어 조금씩 다듬어 가는 개발·운영 방식이다. Claude Code(또는 비슷한 에이전트
하네스)의 hook 기능 위에 얹어 쓴다.

자세한 개념은 `docs/concept.md`, 그림 안내서는 `docs/guide.html`을 본다.

## 공방의 부품 9개

| 이름 | 하는 일 |
|---|---|
| **반장** | 일을 나누고 맡기고 확인하고 보고하는 메인 에이전트 |
| **작업조** | 깎는 손(구현)과 보는 눈(검수)을 따로 둔다 — 자기가 만든 것을 자기가 채점하지 않는다 |
| **울타리** | 사고를 지시문이 아니라 장치(hook)로 막는다 |
| **작업 일지** | 한 번 지적받은 것을 3문장으로 남긴다 — 아직 기준은 아니다 |
| **도면** | 반복 확인되고 승격된 작업 일지만 프로젝트의 정식 기준이 된다 |
| **곳간** | 참고 자료를 쌓고 근거로 꺼내 쓴다 |
| **시험대** | 좋아졌는지 나빠졌는지 숫자로 잰다 |
| **다듬질** | 한 바퀴씩 고치는 고리(아래) |
| **작업판** | 할 일을 한 곳에 모은다 |

## 일하는 순서

**다듬질 고리(모든 수정에):** 돌려 본다 → 원인을 가른다(자료·기준·지시문·도구) → 원인 자리 하나만
고친다 → 같은 평가로 전후를 숫자로 잰다 → 사람이 기준을 정한다.

**착수 전 보고(코드·설정을 고치기 전에):** 읽은 자료(파일:줄) / 예상 위험·병목 / 바꿀 파일 /
되돌리는 법, 네 가지를 먼저 쓴다.

**완료 보고:** 실행한 명령 · 출력의 핵심 숫자 · 미검증 항목. 출력 없이 "완료·통과·성공"이라 쓰지
않는다.

**마지막 교차 점검(권장):** 테스트와 1차 검수를 통과한 뒤, 같은 변경분을 다른 모델 계열에 읽기
전용으로 한 번 더 보인다. 인증·권한·결제·삭제·외부 연동·배포·설정 변경에는 꼭 넣는 것을 권장한다.

**토큰 아끼기:** 필요한 파일만 정확히 지정해서 읽는다. 작업을 전환할 때 컨텍스트를 정리한다. 가벼운
조회·구현·설계 판단에 각각 다른 크기의 모델을 맡기는 식으로 역할을 나눈다.

전체 규칙 틀: `docs/rules/WORKFLOW.md`, `docs/rules/MASTER.md`.

## 승인 관문

되돌리기 어려운 행동(서비스 정지·해제, git push·되돌리기·삭제, 패키지 설치, 재귀 삭제, sudo,
프로세스 강제 종료, 설정/.env 편집, 작업판 완료 표시 등)은 대표가 채팅에 `승인 <TASK>`를 입력한
뒤 설정된 시간(기본 4시간) 동안만 열린다. `승인 전체`는 같은 세션의 모든 관문 대상에, `승인 취소`
(또는 `승인 해제`)는 즉시 닫는 데 쓴다. 승인 여부는 파일이 아니라 대표의 실제 대화 기록에서 매번
다시 계산되며, 세션 단위로만 유효하다. 문법·범위·판정 방식의 자세한 내용은
`docs/approval-gate.md`를 본다.

## 빠른 설치

자동 설치 스크립트는 두지 않는다 — 사람이 눈으로 확인하며 따라 하는 단계 문서를 쓴다.
`install/README.md`를 본다. 짧게 말하면:

1. `gongbang.config.example.json`을 복사해 `gongbang.config.json`을 만들고, 자신의 경로로 채운다.
2. `hooks/*.py`, `hooks/*.sh`를 에이전트 하네스의 hook 디렉터리에 두거나, 그 디렉터리에서 이 경로를
   가리키게 한다.
3. `install/settings.example.json`을 참고해 하네스 설정(`settings.json`)에 각 hook을 이벤트별로
   등록한다.
4. `GONGBANG_CONFIG` 환경 변수로 `gongbang.config.json`의 절대 경로를 지정한다(또는 hook들이 저장소
   루트에서 그 파일을 자동으로 찾는다).
5. `python3 -m pytest tests/`로 확인한다.

## 알려진 한계

1. **같은 사용자 권한에서 의도적 위조·무력화는 막지 못한다.** 울타리는 협조적인 AI의 실수를 막는
   장치다. 확실한 차단은 OS 수준 분리(별도 사용자·컨테이너)가 필요하다.
2. **셸 문법을 완벽히 해석하지는 않는다.** 명령 치환(`$(...)`), `eval`, 깊은 중첩 등은 다루지
   않는다 — 실수를 줄이는 안전망 한 겹이다. 자세한 내용은 `docs/command-parsing.md`.
3. **승인은 세션 단위다.** TASK 이름은 사람이 보기 위한 라벨일 뿐 행동 범위를 제한하지 않는다 —
   어떤 이름으로 승인해도 그 세션의 관문 대상 행동 전체가 열린다. 자세한 내용은
   `docs/approval-gate.md`.
4. **지시문 준수 자체를 100% 강제할 수는 없다.** 이 장치가 막는 것은 되돌리기 어려운 행동과 근거
   없는 완료 선언 두 가지뿐이다. 나머지(지시문을 얼마나 잘 따르는지, 보고의 질, 설계 판단의 좋고
   나쁨)는 계획서 승인·작업조 검수(가능하면 다른 모델 계열)·시험대로 다룬다.
